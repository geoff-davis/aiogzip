# WP6 design: explicit binary read health

WP6 implements plan §10 and closes G10: *three-state binary health and
transitions match C0; temporary accessors are read-only.* It is a representation
change. It must not alter any behavior settled at C0 (`refs/c0/v2.0.0b2`,
[record](../reviews/v2.0.0b2-c0-record.md)).

## Current state at C0

Binary read health is two stored Booleans in `_binary.py`, `_read_broken` and
`_read_validation_failed`, both in `__slots__`. The
[WP0 file-state model](v2.0.0b2-file-state-model.md) maps the pairs:

| Pair | Meaning |
| --- | --- |
| `(False, False)` | healthy |
| `(True, True)` | validation failure: report the error, retain salvage plaintext |
| `(True, False)` | broken: terminal until a successful rewind or reopen |
| `(False, True)` | invalid; never written today, but representable |

**Writers (five, all binary):**

| Site | Transition |
| --- | --- |
| `__init__` (`_binary.py:343–344`) | → healthy, before any open, in read and write modes |
| `open()` initialization (`_binary.py:425`) | → healthy |
| `_poison_read(decoder, validation_failed=...)` (`:1530`) | → validation salvage or broken; sets `_eof`, calls the text poison observer, then discards the decoder |
| `_rewind_reader()` reset (`:1626`) | → healthy, with new decoder, cleared buffer, position 0 |
| exceptional context exit, read mode (`:1924`) | → broken, `_eof = True` |

**Readers:**

- Binary: seven call-availability guards of the form
  `self._read_call_active or self._read_broken` on read surfaces (hot paths);
  seek-to-0 recovery (`:598`); line-salvage paths (`:942`, `:977`, `:1024`);
  `_has_validation_failure()`, `_can_restore_failed_read()` and the usability
  check (`:1451`, `:1455`, `:1510`); and the close path (`:1751`).
- Text: three reads (`_text.py:656`, `:1348`, `:1454`).
- Tests: 13 assertions in five files read the fields. None assigns them.

## Design

### Enum and authoritative field

```python
class _ReadHealth(Enum):
    HEALTHY = auto()
    VALIDATION_SALVAGE = auto()
    BROKEN = auto()
```

Binary stores one field, `_read_health`, replacing both slots. Module-level
aliases (`_HEALTHY = _ReadHealth.HEALTHY`, and so on) keep hot-path checks to a
single identity comparison against a global, with no attribute lookup on the
enum class and no allocation.

### Centralized transitions

Every write goes through one of three private methods:

| Method | Used by | Effect on health |
| --- | --- | --- |
| `_reset_read_health()` | `__init__`, `open()`, `_rewind_reader()` | → `HEALTHY` |
| `_poison_read(decoder, *, validation_failed)` (existing) | validation, limit and decoder failures | → `VALIDATION_SALVAGE` or `BROKEN` |
| `_break_read_on_abort()` | exceptional context exit | → `BROKEN` |

Authoritative health and `_eof` are committed before the text poison observer
is called. At C0, an observer that raises skips the following
`decoder.discard()`. WP6 hardens this as §10.3 requires: the observer call sits
in a `try`/`finally` that always discards the decoder, and the observer's error
still propagates. This is internal hardening of a callback that only the text
layer installs; no public callback behavior is added. EOF, closure, opening
ownership, active calls, native work and transport position stay separate
fields; the enum removes only the invalid Boolean pair.

### Accepted cleanup hardening

Two narrow C0 cleanup gaps are fixed in WP6. Neither changes a public result or
a C0 semantic trace:

- **Raising poison observer.** At C0 an observer error skipped
  `decoder.discard()`; the discard now runs in a `finally` (above).
- **Abort with native work.** At C0, when an exceptional context exit aborted a
  reader whose native read released its reservation before the handle was
  marked closed, neither release nor the abort's close discarded the decoder,
  so a closed reader kept its codec state until garbage collection. The abort's
  close now discards the decoder after `_mark_closed()` (in a `finally`)
  whenever no read reservation remains; a still-active reservation discards it
  on release, as before. Found by the transition matrix; the maintainer
  explicitly accepted this hardening on 2026-10-04 on Codex's recommendation.

### Hot paths

The seven guards become
`self._read_call_active or self._read_health is not _HEALTHY`, a direct
comparison with no helper or property call. Salvage and recovery paths may use
named predicates, since they are not per-byte.

### Temporary read-only adapters (removal owner: WP8)

So the text layer keeps working until WP8 migrates it, binary exposes derived
read-only properties under the old names:

| Temporary name | Definition | Owner |
| --- | --- | --- |
| `_read_broken` | `self._read_health is not _HEALTHY` | WP8 removal |
| `_read_validation_failed` | `self._read_health is _VALIDATION_SALVAGE` | WP8 removal |
| `_has_validation_failure()` | derived from `_read_health` | WP8 review |
| `_can_restore_failed_read()` | derived from `_read_health` | WP8 review |

The two properties have no setter and no storage; assigning them raises. Binary
code never reads them. Text's three reads stay unchanged in WP6. The 13 test
assertions keep passing through the adapters; new tests assert `_read_health`
directly.

## Tests

1. **Structure.** An AST test fails if production code assigns `_read_broken`
   or `_read_validation_failed`, or if either is a slot; assigning either
   property raises `AttributeError`; `(False, True)` is unrepresentable.
2. **Invariants,** checked after every transition: `VALIDATION_SALVAGE` and
   `BROKEN` imply `_eof`. Immediately after a successful open or rewind,
   `HEALTHY` comes with an empty buffer, position 0, `_eof` false and a live
   decoder; later `HEALTHY` states, such as validated EOF or a closed handle,
   are valid combinations and are not held to that. Closure, active calls and
   opening ownership are unchanged by health transitions.
3. **Transition matrix** (`tests/test_read_health_transitions.py`), following
   the C0 transition table: healthy read and validated EOF; each malformed,
   truncated and integrity failure; the decompression limit; no-effect and
   consumed or uncertain source errors; native and repeated cancellation;
   overlap rejection; exceptional context exit through `_break_read_on_abort`,
   including with active custom-source and native work in flight; close
   during and after open; absolute rewind, failed rewind and non-seekable
   cached recovery; and a raising poison observer, asserting committed health
   and `_eof`, decoder discard, the observer's original error and no leaked
   resource. Each case records the immediate
   result, later result, retained buffer, position, EOF, decoder cleanup, work
   settlement, observer events and recovery path. Salvage stays recovery data
   followed by a terminal error, never clean EOF; an uncertain source read is
   never relabeled as salvage.

## Exit evidence for G10

- All eight C0 semantic traces still match on both engines, compared exactly
  as in the C0 record.
- Both full engine suites pass, as does all-file prek.
- No stored Boolean pair remains in binary; the adapters are derived and
  read-only.
- The affected binary read, seek and salvage benchmarks stay within the plan's
  performance policy against C0, measured as described below.
- Codex reviews this design, the code, and the evidence record.

## Benchmark method

The plan requires affected benchmarks to stay within policy (at most 5% slower
needs no investigation). The change replaces a Boolean check with an identity
check on seven read guards, so a measurable effect is unlikely, but it still
needs evidence. The maintainer chose the CLAUDE.md method on 2026-10-04:
`benchmarks/run_benchmarks.py --category io,micro` against clean C0 and
candidate worktrees, using the same venv, on both engines, over several
interleaved rounds compared by per-benchmark minimum, run as one short reviewed
window. Deltas above about 5% that survive interleaving get a targeted
micro-test before any conclusion.

`io,micro` covers ordinary reads, `readline`, `read1` and `readinto1`, but
contains no seek or validation-salvage benchmark. The same window therefore
adds a small targeted benchmark, interleaved the same way, for seek-to-0
rewind of a healthy reader, recovery rewind of a broken reader, and draining
validation-salvage data through `read` and `readline`. Those paths are claimed
as measured only by that benchmark.
