# WP5 timing tools: protocol step 2

This increment implements the sampler and comparison-report portion of the
[reviewed protocol](v2.0.0b2-wp5-timing-protocol.md). It changes no production code,
quiet thresholds, service scheduling or gate status. The existing frozen overnight
manifests and their pinned harnesses are unchanged.

## Measurements

Both throughput harnesses accept `--warmup-seconds`, `--batch-seconds`,
`--batch-min-operations` and `--discard-samples`. `--repeat` is the total number
of batches before the declared discard: use 9 and discard 2 to retain 7.
For the reviewed protocol use warmup 0.25, batch 0.1 and minimum operations 3.
All early samples and warmup observations remain in the JSON. Reported minima and
medians exclude only the declared initial count. Complete output is validated on
every operation, outside its original timer. Fixture construction remains once per
case; each G06 operation still opens a new reader before its timed line iteration.
Total batch wall time includes the untimed per-operation work.

G06 resource mode rejects timing options. With default options, its resource
observations and timing calls retain their prior behavior. G08 adds mutually
exclusive `--latency-only` and `--throughput-only` selection. Latency-only rejects
throughput warmup/batching options; discard requires batched throughput-only mode.
No scheduling samples are silently discarded.

## Comparison report

Run `python scripts/compare_b2_timing.py INDEX.json --output REPORT.json`.
Paths in the index resolve relative to the index file, not the working directory.
The output must not already exist. The index declares one gate and engine's series:

```json
{
  "gate": "G06",
  "sources": {"A": "baseline-full-sha", "B": "candidate-full-sha"},
  "row_count": 175,
  "repeat": 9,
  "max_block_seconds": 3600,
  "sampling": {
    "warmup_seconds": 0.25, "batch_seconds": 0.1,
    "batch_min_operations": 3, "discard_samples": 2
  },
  "blocks": [
    {"status": "complete", "captures": [
      {"side": "A", "path": "0-a1.json"},
      {"side": "B", "path": "0-b1.json"},
      {"side": "B", "path": "0-b2.json"},
      {"side": "A", "path": "0-a2.json"}
    ]},
    {"status": "unstarted", "reason": "window ended"},
    {"status": "unstarted", "reason": "window ended"},
    {"status": "unstarted", "reason": "window ended"}
  ]
}
```

For G08 also include `throughput_only: true` and `latency_only: false` in the
expected sampling object. The example session span is illustrative; freeze an
appropriate bound with the execution manifest. Both harnesses record wall-clock
start/end timestamps, and the report rejects overlap, reversed order or blocks
longer than the declared span. Clock adjustments can therefore reject a capture.

Four block slots are mandatory, in ABBA/BAAB/ABBA/BAAB order. Each complete block
has four captures; a rejected or unstarted block needs a reason and cannot contribute
to accepted summaries. The report preserves the index, hashes each accepted capture,
recomputes retained minima, requires distinct source commits and the declared
sampling settings/repeat count, and checks source/harness cleanliness, consistent
interpreter/platform/dependencies/engine/affinity/sampling, fixture identity, case
matrix, sample counts and duplicate capture paths. It rejects nonfinite or nonpositive
timings and inconsistent stored minima rather than producing a plausible ratio.

The report includes every block, both source drifts, geometric-mean ratios,
all-complete-block median, usable block count, investigation flag and operational
stronger-slowdown flag. A result is only `review-required` or `inconclusive`, never
`pass`. No complete blocks yields an empty row set, not a qualification. Noisy
slowdowns over 5% still trigger investigation. Mixed effect directions cannot
support a conclusive claim. Rejected blocks remain visible and reduce evidence.

This tool checks consistency, not authenticity or completeness of an execution.
The reviewed manifest must declare sources, complete expected matrix and protocol
before collecting measurements; do not derive a favorable index from results.
Host-policy attestation, runner-generated block status, G06 size-family scaling
interpretation, G08 scheduling review and G07 descriptive latency summaries remain
separate. A report never closes a gate or proves that a sub-threshold effect is absent.

## Review and validation

Claude reviewed the implementation through Herdr and requested declared sampling
settings/repeat counts, capture chronology checks and smaller G06 batch records.
Those changes are included. Its final review found no blockers and independently
passed all 84 focused tests. The local full suite passed 3,496 tests with one skip;
all-file prek passed. The index enforces a single consistent engine configuration
but does not separately name the intended engine; manifest review must check that
configuration before using the report. No timed qualification run was performed.
