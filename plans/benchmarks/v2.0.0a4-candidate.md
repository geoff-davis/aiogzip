# aiogzip 2.0.0a4 candidate evidence

Captured on 2026-08-22 after production code and maintained examples were
frozen at `ed0fe742be1a7d9efbb670cf8cf1ac76d7090de8`. The exact comparison
source is published `v2.0.0a3` at
`3e95073581be7cba437da45dacd9724f649e54d0`.

The candidate preserves every measured `2.0.0a3` performance gate. No
reproducible slowdown exceeds the 10% release blocker. Four sub-millisecond
optional-header rows remain between 5% and 10% after controlled reruns and are
recorded below. No performance improvement is claimed for this release.

## Source and method

- Candidate package version: `2.0.0a4.dev0`.
- Candidate source: clean tracked tree at
  `ed0fe742be1a7d9efbb670cf8cf1ac76d7090de8`.
- Comparison source: clean detached worktree at exact `v2.0.0a3`,
  `3e95073581be7cba437da45dacd9724f649e54d0`.
- Runner commit: the candidate source commit above.
- High-level harness SHA-256:
  `db5af0231d62584c907503729eb495dad9206679e54f2536e10b5da0e234cc1d`.
- Fixture generator: `a3-fixtures-v1`.
- Primary matrix: 57 high-level rows, 58 direct-codec rows, and four
  high-level supplement rows per engine and source, five samples per timing
  row where applicable.
- Engines: zlib-ng active and stdlib zlib forced while zlib-ng 1.0.0 was
  installed. The forced mode proves selection independently of installation.
- Capture order: exact a3/candidate pairs, with controlled investigations run
  in A/B/B/A order where CPU pinning was used.
- Correctness: every timed correctness-bearing row retained output byte counts
  and SHA-256 digests. Normalized result-digest sets matched for all 238
  comparable rows.
- Exclusions: every retained JSON record reports an empty
  `discarded_or_excluded_runs` list. An early orchestration attempt that did
  not produce a complete JSON record was not retained or used.

The primary command shape was:

```bash
python benchmarks/bench_a3_regressions.py \
  --source-root SOURCE \
  --engine ENGINE \
  --members-mtime-policy last-header \
  --repeat 5 \
  --memory-repeat 1 \
  --output RESULT.json

python benchmarks/run_benchmarks.py \
  --source-root SOURCE \
  --engine ENGINE \
  --regression-mode \
  --repeat 5 \
  --output RESULT.json

python benchmarks/bench_a4_supplement.py \
  --source-root SOURCE \
  --engine ENGINE \
  --repeat 5 \
  --output RESULT.json
```

Controlled header/write runs used 21 samples on CPU 0. Controlled direct
codec throughput runs used 11 samples on CPU 0. Supplement investigations
used nine samples. The raw records contain the exact executable, command,
individual samples, median, median absolute deviation (MAD), minima, maxima,
fixture metadata, source commit, engine selection, and machine state whenever
the originating harness exposes those fields.

The authoritative controlled comparison is the 148 paired rows from these
six CPU-0 captures:

- `v2.0.0a3-a4-candidate-pinned-stdlib.json` and
  `v2.0.0a4-candidate-pinned-stdlib.json`;
- `v2.0.0a3-a4-candidate-pinned-zlib-ng.json` and
  `v2.0.0a4-candidate-pinned-zlib-ng.json`; and
- `v2.0.0a3-a4-candidate-codec-throughput-pinned-zlib-ng.json` and
  `v2.0.0a4-candidate-codec-throughput-pinned-zlib-ng.json`.

The first four files contain the 21-sample header/write rows; the final pair
contains the 11-sample direct-codec rows. The five-sample primary captures and
the investigation captures remain provenance and diagnostic evidence, but
their noisier pairs are superseded for threshold decisions. Pairing every raw
baseline and candidate file without this selection produces false regression
flags and is not the release-gate comparison.

Durations are medians in seconds. Delta is `(candidate / a3 - 1) * 100`; a
negative value is faster.

| Gate | Engine | a3 | Candidate | Delta | Result |
| --- | --- | ---: | ---: | ---: | --- |

| 10-byte individual writes | zlib-ng | 0.778639 | 0.781475 | +0.36% | pass |
| 10-byte `writelines()` | stdlib forced | 0.098257 | 0.091591 | -6.78% | pass |
| 10-byte 64 KiB batches | stdlib forced | 0.011598 | 0.010475 | -9.68% | pass |
| Direct 8 MiB one-feed decode | zlib-ng | 0.004123 | 0.004165 | +1.02% | pass |
| Direct 64 MiB one-feed decode | zlib-ng | 0.032373 | 0.032466 | +0.29% | pass |
| Ticker 8 MiB one-item decode | zlib-ng | 0.004620 | 0.004666 | +0.99% | pass |

| Full binary read | stdlib forced | 0.012061 | 0.012424 | +3.01% | pass |
| Concurrent independent reads | stdlib forced | 0.018333 | 0.018530 | +1.08% | pass |
| JSONL bounded batches | zlib-ng | 0.046997 | 0.044754 | -4.77% | pass |

Direct decoding remains linear: the candidate's 64 MiB/8 MiB duration ratio
is 7.79 for an 8x fixture-size increase. Scheduler maximum gaps were stable:
0.695756 ms to 0.697459 ms at 8 MiB and 0.704884 ms to 0.707489 ms at
64 MiB.

The full binary-read peak allocation was exactly 33,571,197 Python bytes for
a3 and the candidate under both engines. The supplement also records bounded
JSONL batch counts and maximum batch characters, four independent streams,
output sizes, and digests. Maintained-example tests separately assert handle,
batch, staging, and queue high-water invariants; the supplement is
informational rather than a noisy absolute memory gate.

## Greater-than-5% investigations

Initial five-sample captures contained noisy flags. Every positive slowdown
over 5% was repeated with more samples, CPU affinity where applicable, and
paired exact-source runs. The controlled residuals are:

| Row | Engine | a3 median | Candidate median | Delta | Candidate MAD |
| --- | --- | ---: | ---: | ---: | ---: |
| High-level 32 MiB incomplete FCOMMENT | zlib-ng | 0.00230655 | 0.00242749 | +5.24% | 0.00013222 |
| Direct 64 MiB incomplete FCOMMENT | zlib-ng | 0.00237942 | 0.00257375 | +8.17% | 0.00006731 |
| Direct 4 MiB filename, one feed | zlib-ng | 0.00015259 | 0.00016520 | +8.27% | 0.00001002 |
| Direct 16 MiB comment, one feed | zlib-ng | 0.00066172 | 0.00069805 | +5.49% | 0.00002584 |

These rows are below the 10% blocker, are sub-millisecond parser-only
measurements with MADs material relative to the deltas, and do not identify a
new proportional code path. Analogous stdlib, fragmented-feed, completed
header, and other-size rows remain within policy. The previously noisy direct
output-bound 1024 row fell from an unpinned +11.24% observation to +4.64% in
the controlled 11-sample run. Direct scaling, scheduler gaps, semantic hashes,
and retained-memory results remained stable. No optimization or waiver was
introduced from these observations.

## Quality and artifact evidence

The frozen candidate passed:

- default zlib-ng suite: 2,319 passed, 1 skipped;
- forced stdlib suite with zlib-ng installed: 2,319 passed, 1 skipped;
- initial library-only coverage suite: 2,319 passed, 1 skipped, 92.98%;
- focused contract/integration suite: 435 passed;
- Ruff lint and format checks;
- mypy and `ty` over `src` and `examples`;
- strict MkDocs build;
- `uv run prek run --all-files`.

Independent review correctly noted that the initial coverage source list did
not measure `examples/` even though their behavior was extensively tested.
The review correction added both maintained examples to the formal source
list. The resulting full gate passed with 2,377 tests, one skip, and 91.78%
combined coverage; the fragmented-transport example measured 78.09% and the
concurrent-ingest example 88.81%. The unrecorded example lines are principally
CLI/self-test paths exercised in subprocesses. The same corrected tree passed
2,377 tests with one skip under forced stdlib and 2,350 tests with 20 skips in
an isolated `[test,csv]` environment that first asserted `zlib_ng` was absent.

The repository's CI definition already covers Linux Python 3.11–3.14,
Windows 3.12, macOS 3.12, zlib-ng, no-zlib-ng, and forced-stdlib modes. This
local record does not claim that remote CI ran against this candidate.
