### Exit criteria (§14.1)

- **Generated public sequences.** `tests/stateful/generator.py` generates
  deterministic scenarios over binary and text reads (`read`, `read1`,
  `readinto`, `peek`, `readline`, `readlines`, iteration), `tell`,
  absolute, relative and backward seeks, text cookies (`tell_mark` /
  `seek_mark`), `buffer_read`, writes, source and sink failures,
  validation and limit failures, cancellation, abort, open and close,
  context exit, and rejected overlap. Scenarios vary seekability,
  fragmentation, encodings and newlines, member layouts and padding,
  corruption and truncation boundaries, ownership (`closefd`), and native
  versus custom async sources, with and without checkpoints. Ordering uses
  a gated executor and explicit events; no sleep is a correctness barrier.
- **Model.** `tests/stateful/model.py` holds the lifecycle table (20 rows)
  and the read-health table (29 rows); `observer.py` checks the
  candidate's private state against them after every event.
  `test_read_health_transitions.py` was migrated to the shared table.
- **PR CI set.** `tests/stateful/test_stateful.py` runs seeds 0–999 plus 14
  named regression seeds above that range (1,014 distinct seeds, one test
  each) on every build leg, with model assertions and the observer. (At
  `39a01b7` the regression list also named 943, already in 0–999, so that
  commit ran 1,015 test cases over the same 1,014 seeds.) `test_seed_set_covers_every_table_row`
  requires every table row to be reached, except four rows the generator
  cannot reach (OPENING cleanup precedence, context exit during open, and
  the failed abort cleanup), each mapped to a focused test whose body
  asserts that row through `observer.assert_lifecycle`.
- **Release set.** Seeds 0–5999 (6,000 seeds) on both engines (stdlib and
  zlib-ng), against both references, at `2f85f5b` (source identical to the
  candidate):

  | Reference | Engine | Failed | Seeds claimed, per predicate |
  | --- | --- | --- | --- |
  | C0 | stdlib | 0 | BC7 17, BC8 219, BC9 22 |
  | C0 | zlib-ng | 0 | BC7 17, BC8 219, BC9 22 |
  | b1 | stdlib | 0 | BC2 605, BC3 358, BC7 18, BC8 214, BC9 21, BC10 1 |

  Each candidate run also checks every event against the model and the
  observer, so these are 24,000 model-checked candidate runs (6,000 seeds,
  two engines, two references). The runner
  records the imported `aiogzip.__file__` and active engines of both sides.
- **No unexplained drift.** Every difference from C0 or b1 is claimed by
  exactly one predicate tied to a ledger row (BC1–BC10), with positive,
  near-miss and composition tests in
  `tests/stateful/test_differential.py`. No predicate was widened from

- **Minimization.** No failure needed a minimized regression under
  `tests/data/stateful_regressions/`: each defect has focused regression
  tests, and the seeds that exposed defects or model gaps run in the PR

### Integration cancellation (§14.4)

`tests/integration/test_example_concurrent_jsonl_ingest.py::test_cancellation_inside_native_source_read_settles_before_close`
gates one shard's native source read inside its executor worker and cancels
the top-level ingest. The task cannot finish while the worker holds the
read; afterwards the order is exactly read entered, read returned, handle
closed; no task outlives the ingest; staging is removed and nothing is
published. Replacing `_call_native_source` with a plain executor await
fails the test (the task finishes while the worker still reads).

### Test corrections after sign-off

The first hosted run on the release pull request (see
[G16](#hosted-runs-on-the-release-pull-request)) found three test defects

changes; no `src/` file changed, and Codex reviewed each.

| Commit | Defect | Correction |
| --- | --- | --- |
| `e17a224`, `03ccda7` | Before Python 3.13, CPython's UTF-16 and UTF-32 incremental decoders raise a plain `UnicodeError`, with no `.start`, for a stream that does not start with a BOM; aiogzip passes it through. The model, generator and differential caught only `UnicodeDecodeError`, so seeds 288, 345, 415 and 469 failed on 3.11 and 3.12. | `model.is_decode_error()` accepts `UnicodeDecodeError` or an exact `UnicodeError`; the wire-view expectation re-raises anything else and takes offset 0 when the error carries none. |
| `e17a224`, `03ccda7` | Descriptor counts (`fd_delta`) need `/proc/self/fd`. On macOS and Windows no run records them, so every differential test that compares against the Linux-recorded b1 and C0 references failed. | `differential.FD_COUNTS` records whether the platform counts descriptors. A pair ignores a missing candidate `fd_delta` only where it does not; on Linux a missing field is still a difference. The two tests about `fd_delta` itself skip where counts are unavailable. |
| `e17a224` | `test_exceptional_exit_with_active_native_work_breaks_the_reader` asserted the decoder was discarded as soon as the context exit returned. The exit settles the native call, but the `read()` task can still hold its reservation, and the decoder is kept until that reservation ends, as the [state model](../design/v2.0.0b2-file-state-model.md) specifies. ### Installed manifest check

The runtime manifest check (`scripts/capture_public_api.py --check

  `ty check` on `tests/typing/public_api_positive.py`.

The `build` job also runs the check from source on every leg.

### Negative typing fixtures fail for intended reasons

Each `EXPECT_ERROR` marker in `tests/typing/public_api_negative.py` and
`tests/typing/reject_plain_iterator_close.py` now names its expected error
code per checker (for example
`# EXPECT_ERROR[mypy=arg-type, ty=invalid-argument-type]`).
`tests/_typing_contract.py` parses the markers and the checkers' concise
output; `test_negative_public_api_typing` and the codec-operation rejection
tests assert that the reported `(line, code)` set equals the expected set
exactly, under both mypy and ty. A marker that does not name exactly one
non-empty code per checker (missing, empty, duplicated or unknown), a
diagnostic in another file, a diagnostic without a code, or an error or
warning line the parser cannot read fails the test. Paths are compared
resolved, and Windows drive paths parse (the Windows build leg runs these
tests). `tests/test_typing_contract.py` covers each of these cases.

Mutation checks: an extra error line, a changed expected code and a broken
import each fail the tests. Checker versions: mypy 2.3.1, ty 0.0.84; a
failure message names the checker version that produced it.

### No private type is exported

`tests/test_public_exports.py::test_no_private_type_is_exported` collects
every class named `_…` defined in an aiogzip module (19 today, including
WP6–WP9's `_ReadHealth`, `_StreamBudget`, `_NativeSourceCall` and
`_TextBufferOrigin`, which the test requires to be present) and asserts that
no name in `aiogzip.__all__` or `aiogzip.codec.__all__` is one of them, and
that no exported class inherits from one, except b1's `codec._CodecBase`,
the shared base of `GzipEncoder` and `GzipDecoder`. Exporting a private
class, or a public class derived from one, fails the test.

### Clean-worktree build

`scripts/build_release_artifacts.py --evidence-dir DIR [--ref REF]`:

1. adds a detached worktree of the commit and refuses one that is not clean
   (including ignored files);
2. builds the wheel and sdist there with `uv build`, the same builder CI
   uses;
3. runs `twine check --strict` on both;
4. extracts the sdist and requires its `examples/` and `tests/integration/`
   to equal the commit's byte for byte;
5. installs each artifact with `--no-deps` into a fresh venv outside the
   repository, with the latest aiofiles and aiocsv and the pytest tools,
   and runs `smoke_installed_artifact.py` (which asserts that
   `aiogzip.__file__` is in that venv and not in a checkout, then runs the
   manifest check and the codec, file, streaming, inspect, verify, CLI and
   aiocsv smokes) and `run_maintained_examples.py` (both examples and their
   integration tests), from a working directory outside the repository.
   For the sdist the examples and tests run from the extracted sdist; the
   wheel ships no examples, so its run uses the worktree copies;
6. writes `inventory.json`: the commit, version, the uv, twine and build
   backend (from the wheel's `Generator`) versions, the interpreter and
   platform, each artifact's size, sha256 and member list, and the digests
   of the sdist's packaged example and integration files, beside the smoke
   and example reports;

##### Code paths

- **Flush (`a53088a`, BC8).** `flush()` and the compressed write it
  triggers now reach a native sink through `_call_native_sink`, a tracked
  `_NativeSourceCall` executor job that a writer abort settles before
  closing the sink. Before BC8, leaving a writer's context with an
  exception during a write or flush closed the sink under the in-flight
  call: a custom sink received a write after `close()`, and a native file
  write failed with "write to closed file". The cost is that settlement
  record per sink call, about 3 µs per flush (100 flushes, +0.3 ms).
- **Small-buffer reads (`ddc8e95`, then `f66c92b`).** The benchmarks open
  the file with `chunk_size=4096` on 2 MiB of random data, so each pass
  makes about 512 native source reads of 4 KiB. `ddc8e95` (WP2, G03)
  routes each one through `_call_native_source`: a `_NativeSourceCall`
  that owns the read's completion so that a cancelled read's bytes are
  kept exactly once instead of lost, and that settles before cancellation
  propagates. `f66c92b` removed one event-loop hop by publishing completion
  from the worker. The remainder is about 2 µs per native source read (read1:
  +1.1 ms over 512 reads). At the default chunk size the same work is
  amortized: stdlib `read(-1)` on 1 MB is +0.6% from WP0. The `read_health`
  rewind and limit-break rows add the same settlement to each native seek.
- **zlib-ng `read(-1)` 1 MB** combines the same per-read settlement with
  `3ef0266` (WP3), which reserves opening ownership and settles native
  acquisition. Its +2.28% of a 0.22 ms operation is about 5 µs per
  operation, consistent with a fixed per-open cost; this has not been
  isolated.
