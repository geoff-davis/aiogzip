1. A fresh no-cache Python 3.12.12 environment outside the checkout
   installed `aiogzip[csv,fast]==2.0.0` from the canonical PyPI Simple
   Index. The first attempt, moments after the upload, did not yet see the
   release; the next one did.
   - The import resolved from the environment's `site-packages`, with engines
     `compression='stdlib-zlib', decompression='zlib-ng', crc32='zlib-ng'`.
2. The wheel downloaded from PyPI had the table's SHA-256.
3. `scripts/smoke_installed_artifact.py --expected-version 2.0.0
   --expected-engine zlib-ng --require-aiocsv`, given that wheel,
   `scripts/capture_public_api.py` and the frozen manifest, exited 0.
4. With pytest, pytest-asyncio, pytest-timeout and hypothesis added,
   `scripts/run_maintained_examples.py` passed: the fragmented-transport
   self-test and 68 example tests.

### 6. Documentation

The documentation run
[39074078389](https://github.com/geoff-davis/aiogzip/actions/runs/39074078389)
on `d75c0ae` deployed docs version `2.0`, titled `2.0.0`, with the `latest`
alias. `versions.json` lists `dev` (still `2.0.0rc3.dev0` until this PR
merges), `2.0` with `latest`, and `1.11` with no alias. The site root
redirects to `latest/`, the `latest` symlink points to `2.0`, and `/`,
`/latest/`, `/2.0/`, `/1.11/` and `/dev/` all return 200.

This deploy ran when #155 merged, before the tag. It finished at
22:12:29Z and the first file reached PyPI at 22:26:19Z, so `latest` served
2.0 for about 14 minutes before 2.0.0 was installable. That is the D3 routing
working as designed, since `main` carried a stable version. Nothing
misrouted, but a future release plan should expect `latest` to move at the
release PR's merge, not at publication.

### 7. Development version

Development moves to `2.0.1.dev0`. Under PEP 440 it sorts after `2.0.0`,
and `scripts/docs_version.py` routes it to the `dev` docs version, so
`latest` keeps serving 2.0.0.
