## Excluded or invalid runs

- An initial exact-`v2.0.0a2` stdlib run from harness commit `937fb5c` was
  interrupted after approximately 71 minutes before it emitted JSON. The
  harness incorrectly applied tracemalloc to complete and incomplete headers
  at all 16/32/64 MiB sizes. The plan's peak-allocation gate is the 32 MiB
  incomplete FNAME/FCOMMENT pair; complete and larger fixtures are wall-time
  cases. No partial measurements were retained. The correction was committed
  before any production change, and all baseline/candidate captures use the
  corrected identical harness.
- A second exact-`v2.0.0a2` stdlib run from harness commit `4fd1b90` was
  interrupted after approximately 55 minutes before emitting JSON. The first
  correction still reused the five-sample primary timing repeat count for
  tracemalloc peaks. Allocation peaks are not wall-time claims; the finalized
  harness records one peak sample by default through an explicit
  `--memory-repeat` option while preserving five samples for every primary
  timed comparison. No partial measurements were retained, and every final
  source/engine/candidate capture uses the same finalized settings.
- Subsequent minimal reproduction established that both interrupted runs also
  hit an execution-environment defect: inside the managed filesystem sandbox,
  `asyncio.run(asyncio.to_thread(len, b"x"))` completes its worker call but
  hangs while shutting down the default executor. Exact 1 MiB compressed
  source items correctly cross aiogzip's decoder-offload threshold, triggering
  the same shutdown hang after the benchmark coroutine. The reproducer exits
  normally outside that sandbox. All final benchmark captures therefore run
  in the approved local unsandboxed environment; they remain credential-free
  and perform no network I/O. A 1 MiB final-harness smoke then completed in
  2.2 seconds and confirmed five primary samples plus one allocation sample.
