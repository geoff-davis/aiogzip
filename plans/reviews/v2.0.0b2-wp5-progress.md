## Initial F7 fairness repair

Ready empty source items previously bypassed every checkpoint. Nonempty feeds
also restarted the driver's work/output budgets, allowing repeated individually
small operations to monopolize the event loop.

The initial repair counts every accepted source item before an empty-item skip.
A private ceiling of 256 items triggers a deliberate checkpoint before the next
source pull. The existing 16 MiB source-byte backstop now applies to compression
as well as decompression. Both share the driver's existing output-byte/chunk and
consecutive no-output-byte/step budgets across start/feed/finish operations.
A new operation or an executor await does not reset streaming counters: an
already-ready await need not yield. A deliberate checkpoint resets the shared
budgets. Consecutive no-output counters still reset when visible output occurs.

File callers omit the optional stream budget and retain their existing driver
accounting. No producer task, queue, source prefetch, public empty output, or
public tuning API is added. Cancellation at a checkpoint propagates through the
existing operation close, codec discard, and source-close ownership paths.
This is the scoped BC5 scheduling correction authorized by the plan.

The 256-item ceiling is an initial private choice, not a wall-clock latency
promise or completed throughput qualification. Existing single-operation budgets
still bound large-item progress. Representative throughput and latency comparisons
must qualify the choice before G08 closes.

The two F7 reproductions are ordinary passing assertions. New coverage checks
sibling progress before finite ready sources finish (empty items, tiny items,
and empty gzip members), output/raw-work budgets across operation boundaries,
already-ready executor results, cancellation cleanup without source prefetch,
and infinite empty sources under an external subprocess watchdog.
