# WP5 G06 long-line measurement preparation

This increment adds a measurement harness and its checks, with no production
changes. G06 remains open for comparative qualification; C0 is not pinned.

`scripts/measure_b2_long_lines.py` separates resource observations from timing.
Resource mode records append work, Python allocation and before/after RSS, with
no wall-clock measurements. Timing mode has no append wrapper or allocation
tracer and requires quiet-machine interleaved captures. The original WP0 scaling
harness and its attested captures are unchanged.

The 175-row matrix includes:

- Fifty scaling rows: 1/2/4/8/16 Mi characters, all five newline modes, UTF-8 and
  ISO-2022-JP, 64 KiB chunks, no terminator.
- Eighty controls: 1 Mi characters, 4 KiB/256 KiB chunks, repeated or seeded
  printable ASCII content, ending in CRLF or a final trailing CR, both encodings
  and all newline modes.
- Ten split-CRLF controls: seeded ASCII in both encodings, 1 Mi characters minus
  one before CRLF and 64 KiB chunks, placing CR at the last byte of a decoded
  input piece, in all newline modes.
- Twenty-five incompressible controls: 1/2/4/8/16 Mi Latin-1 characters, seeded
  random bytes with CR/LF excluded, all newline modes, 64 KiB chunks. Every
  fixture must retain at least 99% of its encoded size after gzip compression.
- Ten short-line controls: 32,768 lines of 30 characters plus CRLF, the default
  256 KiB chunk size, both encodings and all newline modes. These include the
  generic-path throughput controls required after the origin-snapshot change.

Seeded printable ASCII is a higher-entropy control, not a claim of completely
incompressible input. Repeated Japanese exercises the stateful encoding. The split resource rows are backed by tests observing CR and LF on opposite
sides of actual binary refills. Broader decoder replay, cookies, limits, rollback
and salvage remain covered by the public/structural pytest modules rather than
inferred from benchmark output. The matrix is factorized, not every possible cross-product.

Fixtures, hashes, independent stdlib reference lines and open precede measurement.
Collecting returned lines is included. Complete output is checked afterwards.
Append work sums lengths presented to `_append_buffer`, so it exposes growing
prefixes; it does not count actual allocator copies, final joins or slicing, and
makes no scanning-work claim. Fast paths bypass this hook, so a zero count does
not mean zero copying. The baseline generic search already used an incremental
search offset; the candidate searches new chunks plus a carried CR. Allocation peaks do include those other Python
allocations. Unlimited lines inherently need O(N) result storage. Tracemalloc
omits native allocations; RSS is a point observation, not a peak. Rows share a
process and therefore allocator history. Only unlimited iteration is measured;
bounded readline is covered by separate structural tests. Resource and later
timing doubling ratios will be calculated in the evidence record. The supplied
chunk size reaches both the binary reader and text refills; each sample checks
and records the binary chunk size.

Use clean cea195d as the pre-accumulator baseline and a clean candidate containing
55c1e3e's fix, with the same committed harness and interpreter for both. This
isolates the accumulator change from the earlier cookie fix. Source/harness commit,
tree/status, import origin, engine, fixture hashes and host load/affinity are
recorded. Commit the harness before capturing either side; record evidence in a
separate commit. The frozen overnight G08 job remains unchanged.
