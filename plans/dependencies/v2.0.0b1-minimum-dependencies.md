## aiofiles investigation

There is no aiofiles release named `23.0.0`. Although `23.1.0` is the oldest
published 23.x release, it does not satisfy aiogzip's owned-file close
contract. This minimal reproduction was run from both Python 3.11 and 3.12
wheel environments:

```python
import asyncio
from pathlib import Path

import aiogzip


async def main() -> None:
    path = Path("floor-probe.gz")
    async with aiogzip.AsyncGzipBinaryFile(path, "wb") as file:
        await file.write(b"x")
    print(path.stat().st_size)


asyncio.run(main())
```

With aiofiles 23.1.0 this printed `0`: that release's delegated `close()`
returns a generator-based awaitable, while the unchanged a4 close path awaits
objects exposing `__await__`. The owned file therefore remained open and
unflushed. The same failure on Python 3.12 rules out a Python 3.11-only
requirement marker.

`aiofiles==23.2.0` produced the expected 33-byte gzip member but is yanked on
PyPI for a Windows import issue. `aiofiles==23.2.1` produced the expected
member, closed the underlying file, and passed the full applicable suite.
Raising the uniform floor to 23.2.1 avoids a b1 runtime behavior change and is
the smallest non-yanked compatible choice.

## aiocsv investigation

PyPI's release metadata contains no `aiocsv==1.2.0`. The exact resolver probe
failed with:

```text
Because there is no version of aiocsv==1.2.0 and you require
aiocsv==1.2.0, your requirements are unsatisfiable.
```

The next two published releases, 1.2.1 and 1.2.2, both failed to build on
Python 3.11 at `aiocsv/_parser.c` because they include the removed private
header `longintrepr.h`. Version 1.2.3 is the first release that builds on the
oldest supported interpreter; its two integration tests and the full
applicable suite pass. The optional floor is therefore raised to 1.2.3.

Each environment installed the wheel with `--no-deps`, then exact runtime
versions with `uv pip install --python <venv>/bin/python ...`.

The CSV test is ignored only in modes where aiocsv is intentionally absent.
`test_source_root_attestation_identifies_current_checkout` is deselected in
all four modes because its purpose is to require a source-checkout import,
which is the opposite of this installed-wheel test. Every other applicable
test ran.

The committed `minimum-dependencies` CI job repeats the four modes on Python
3.11, asserts exact versions and optional-package absence with
`scripts/report_runtime_versions.py`, checks active and forced engine
selection, runs the installed API and typing contract, smokes the wheel from
outside the checkout, runs both maintained examples at the base floor, and
runs the full applicable suite. Existing latest/unpinned jobs remain in place.

The same gates were also run locally against the post-metadata wheel. All four
installed-wheel smokes passed. The base floor matched the public API manifest,
and its positive fixture passed mypy and ty. The fragmented-transport self-test
passed, and the concurrent-ingest example published three partitions with 120
rows, 6,570 bytes, and digest
`da984903329763970288bb264a05cc963923e054a1aa717d4a5880b35e0f0b0f`.
