## Clean reference and validation, after G06–G08 acceptance

- Select a clean committed source after the correctness/performance packages and
  before any enum/origin/bridge state refactor. A dedicated clean worktree avoids
  treating the intentionally untracked original plan as reference-source changes.
- Record full commit and tree IDs, environment/lock hashes, engine selection and
  the public manifest hash. Use `scripts/capture_public_api.py` and the established
  public contract at `tests/data/public_api_2_0.json`; retain actual outputs and
  compare the frozen public API rather than assuming unchanged signatures.
- Re-run both full engine suites and affected integration tests against that exact
  source. Record executed commands, environment, outcomes and provenance; distinguish
  local runs, reviewer runs and hosted CI. Run all-file prek before the record commit.
- Capture semantic traces with the committed trace harnesses, compare b1 unchanged
  scenarios and exact allowlisted corrections, and attach targeted benchmark evidence.
- Fill the C0 record with commit/tree/public-manifest hashes, trace hashes, exception
  ledger revision and G06–G08 dispositions. Leave no placeholder that looks like a pin.
- Pin a local reference only. Do not create or push a release tag. Verify the ref
  resolves to the recorded commit/tree, then close G09 only after review.

Only then may WP6 begin. Its three-state read-health change must match C0 semantics;
it must not hide additional correctness changes or weaken the independently asserted
corrected cases. The post-processing tools do not perform any of these pinning actions.
