## Long-line repair

The repair is clear. The worst baseline cases improve by up to 84.83% (stdlib)
and 90.12% (zlib-ng), for example `newline=""` and the seeded Latin-1 controls
at 16 MiB. On the generic newline paths (`""` and `\r\n`, including the
Latin-1 controls), the baseline's 8→16 MiB doubling medians are 2.94–4.56
(stdlib) and 3.69–4.97 (zlib-ng); the candidate's are 2.05–2.42 (stdlib) and
2.04–2.66 (zlib-ng).

### Investigation

All probes were exploratory, outside qualification, on a busy host (load
average 2–8). The probe scripts and four outputs are archived with the
evidence; the fresh-process output in item 2 printed only to the terminal and
is archived as Claude's transcription of it. They support the disposition,
not qualification.

1. **Source.** Only two source commits separate cea195d from 2f78925. 2f78925
   changes compression only. 55c1e3e changes the generic-newline line path; on
   the single-character `\n` and `\r` paths these rows use, it only widens the
   pending-origin tuple by one element. No plausible per-row algorithmic
   regression of 7–11% exists there.
2. **Fresh processes.** Timing the exact harness fixture and operation alone
   (`async for` over the 16 MiB ISO-2022-JP fixture), interleaved across
   cea195d, 55c1e3e and 2f78925 on both engines, gave all three within about
   1–2%, with no consistent direction.
3. **Matrix order.** The harness runs all rows in one process. Running its
   `run()` over rows 0–47 with the qualification sampling, alternating
   baseline and candidate, reproduced the zlib-ng gap at rows 45 and 47:
   baseline 81–83 ms against candidate 87–88 ms. stdlib was ambiguous. Row 43
   is the 16 MiB ISO-2022-JP generic `newline=""` row, whose allocation
   behavior 55c1e3e changes substantially.
4. **Allocator intervention.** The same zlib-ng run with glibc's mmap threshold
   fixed (`GLIBC_TUNABLES=glibc.malloc.mmap_threshold=131072`, which disables
   its dynamic adjustment) removed the gap: baseline 89.7–94.3 ms, candidate
   88.1–90.9 ms.

This is a qualification-visible, order-dependent allocator-state effect: the
earlier generic rows leave glibc's allocator in a different state by rows 45
and 47. No intrinsic fresh-row slowdown was demonstrated. That is not a claim
that no slowdown can occur in a long-lived process. No repair is justified:
reworking the correct generic fix or the fast path to steer glibc state would
be unsound.

### Candidate scaling above 2.5

Seven zlib-ng candidate 8→16 MiB doubling medians exceed 2.5 (2.507–2.672),
across UTF-8 and ISO-2022-JP and several newline modes. Fresh-process minima on
zlib-ng (exploratory, busy host):

| Family | Baseline 8→16 MiB | Candidate 8→16 MiB |
| --- | ---: | ---: |
| ISO-2022-JP `\n` | 2.444 | 2.580 |
| ISO-2022-JP `\r` | 2.577 | 2.593 |
| ISO-2022-JP `""` (generic) | 4.505 | 2.540 |
| ISO-2022-JP `\r\n` (generic) | 4.282 | 2.499 |
| UTF-8 `None` (control) | 2.778 | 2.778 |
| UTF-8 `\r` (control) | 2.778 | 2.824 |

The baseline and the unchanged fast-path controls show comparable excess
scaling, consistent with a size or platform effect; its cause was not
measured. The repaired generic paths improve sharply. There is no evidence of
a candidate-specific scaling regression. The ratios stay descriptive, with no
universal complexity claim.

## Maintainer dispositions (2026-10-04)

The maintainer accepted all four on October 4.

1. **The long-line repair is confirmed** on both engines.
2. **The ISO-2022-JP 16 MiB `\n` and `\r` flags** are recorded as a
   qualification-visible, order-dependent allocator-state effect, with no
   intrinsic fresh-row slowdown demonstrated, and accepted without repair.
3. **Candidate 8→16 MiB ratios above 2.5:** comparable excess scaling
   appears in the baseline's single-character paths and the UTF-8 controls,
   while the generic paths improve sharply; no candidate-specific regression
   is demonstrated. The ratios stay descriptive.
4. **Inconclusive rows** are accepted without a speed claim. The maintainer
   accepts their uncertainty for G06; this neither establishes the absence of
   a regression nor upgrades the measurements.
