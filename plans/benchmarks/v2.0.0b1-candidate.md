# aiogzip 2.0.0b1 benchmark candidate

> **Status:** local exact-a4 performance gate passes; hosted CI remains pending
>
> **Date:** 2026-08-31

## Provenance and method

The primary baseline is exact tag commit
`262d9a5a0eb5f84fc54432e968b845b182fd255c` (`v2.0.0a4`). The primary codec
candidate is clean commit `0534a64c92b1d6bca91c975582c60e68f99339f0`.
The codec baseline and candidate used the same regression harness, whose
SHA-256 is
`64c3c0e2431ac265b10736940bcddebb8c775f9e6cf6115dc3a26d21a3af6d27`.

The controlled a3 and a4-supplement recaptures compare the exact a4 checkout
with clean candidate commit `08f2517798d671cd8f3586cd1b6636a4a02f49fd`
under the same Python 3.12.12 environment and CPU-0 affinity. The only runtime
source difference between exact a4 and that candidate is
`aiogzip.__version__`; the intervening changes are tests, documentation,
metadata, CI, artifact tools, and benchmark progress output. The a3 matrix
uses 21 timing samples and one allocation sample. The supplement uses nine
samples. Fixtures, ordering, statistics, and thresholds were not changed.

Every harness prints `START <benchmark name>` before entering a timed row.
This makes a long-running case distinguishable from a stalled process without
placing output inside the measured region.

Policy is applied per comparable named row: at most 5% slower passes, more
than 5% requires investigation, and more than 10% blocks release. Negative
percentages below mean the candidate was faster.

### Investigated codec threshold crossing

The stdlib `direct output bound 262144 bytes` row moved from 96.44 us to
101.87 us, a 5.63% or 5.43 us slowdown. Baseline samples ranged from 94.90 us
to 112.20 us; candidate samples ranged from 100.21 us to 117.76 us, so the
sample distributions overlap. The output byte count, output digest, chunk
count, maximum chunk, engine-call count, and fixture digest are identical.
The zlib-ng form of the same row moved by only +2.08%. The source operation is
unchanged from exact a4, and no related size or scaling row regressed. This is
a small sub-millisecond timing fluctuation, is below the 10% blocker, and is
accepted as investigated noise rather than a performance claim.

## High-level, member, and write matrix

In the first CPU-pinned stdlib comparison, two complete-FNAME 64 MiB rows
reported +18.94% (high-level) and +10.69% (direct). The equivalent zlib-ng
rows in the adjacent comparison moved in the opposite direction, -19.35% and
-13.74%, despite both engines targeting the same unchanged source. This
engine-dependent reversal identified ordering, cache, or frequency noise.

Following the locked investigation policy, the complete header category was
recaptured with the candidate first and exact a4 second, retaining the same
fixtures, 21 samples, statistics, and CPU affinity. The two affected rows then
measured +3.41% and +9.19%. The remaining +9.19% direct row is a 0.266 ms
difference on unchanged code and remains below the 10% blocker. Both captures
are retained in the raw evidence rather than replacing the noisy first result.

The controlled write and member rows were stable:

| Surface | stdlib range | zlib-ng range |
| --- | ---: | ---: |
| write curve, 10 B through 256 KiB | -2.27% to +2.14% | -2.64% to +4.64% |
| concatenated members, 1/2/1001 | -0.83% to +1.94% | -0.57% to +1.72% |
| 10-byte one-call diagnostic | -0.75% | +0.02% |

The 10-byte diagnostic remains an active anti-regression row and comfortably
passes the exact-a4 10% gate. No cross-call buffering was introduced.

## a4 supplement

| Row | stdlib change | zlib-ng change |
| --- | ---: | ---: |
| bounded JSONL `iter_batches()` | -0.87% | +0.20% |
| full binary read throughput | +1.21% | +1.19% |
| full binary read peak-allocation timing | -26.95% | -0.59% |
| concurrent independent-file reads | -12.70% | -1.29% |

The allocation row's timing is informational. Its measured peak changed only
0.0023% for stdlib and 0.0184% for zlib-ng. Codec peak allocations were equal
to the byte or within 24 bytes of exact a4. Scheduler p95 and maximum gaps for
the one-item and empty-block cases were unchanged or lower apart from
sub-microsecond zlib-ng maximum-gap changes. There is no memory or scheduler
regression.

## Disposition

The local exact-a4 performance, correctness-bearing benchmark, memory,
scheduler, high-level integration, and retained tiny-write gates pass. No
performance improvement is claimed for b1. Hosted CI and independent review
remain separate release gates.
