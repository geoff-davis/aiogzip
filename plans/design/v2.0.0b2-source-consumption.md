# WP2 source consumption and settlement

BC2 prevents a failed read of gzip(A) followed by successful decoding of only
gzip(B). Decoder progress alone cannot establish source health. The maintainer
explicitly selected terminal failure for unknown-effect custom-source exceptions,
with retries preserved only where no effect can be proved. This includes ordinary
exceptions as well as cancellation; it is an intentional compatibility correction.

## Source policy

| Source outcome | Policy |
| --- | --- |
| Cancellation before the read starts, or native submission rejected | No source effect; preserve the healthy reader |
| Native read succeeds after cancellation | Retain its bytes, including an empty EOF result, in one pending slot; propagate cancellation; deliver on retry |
| Read or seek fails with an unchanged authoritative synchronous cursor | Preserve retry/rollback behavior |
| Custom read cancellation or any source error with changed/unknown cursor | Terminal non-validation failure; no buffered salvage or successful suffix-only read |
| Rewind succeeds after native cancellation | Remain terminal: physical position may have changed without decoder reset; another successful rewind is required |
| Physical rewind completes successfully | Reset decoder and buffers; discard pending input superseded by the rewind |
| Non-seekable rewind with complete cached prefix | Replay the prefix before any pending physical bytes; never treat an empty prefix as EOF |
| Uncertain consumption leaves a hole in the replay cache | Invalidate and disable cache recovery; require physical rewind or reopening |

`_source_io.py` recognizes aiofiles' unmodified binary delegates
(`AsyncBufferedIOBase`, `AsyncBufferedReader`, `AsyncFileIO`). Both library-opened
files and caller-supplied delegates use their configured loop/default or custom
executor. The loop must match the active loop before submission. Subclasses or
instance overrides of the invoked delegate method follow the custom-source
contract; the adapter does not silently bypass their behavior.

The native call records a cursor checkpoint in the worker before invoking the
underlying method. On failure, a matching final cursor establishes no effect only
under the ordinary byte-stream contract. Failure evidence is read by the owner
only after the actual executor future is terminal. `_settle_before_cancel` from
WP1 shields that privately retained future, preserving the first cancellation and
chaining any simultaneous native failure. No cancellable aiofiles coroutine task
is substituted for native completion, and no new executor or background producer
is introduced.

## Input ownership and ordering

The active binary reservation owns source acquisition through publication. A
single `_source_work` future identifies native work; normal read/seek/close calls
remain rejected while the reservation is active. After cancelled native success,
`_pending_compressed_chunk` retains exactly one result without copying it. It is
consumed before another physical read and cached exactly once at that point.
Standard native reads bound that slot by the configured chunk size. Existing
replay-cache limits remain independent of the single pending result.

A failed bulk/text read restores its prior output only while the reader remains
healthy or in the existing validation-salvage state. Native cancellation with
retained input therefore preserves earlier output; uncertain consumption invokes
non-validation poison, also notifying the text wrapper. Buffered bytes cannot
conceal a missing compressed interval. CRC/output-limit salvage rules are unchanged.

## Custom-source completion contract

Custom `read()` and `seek()` must finish all source access before returning or
raising, including on cancellation. No hidden background mutation may outlive that
boundary. A truthful synchronous `tell()` is optional, but required to establish
no effect after an invoked custom method fails. Its nonnegative integer must fully
identify the next compressed byte, including consumption before an exception;
a counter updated only on successful returns is insufficient. No-effect inference
is unavailable from an async `tell()`, a missing/failing checkpoint, or a source
whose reported cursor does not account for all consumption.

Existing no-effect fixture sources now expose that cursor explicitly. Their
retry/rollback assertions and b1 semantic outcomes remain unchanged; this is not
an allowance for unknown-effect sources to keep retrying. The public async-read
protocol gains no required method or signature.

Exceptional context exit marks the reader aborted. Native work is allowed to
settle before close. A cooperative custom read/seek is cancelled and its completion
boundary is awaited before close; a notification future is allocated only when
this path needs it. Existing aborted-call `OSError` behavior remains. `closefd=False`
still leaves borrowed resources open. A blocked native call or non-cooperative
custom source can delay settlement indefinitely; the library cannot forcibly
terminate arbitrary threads or hidden work safely.

## Evidence requirements

`tests/test_source_read_settlement.py` covers header/body/trailer/member boundaries,
repeated and before-start/after-completion cancellation, errors before/after cursor
advancement, binary/text/direct buffer calls, physical and cached rewind, failed
rewind, empty retained EOF, queued custom-executor work, borrowed resources,
exceptional context exit and whole-runner shutdown. Native gates use real threads
with independent watchdogs and `finally` release. Custom gates obey the completion
contract. The original two F2 tests become passing regressions.
