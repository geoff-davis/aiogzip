# v2.0.0a2 WP5 Async Scheduler Policy

> [!WARNING]
> These measurements were captured on an Apple M3 MacBook Air. They validate
> WP5 locally, but the release scheduler and throughput gates remain incomplete
> until the identical commands are rerun on the Framework Desktop used for the
> published GitHub benchmark numbers.

## Framework follow-up

The release-reference run showed that first-step executor dispatch on every
256–512 KiB decoder source item missed the central 512/256 KiB throughput gate.
The final candidate keeps the 256 KiB compression threshold but uses 1 MiB for
decoder inputs. Its no-output byte checkpoint is tightened to 128 KiB so the
500 KiB empty-block fixture still gives a sibling task progress without an
executor hop. Fragmented inline sources checkpoint before processing more than
16 MiB cumulatively.

## Provisional decision

Keep the private scheduler policy at:

```python
_ZLIB_OFFLOAD_THRESHOLD = 256 * 1024
_INLINE_OUTPUT_BYTES_CHECKPOINT = 1024 * 1024
_INLINE_OUTPUT_CHUNKS_CHECKPOINT = 4096
_NO_OUTPUT_BYTES_CHECKPOINT = 1024 * 1024
_NO_OUTPUT_STEPS_CHECKPOINT = 8
```

Only the first raw advancement of a threshold-sized operation is offloaded.
Later byte blocks and output-only slicing stay inline. The async driver
checkpoints after any fairness threshold and resets all counters after either
an executor hop or checkpoint. Visible output resets the consecutive
no-output counters.

`_engine.py` no longer imports `asyncio` or owns executor policy.
`_codec_async.py` owns executor and cooperative scheduling. The concrete codec
operation has one private raw-advance method, while its public `Iterator[bytes]`
surface consumes private progress events internally.

## No-Output Progress

The valid fixture contains 100,000 empty DEFLATE blocks, is 500,054 compressed
bytes, and expands to 26 bytes. Stdlib `gzip.decompress()` validates it before
measurement. Each of nine samples under each engine recorded:

- exactly two inflate calls;
- exactly one private progress event covering 237,892 compressed bytes;
- zero empty public chunks;
- the expected 26 output bytes and SHA-256;
- ticker progress before completion.

| Engine | Median | MAD | Minimum ticker count | Largest observed gap |
| --- | ---: | ---: | ---: | ---: |
| stdlib | 0.653 ms | 0.015 ms | 24 | 1.183 ms |
| zlib-ng | 0.468 ms | 0.042 ms | 18 | 1.411 ms |

Deterministic tests separately prove that every raw advancement performs at
most one inflate call and that the byte and step thresholds independently
produce a checkpoint.

## Throughput Check

The policy recorder interleaves nine enabled and nine disabled-checkpoint
samples using the same 8 MiB fixture and streaming helper. This isolates
checkpoint cost from the thermal and scheduling dispersion visible after the
full direct-scaling matrix.

| Engine | Case | Enabled | Disabled | Policy delta | v1.11 M3 | Historical delta |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| stdlib | 64/64 KiB | 3.975 ms | 4.030 ms | -1.4% | 10.668 ms | -62.7% |
| stdlib | 512/256 KiB | 4.885 ms | 4.823 ms | +1.3% | 6.801 ms | -28.2% |
| zlib-ng | 64/64 KiB | 3.978 ms | 3.900 ms | +2.0% | 9.461 ms | -58.0% |
| zlib-ng | 512/256 KiB | 4.764 ms | 4.655 ms | +2.4% | 7.281 ms | -34.6% |

All named cases remain within the historical hard gate, and checkpoint cost
is below the plan's 5% tuning trigger. The full release-profile records are
also committed. Their zlib-ng stream cases were more dispersed because the
candidate runs the new direct-codec matrix before streaming while v1.11 skips
that unsupported matrix; the interleaved isolated cases above are the
checkpoint-policy comparison.

An initial five-repeat zlib-ng throughput run was discarded as insufficient
after the 64/64 median had material dispersion. It was rerun with nine repeats
and replaced before commit; no baseline file was changed.

  `1608 passed, 1 skipped`.

  runs under each engine.

cleanup errors.
