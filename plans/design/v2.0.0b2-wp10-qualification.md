## G14: stateful differential harness (§14.1)

### Shape

A seeded generator, not a Hypothesis state machine. Sequences must replay
byte-for-byte in a subprocess against another source root (C0, b1), so each
sequence is plain JSON produced from an integer seed by `random.Random(seed)`.
Hypothesis stays for the existing focused properties.

- `tests/stateful/generator.py`: `generate(seed) -> Scenario`. A scenario
  fixes the configuration (mode `rb`/`rt`, encoding and newline, member
  layout, fragmentation, seekability, source kind, `chunk_size`) and an
  operation list.
- **Operations:** `read(n)`, `read1`, `readinto`, `peek`, `readline(limit)`,
  `readlines(hint)`, one iteration step, `tell`, absolute, relative and
  backward `seek`, `seek` to an earlier text cookie, direct `buffer` reads,
  `close`, context exit, and the injected events below. Every scenario starts
  with an acquisition step: `open()`, `async with`, or the module factory,
  over a path (native acquisition) or an external file object. Acquisition
  events cover a failed open, cancellation during native acquisition, an
  initialization failure after acquisition (the gzip header write failing on
  a write-mode open, or the native file wrapper failing, as in the WP3 open
  traces), open/open and open/close overlap (`ConcurrentOperationError`), and
  `open()` after close, which must raise `ValueError` because a closed
  instance cannot be reopened. A new handle on the same path is the reopen
  case. These exercise BC3 differentially. Writes get their own
  smaller generator (write, writelines, flush, sink failure, cancellation,
  close), checked against the model by decompression and differentially
  by raw output.
- **Configuration space:** seekable or not; native file (`aiofiles`), custom
  async source and `FramedAsyncReader` with chosen frames; single, multiple
  and empty members, NUL padding, corrupt CRC/ISIZE, truncation, an exact
  `max_decompressed_size`; utf-8, utf-16 and shift_jis with every `newline`.
- **Injected events:** a source failure with no effect (with a `tell`
  checkpoint) or with consumed input; cancellation while a source read or
  native work is in flight; overlap (a second call while one is parked);
  close during an active call; context-exit abort. Ordering uses events and
  barriers on the fake source; there are no sleeps. Before a parked call
  is released, the loop gets a fixed number of turns to settle the
  cancellation or abort. An executor job other than the parked call (C0's
  exit closing a native file on another worker, for example) can still be
  running then. The release waits for such jobs to finish, woken by
  their completion, and then gives the loop a fresh round of turns
  (commit 2: under load C0 seed 5511 otherwise varied between runs; 192 of
  192 loaded repeats now match). C0 is still nondeterministic on seed 959,
  in 49 of 6400 loaded runs: both outcomes pass the comparison, so only
  its claim counts vary.
- `tests/stateful/interpreter.py` drives a scenario through public
  operations only, so the same interpreter runs unchanged against b1, C0
  and the candidate. It emits a symbolic trace in the existing oracle
  format (symbolic cookies, exception type and message class, no per-call
  I/O counts), plus the harness witnesses described below, reusing
  `scripts/compare_file_state_trace.py`'s conventions.
- Every sequence runs under a hard `asyncio.timeout`; a timeout fails the
  test (§14.1).

### Public replay and candidate-only observation

Two layers, kept separate:

1. **Public replay** (`interpreter.py`). It performs public operations
   only, so it runs against b1, C0 and the candidate. Its trace records
   what a caller can see (returned data, exceptions, `closed`, `tell()`
   symbolically) plus harness witnesses. Most witnesses are the fake
   source's and sink's own facts: reads or calls after close, close calls,
   and whether a parked custom-sink call resumed. The parked-call record
   below is the exception, because it inspects an implementation object.
   Writers use a fixed `mtime=0`, so raw output is comparable across roots.
   The final event records the decoded output and the raw output: as raw
   bytes in scenarios with an `abort` or `cancel` event, otherwise as a
   length and digest. An event that parked a sink write records the parked
   call: whether it was custom or native, the bytes it carried, and, for a
   custom sink, whether the call resumed (rather than being cancelled
   while parked) and the bytes it accepted. Those bytes are kept raw in the same
   abort/cancel scenarios. For a native sink, the call's description comes
   from the callable submitted to the harness's gated executor: aiofiles'
   `partial` on C0 and b1, `_NativeSourceCall` on the candidate. This is the
   replay's one inspection of an implementation object, and is
   instrumentation, not caller-visible behavior. It fails closed:
   an unrecognized callable records no bytes, and `BC8-WRITER-ABORT` then
   accepts nothing for that event. Error messages replace the per-run
   temporary directory with `$WORKDIR`.
2. **Candidate observation** (`observer.py`). Runs only against the
   candidate, in-process, after each replayed operation. It may read private
   state (`_read_health`, `_eof`, decoder liveness, reservation flags,
   observer attachment) and checks it against the model's expectation. It
   never feeds back into the public trace.

### Model

`tests/stateful/model.py` holds two importable tables, written from the
documented contracts (the [open-ownership](v2.0.0b2-open-ownership.md),
[read-health](v2.0.0b2-wp6-read-health.md) and
[bridge](v2.0.0b2-wp8-bridge.md) designs), not from the implementation.

**Lifecycle and ownership table.** One row per handle:

- **Lifecycle:** UNOPENED, OPENING, OPEN, CLOSED.
- **Resource:** none, held locally by the opener (unpublished), published.
- **Ownership:** owned (path acquisition, or an external object with
  `closefd=True`) or borrowed (an external object with `closefd=False`).
- **Reservations:** the open/close reservation, and the read or write call
  reservation, each idle or active.
- **Text binding:** for text handles, whether observers are attached.

Events and expected outcomes:

| From | Event | Outcome |
| --- | --- | --- |
| UNOPENED | A read, write or other reserved call | `ValueError` (file not opened); no state change |
| UNOPENED | `close()` | CLOSED; nothing was acquired, so nothing is closed |
| UNOPENED | `open()` starts | OPENING; open/close reservation active; resource none, then held locally |
| OPENING | Acquisition or initialization succeeds | OPEN; resource published with no suspension in between; reservation idle; text observers attached |
| OPENING | Acquisition fails, or is cancelled after native acquisition | UNOPENED; a natively acquired resource is closed exactly once before the error or cancellation propagates; nothing published |
| OPENING | Initialization fails (header write, native wrapper) | UNOPENED; an owned resource is closed exactly once; a borrowed external object is not closed; the open/close reservation stays active until cleanup settles |
| OPENING, cleanup | Cleanup raises an ordinary `Exception` | The original opening exception propagates with its cause unchanged; the cleanup error is added as a note |
| OPENING, cleanup | Cleanup raises a non-`Exception` `BaseException` (cancellation, including repeated cancellation, or an interrupt) | The `BaseException` propagates once cleanup has settled, with the opening failure as its `__context__` and the opening failure's own cause unchanged. Cancellation requested during cleanup does not interrupt it: the resource is closed exactly once. A close call that itself raises is never retried, so the resource is closed at most once |
| OPENING | Overlapping `open()` or `close()` | `ConcurrentOperationError`; no state change |
| OPENING | Exceptional context exit | Body exception propagates; no closure claimed; the opener still owns its resource |
| OPEN | `open()` | `ValueError` (already open); no state change |
| OPEN | Reservation-taking read or write call starts | Call reservation active; an overlapping reservation-taking call raises `ConcurrentOperationError`. Calls that take no reservation, such as text `tell()` during an active read, are allowed and are checked by cookie replay |
| OPEN, call active | `close()` | `ConcurrentOperationError`; no state change |
| OPEN, call active | Context-exit abort | CLOSED; read health BROKEN, retained; resource closed if owned; text notified |
| OPEN, call active | Context-exit abort whose underlying close fails or is cancelled | OPEN; read health BROKEN; text notified; the body error, or the cancellation, propagates; `close()` later retries the underlying close. Unlike `close()`, an abort latches CLOSED only once the resource is closed |
| OPEN | `close()` | CLOSED; read health and `eof` retained as they were; an owned resource closed exactly once, a borrowed one never; observers detached |
| CLOSED | `close()` | No state change. A text handle whose binary file was closed directly still surfaces encoder bytes it could not write, as `ValueError` |
| CLOSED | `open()` | `ValueError`; a closed instance is not reopened |
| — | New handle on the same path | An independent row; the reopen case |

**Read-health table.** HEALTHY, VALIDATION_SALVAGE and BROKEN plus `eof`,
moved by no-effect source failure, consumed-effect failure, cancellation,
validation failure, salvage exhausted, successful rewind, failed rewind and
abort. Health and `eof` are defined from OPEN onward and are retained,
unchanged, across close: a closed reader keeps the health and `eof` it had,
as C0 does (`test_close_of_a_broken_reader_keeps_health_and_eof`). Abort
sets BROKEN before closing.

Combination rules tie the tables together. For example, CLOSED implies that
an owned resource is closed, the binary holds no reference to text, and no
call reservation is active, while health and `eof` keep their last OPEN
values. Every reachable (lifecycle, health, `eof`) combination is listed,
including CLOSED with each health state.

Completions found while building the harness. Each restates a documented
contract the first draft of the tables left out; none is a tolerance:

- **An abort with no active call is a close.** Exceptional context exit
  aborts only a call that is active; when none is (the body raised, or an
  abort's call finished before exit), exit closes normally, retaining
  health and `eof`. Only an active call takes the context-exit-abort row
  and BROKEN.
- **A consumed-effect failure at the end of the source consumes nothing
  physically,** but the implementation can prove that only with a
  checkpoint. The fake source reports it with its own message; the model
  expects a no-effect failure when the source has a checkpoint and an
  uncertain one otherwise, as for any injected no-effect failure.
- **Cancellation of an unhealthy reader's call** (a recovery rewind): a
  proven no-effect cancellation keeps VALIDATION_SALVAGE or BROKEN; an
  uncertain one makes VALIDATION_SALVAGE BROKEN.
- **Rewinds are parked too.** The generator parks a `seek0` for abort,
  cancellation, overlap and close-during-call on any rewindable source,
  which found BC9.
- **A clean empty result proves the end (commit 2).** When a modeled
  reader's position is uncertain on a stream that must reach validated
  EOF, an empty result that asserts EOF (iteration stopping, an empty
  `readlines`, an empty `readline` with a nonzero limit, an empty sized
  read) narrows the position to the end of the allowed data before the
  result is checked. Without it, the model later demanded validated-EOF
  evidence it had already been given (seed 4946); a test disables the
  narrowing and expects those violations back.

Migration: `test_read_health_transitions.py` asserts against the read-health
table, and the focused opening tests (`test_b2_open_ownership.py`,
`test_open_settlement.py`, `test_open_qualification.py`, which owns the
cleanup-precedence states, and `test_file_lifecycle.py`) assert their end states
against the lifecycle table wherever they check states. The tables and the
focused tests therefore cannot drift apart.

The G14 record reports coverage of both tables in two columns: transitions
inferred from the public trace (for example, a validation error, then
salvage data, then a broken-stream error; or `ConcurrentOperationError` plus
the fake resource's close count), and transitions inspected privately by the
observer (reservation flags, observer attachment, decoder liveness).

The expected bytes come from the generator, not from decoding the produced
file. The generator builds each member from a known clean payload, so the
model knows every member's payload and boundaries before corruption:

- **Clean members:** expected output is the concatenated payloads.
- **CRC or ISIZE corruption:** the DEFLATE body is intact, so the member's
  full payload is the expected provisional output, followed by the
  validation error; the salvage contract (C0) then serves exactly that
  payload's undelivered remainder, then a broken-stream error.
- **Truncation of a valid body:** the bytes before the cut are a prefix of
  a valid DEFLATE stream, so any engine can emit at most the member's clean
  payload. The model accepts any delivered prefix of the expected payloads
  that is no shorter than the payload bytes of earlier complete members,
  followed by an error. This allows engine buffering differences without
  accepting lost or invented data.
- **Body corruption:** malformed DEFLATE has no cross-engine output bound;
  stdlib zlib and zlib-ng may emit different bytes before detecting the
  error. The reference is therefore engine-matched per leg: the generator
  feeds the corrupted member body to the raw decompressor
  (`wbits=-15`) of the engine that `aiogzip.engine_info().decompression`
  reports for that leg (`zlib.decompressobj` on stdlib legs,
  `zlib_ng.zlib_ng.decompressobj` on zlib-ng legs). A single
  `decompress(body)` call is not a reference: it raises at the bad code and
  discards everything it inflated in that call, while aiogzip may already
  have returned that output from earlier bounded steps. The reference is
  instead built on a fixed schedule: feed the body one compressed byte at a
  time, and for each byte call `decompress(data, 1)` repeatedly (passing
  `unconsumed_tail` back in) until a call returns no output and leaves no
  tail; append the output of every successful call and stop at the first
  engine error. Because each call can produce at most one byte, every byte
  the engine can inflate before reaching the bad code is captured, so the
  reference is the largest prefix that engine can emit. Scenario evidence
  retains the schedule's name and version (`raw-1in-1out/v1`), the reference
  length, the compressed offset of the failing byte and the engine's error
  message. A corruption the engine does not detect (it inflates to garbage
  and fails only at the trailer or stream end) is not a body-corruption
  scenario. Whether an engine detects a random overwrite depends on the
  fixture: a prototype detected about 7% on one 300 KB payload and about
  half on others. The generator therefore
  re-rolls until the reference schedule reports an engine error, and records
  the number of re-rolls. The model accepts any delivered prefix of that
  leg's reference under the same lower bound, followed by an error.
  A focused oracle test (`tests/stateful/test_oracle.py`) pins the
  schedule. It uses a corruption more than 64 KiB of output past the start
  of the body, and asserts on both legs that a one-shot `decompress` raises
  with no output, that the reference captures that output, and that
  `GzipDecoder` and `AsyncGzipBinaryFile` output across several
  `chunk_size` and `output_chunk_size` values is always a prefix of the
  reference. Each scenario records the reference engine, and the
  run fails if it differs from the engine the candidate (or C0, or b1)
  reports on that leg. A C0 or b1 differential compares implementations on
  the same leg only, never across engines.
- **Text:** an incremental model, not `io.TextIOWrapper` over a finished
  prefix. The allowed bytes go through `codecs.getincrementaldecoder(encoding)`
  with `final=False`, then the newline stage `TextIOWrapper` itself uses:
  `io.IncrementalNewlineDecoder` with `translate=True` for `newline=None`
  and `translate=False` for `newline=""`, and no newline decoder for `"\n"`,
  `"\r"` and `"\r\n"`. A gzip failure can end inside a multibyte character, so at a gzip
  failure the expected text is that `final=False` output: every complete
  character, then the gzip error, with the incomplete tail retained. The
  newline stage, by contrast, is finalized at that boundary: a pending CR
  is resolved as a line end (`"\n"` for `newline=None`, `"\r"` for
  `newline=""`). Every continuation of the bytes decodes to text that begins
  with that resolution, so emitting it is a correct prefix. (The first model
  held the CR; b1, C0 and the candidate all emit it, and that disagreement
  was recorded as model finding F1b.) Only the returned text is resolved.
  The `newlines` record stays unresolved at a failure boundary, because the
  continuation could have made the CR part of a CRLF; b1, C0 and the
  candidate all leave it unrecorded, and the model expects that. After a validation failure the
  drained salvage obeys the same rule, and a salvage that completes no
  character ends in the broken-stream error, never `''` (ledger BC7). This holds only when
  every byte the reference allows is valid in the encoding. Truncation of a
  valid payload satisfies that. DEFLATE body corruption can emit bytes that
  are invalid for the encoding, so for text scenarios the generator keeps a
  body corruption only if the whole engine-matched reference prefix decodes
  without error under `final=False`, re-rolls it otherwise, and records the
  check per scenario. Body corruption that emits invalid encoded bytes stays
  binary-only in the stateful run. No existing test covers invalid decoded
  bytes racing a gzip body-corruption error (`test_text_io.py`'s `errors`
  tests use valid gzip streams), so WP10 adds one focused regression in
  `tests/test_text_io.py`: a UTF-8 member whose clean payload contains
  invalid bytes ahead of a body corruption, read under `errors="strict"`
  and `errors="replace"`, with the invalid bytes placed both more than one
  `chunk_size` ahead of the corruption and inside the refill that reaches
  it. It pins which error surfaces first, the text delivered before it, the
  read-health state after each, and that a retry does not re-deliver text.
  The expected ordering is not predicted here: the test is written against
  C0's observed behavior, and any candidate difference is classified under
  the differential rules like any other mismatch.
  `final=True` is applied only at validated EOF, where payloads are valid
  text by construction. For truncation, the generator deliberately places
  cuts both on and inside character boundaries, and records which for each
  scenario, so both cases are attested. If C0 and the candidate agree with each other but not
  with the model at a failure boundary, that is a model finding to
  investigate and record, never a tolerance added afterwards.

After each operation the model checks:

- returned data is exactly the next unread slice of the expected bytes:
  nothing lost, nothing duplicated across retries, and a later valid member
  never hides an earlier lost one;
- a failed stream never reaches validated EOF;
- public outcomes are consistent with the transition table (public replay),
  and private state equals the table's state (candidate observation);
- after close, cancellation or failure, the fake source and sink are not
  touched again, and an owned resource is closed exactly once;
- a rollback restores state that a retry or replay continues identically;
- per-operation work stays bounded, using the source read counters the
  scaling tests already use (no wall-clock thresholds).

### Differential comparison

Post-C0 production changes, inventoried for their public-trace effect:

| Exceptional exit with native work in flight discards a closed reader's decoder | G10 | None (the reader is already closed) | None |
| Observer-failure precedence on close and abort | G12 | None (observers are private) | None |
| Failed abort notifies text, which then refuses further reads | G12 | Yes: after an abort whose underlying close fails, C0 serves one more decoded line; the candidate raises | `C0-WP8-FAILED-ABORT` |

F1a: a text `read()` drain whose salvage ends inside a multibyte character; C0 raises `UnicodeDecodeError`, the candidate returns the complete characters. Rules:

- **Candidate vs C0:** every seed. Traces match exactly, except differences
  that `C0-WP8-FAILED-ABORT` claims. This closes the ledger's pending C0
  trace comparisons for BC4 and BC5.
  `BC7-TEXT-SALVAGE`, `BC8-WRITER-ABORT` and `BC9-REWIND-ABORT` also claim
  differences, under the rules below.
- **Candidate vs b1:** every seed. A difference is claimed only by a
  predicate named for one ledger exception, BC1 to BC9. No other allowance exists; b1's
  traces already contain the a3 behavior.
- **Event-wise composition.** A seed may carry several independent
  corrections; against b1, for example, seed 584 differs at a cancelled
  native read (BC2) and later at an aborted native rewind (BC9). Each
  predicate therefore claims specific differing events, and for the final
  event specific fields; it never accepts a whole trace. A seed passes
  when every differing event and every differing final field is claimed
  by exactly one predicate, and everything unclaimed matches exactly. An
  unclaimed difference fails the seed, and so does a difference that two
  predicates claim. A predicate's conditions on its own claimed events
  are evaluated as written, against the full traces and scenario for
  context; it places no condition on events claimed by another predicate.
  Events are aligned by key: the scenario index and the op the
  interpreter recorded. Both traces must carry the same keys in the same
  order, except for one-sided events, which a predicate must claim
  explicitly. Only `BC3-OPENING` clause O2 claims one-sided events.
- **`BC7-TEXT-SALVAGE`** applies to both comparisons. It claims an F
  event: a text `read` whose read health is VALIDATION_SALVAGE at that
  event. The `read` is a top-level op, the call of an `overlap`,
  `close_during` or `cancel` (its outcome is the row's outcome, and the
  rows' second outcomes must be equal), or the call of an `abort` that
  finished before parking (its outcome is the row's second outcome, and
  the rows' first outcomes must be equal). Parked records and witnesses
  must be equal on both sides. (Amended in commit 2: the C0 run reaches
  F events at all three call positions: `overlap` in seeds 2512, 2575
  and 3152, `cancel` in 921 and `abort` in 3134.)
  - **Exact salvage.** The bytes a reader drains before a validation
    failure are computed, not bounded. For truncation they are the
    payloads before the truncated member plus the engine's raw-DEFLATE
    output for that member's body up to the cut,
    `raw_reference(wire[start + 10 : cut])`, capped at the member's
    payload length. For CRC, ISIZE and body corruption they are the
    model's allowed bytes. Truncation is the validation case where the
    allowed bytes exceed what the reader can drain, so it needs the
    oracle (seeds 4819, 921, 2575 and 3608).
  - **Remaining text.** For a modeled reader, the remaining text is the
    boundary text of the salvage (`text_model(..., boundary=True)`) from
    the model's exact position; an uncertain position is not claimed. A
    reader whose position the model does not track (for example after a
    text `buffer_read` pulled bytes from under the decoder) is replayed. The replay covers
    the candidate's events since acquisition or the last successful
    `seek0`. Text reads, `buffer_read`, `tell_mark`, `open` and failure
    arming are allowed. Each `buffer_read` must carry the new `pulled`
    witness (the decompressed `[start, end)` it returned, recorded from
    `buffer.tell()` before the call). The pulled ranges are excised from
    the salvage, and the text returned since the reset must be a prefix
    of the result's boundary text. A refused rewind leaves the reader
    unchanged. Any other event, a `buffer_read` without the witness, or
    two text results from one concurrent call fails closed (seeds 3134,
    2575, 3152 and 3608).
  - **Clause F1a:** only for an unbounded `read` (size normalized to -1,
    which includes `read(None)` and negative sizes): the reference raises
    `UnicodeDecodeError` whose message reports an incomplete tail
    ("unexpected end of data", "truncated data" or "incomplete multibyte
    sequence", the wording of the supported codecs), and the salvage ends
    inside a character. The candidate's return value must equal the
    remaining text exactly. When no complete character remains
    (F1a-empty), the candidate gives the broken-stream refusal instead.
    Sized `read(n)` already held the incomplete tail in b1 and C0, so the
    fix did not change it.
  - **Clause F2:** for sized and unbounded `read` alike: the reference
    returns `''` and the candidate raises the broken-stream `OSError`.
  - **Later events.** It also claims the later text reads (`read`,
    `readline`, `readlines`, iteration) of the same reader that differ only
    because of the F event's outcome. Each is the broken-stream refusal on
    the candidate's side, and on the reference's side one of: the F
    event's outcome repeated; for F2, the empty result; for F1a, text
    that the reference serves from what it held back, where everything
    served after the F event, concatenated in order, must remain a prefix
    of the candidate's F text. (C0 seeds 2500 and 3152 have later
    events.) The symmetric F2 case, a
    reference refusal against a candidate empty result, is also claimed.
  - Its near-miss tests cover a healthy reader (clean EOF `''` must still
    match), a binary reader, a non-`read` op, a `UnicodeDecodeError`

### First b1 comparison: findings and amendments

The first b1 comparison (b1 `048700f`, seeds 0 to 5999, both engines) failed
460 seeds on stdlib and 461 on zlib-ng. Three harness and model defects were
fixed in `3ecc4fe`: the parked-open witness, fd isolation between seeds, and
the lossy model's pre-trigger view. After that fix, 334 seeds fail on each
engine, the same seeds on both. C0 still passes all 6000. Codex reviewed the
amendments below with four precision edits (D, F2, G native, H, I as now
written) and this order: (1) D and the narrow I; (2) E's trigger-only clause,
F1 and G custom; (3) the tightened F2, then a rerun and reclassification;
(4) the shared E/G-native oracle and H's loss epochs. H waits for the oracle
because a later loss can be mid-member. Each amendment's seeds stay unclaimed
until it is implemented and tested.

Step 4a (the oracle, E and G native, below) leaves 32 failing seeds on each
engine, the same seeds (217 after step 3). C0 still passes all 6000 on both,
and BC9 claims the same 21 b1 seeds as before. Of the 32:

- 18 fail in the lossy model and 4 (53, 1559, 2473, 5712) differ after the
  lossy run's rebase. Both groups are expected to be H, and each is to be
  confirmed there.
- 6 are the deferred broken refusal (F2).
- 4 are residue: 899, 2228, 3525 and 5254.

Step 4b (H, below) leaves 13 failing seeds on each engine, the same seeds:
44, 647, 899, 1404, 1833, 2719, 3228, 3497, 3525, 3645, 4925, 5254 and 5712.
C0 still passes all 6000 on both, and BC9 claims the same 21 b1 seeds. Of
the 13:

- 6 are the deferred broken refusal (F2): 44, 647, 3228, 3497, 3645, 4925.
- 2 are later losses H does not model (2719, 5712; see H).
- 2 fail in the lossy model with a `UnicodeDecodeError` on valid text
  (1404, 1833), so they are not H.
- 3 are residue: 899, 3525 and 5254. Residue seed 2228 was H.

- **D. Rebase needs a physical rewind and converged state** (about 30 of
  the 51 lossy-model failures fail after a `rewind_ok` rebase). `rewind_ok` is
  not evidence that b1's source moved. b1 answers `seek0` or `seek_mark` at
  decompressed position 0 without a source call, so after seed 584's loss it
  stays on the lossy wire to the end: its abort at op 13 parks nothing and
  returns `0`. That abort is a BC2 residual, not BC9. Proposal:
  - The interpreter records, outside the compared trace, the absolute
    source seeks that completed during each event: a custom source's `seek`
    calls, and native `seek` calls seen by the gated executor, with their
    targets. Each run record keeps them as evidence (`seeks`).
  - The lossy model switches back to the true view only at an event where
    BOTH its own model makes a successful rewind (`rewind_ok`) AND the
    event's recorded seeks include one to an offset at or before the lost
    range's start. A cancelled call never switches the view, even when its
    native seek ran (that is G).
  - The view switch is not the span's end. The span ends at the first event
    after which the candidate's model and the lossy model are both certain,
    at the same position, with the same health and `eof`, and the lossy
    model is on the true view. A physical rewind alone is not enough: after
    a relative seek, b1's position stays ahead by the lost length (seed
    168). If they never converge, the span runs to the end of the trace.
    Run records carry each model's per-event state (`states`) for this.
  - Seed 584 then stays lossy to the end, and BC2 claims its op-13 abort.
    The hand-built `b1_584` test reference, which followed this section's
    earlier shape (BC9 at 13), is replaced by b1's recorded run.
- **E. Mid-member lost ranges.** 185 seeds (127 custom L1, 58 native L2,
  classified by their first unclaimed difference) lose a range with an
  endpoint inside a member. They stay unclaimed until an engine-matched incremental
  lossy-wire oracle exists. That oracle feeds `wire[:a] + wire[b:]` through
  the engine, including header and trailer failure and text decoding.
  - **The oracle (step 4a).** `wire_reference` in `tests/stateful/oracle.py`
    (schedule `wire-1in-1out/v1`) is an independent model of the decoder's
    member loop over a whole decoder input:
    - zero padding is skipped only after a completed member;
    - each RFC 1952 header is checked: magic, method 8, reserved flags, the
      optional fields, and FHCRC when present;
    - each raw DEFLATE body goes through the leg's raw decompressor under
      `raw-1in-1out/v1`;
    - each CRC32/ISIZE trailer is checked.

    It returns:
    - every byte the members yield before the first failure;
    - `validated`, the bytes guaranteed before that failure is terminal: the
      completed members' output, or the whole member for a CRC or ISIZE
      mismatch, as the payload model already does;
    - the completed members' spans;
    - the failure stage: `header invalid`, `header truncated`,
      `body invalid`, `body truncated`, `trailer truncated`, `trailer crc`,
      `trailer isize`, or none for a clean end.
  - **The wire view.** `lossy_scenario` keeps the structural payload model
    for ranges that start and end on member boundaries. A range with an
    endpoint inside a member gets a `wire` view (`_wire_scenario`). That view
    carries:
    - the spliced wire;
    - `corruption = {"kind": "wire"}`;
    - no payloads or spans;
    - `lossy_range`.

    `expectation()` judges the view by the oracle over its wire. Upper is the
    output and lower is `validated`. The view is clean only when there is no
    failure; otherwise the failure is `validation`.
  - **Decompression limit.** When the oracle's output passes the limit, the
    limit fails first: upper is the output up to the limit, lower is 0, and
    the failure is `limit`, as for a clean limit scenario. One order is not
    determined: a body that inflates past the limit and then fails, while
    the validated output is at or under the limit. A batched inflate can
    raise before it emits the bytes past the limit, so that view is refused.
  - **Text.** The text view holds the bytes before the first sequence the
    scenario's incremental decoder cannot decode, and lower is capped there.
    Such a wire must fail; a clean wire whose bytes are not text is refused.
    A reader's `UnicodeDecodeError` is not modeled and stays a violation.
    The gzip failure lies past those bytes, so a reader may raise it first.
  - **Evidence.**
    - Over the generated read scenarios (seeds 0 to 5999, both engines, the
      4206 without a limit), the oracle reproduces the payload model's
      expectation exactly: upper, lower and clean. For a truncation, whose
      structural upper bound is the whole truncated member, the oracle gives
      the exact inflatable prefix instead. A test pins seeds 0 to 399.
    - The library's `GzipDecoder`, at feed sizes 1, 13 and 1 MiB, agrees
      with the oracle on every stage case and on 120 random lost-range and
      120 replayed-prefix wires. A clean wire decodes exactly. A failing one
      raises after at least the validated bytes and never more than the
      oracle's.
    - Over the same splice on member boundaries, the wire view and the
      structural view expect the same.
  - **Trigger-only clause kept.** It now applies only where no lossy view
    exists. 169 and 232 go to the lossy run and are claimed there.
  - **Original narrow claim.** For L2, when the trigger row differs only by b1's
  one-sided `taken` and every other event and every final field matches
  exactly, the trigger row is claimed without a lossy run. b1 rewound
  before it observed the loss, so no public difference exists (17 seeds,
  e.g. 169, 232, 236). Implemented as `bc2_trigger_only`: native source,
  read mode, healthy before the trigger, the trigger is an L2 trigger whose
  candidate row has no `taken`, the seed has no other event, final or
  one-sided difference, and no BC2 request exists (an eligible range goes
  to the lossy run instead).
- **F. Abort of an active call, inventoried under BC2.**
  - **F1, a parked native read.** Claimed at the `abort` event only when
    both rows park the same native `read`, the candidate's second is
    exactly `OSError: read aborted because the gzip file was closed while
    the call was active` and its row carries `taken` (its read completed and
    settled), b1's second is exactly `OSError` with the message `Error
    reading from file: I/O operation on closed file` (no final period) and
    no `taken`, both primaries are exactly `InjectedAbort` `abort at <i>`, and `closed` matches in the
    final record (28 seeds, e.g. 290, 1426). Implemented as
    `bc2_aborted_native_read`. The candidate's `taken` must be a valid wire
    range (`wire_range`: a JSON list of exactly two non-Boolean integers
    with `0 <= a <= b <= len(wire)`; an empty range at the end of input is
    valid). Every BC2 trigger witness passes the same check before use; a
    malformed one makes no trigger.
  - **F2, a custom-source call not parked at the source.** The candidate
    aborts the still-active call. b1 lets it finish with its own outcome: an
    injected failure, a validation or limit error, or the broken refusal
    (28 seeds, e.g. 4, 99, 44, 621). Claimed at the `abort` event only when
    the candidate's second is exactly the read-aborted `OSError` and a
    shadow run reproduces b1's second. The shadow run is a fail-closed
    metamorphic check: the same pinned candidate, engine and scenario, with
    `ops[:i] + [call]` (the abort's call without the abort). It must have
    zero model violations, its trace must equal the candidate's exactly
    through event `i - 1`, and the shadow call's outcome and witness must
    exactly equal b1's second and witness. That the model would accept b1's
    outcome is not enough. No outcome list is enumerated. Implemented as
    `shadow_scenario` and `bc2_shadow_claim`: the abort's call is a read
    call on a custom source in read mode; both primaries are exactly
    `InjectedAbort` `abort at <i>`; neither row has a parked record
    (custom sources park without one) or a `pulled` witness; the
    candidate's row has no `taken`; b1's `taken`, if any, is a valid
    `wire_range`. The runner records the shadow runs on the candidate
    root with `--observe` and keeps them with retained seeds. b1's broken
    refusal (6 seeds, e.g. 44, 647, 3228) is not reproduced: b1's exit
    close marks the stream broken under the parked call, which the shadow
    has no way to show, so those seeds stay unclaimed until separately
    explained.
- **G. Cancelled rewinds, inventoried under BC2 (WP2 design).**
  - **Custom:** a `cancel` of a parked custom `seek0` is an L1 trigger with
    an empty range. The source did not move, b1 keeps its position, and the
    candidate is BROKEN (seed 1956). It uses the same lossy run, with the
    true scenario and the trigger treated as no effect. As for a cancelled
    read, the source has no checkpoint and the reader is healthy before the
    cancel; a cancel from validation salvage (seed 5254) is not covered.
  - **Native:** a cancelled native `seek0` repositions the file without
    resetting b1's decoder, so b1 decodes the wire from 0 with mid-stream
    state (seed 1620: `invalid distance too far back`). It needs the same
    engine-matched oracle as E, but not over a fresh spliced input: the
    oracle replays the compressed prefix consumed before the cancel to
    rebuild b1's decoder state, then feeds the true wire from offset 0 into
    that state (or an equivalent copy of it), because the cancellation moved
    the source without resetting the decoder.
    - **Trigger (step 4a).** Clause G of `_trigger` fires on a `cancel` of a
      parked native `seek0` when:
      - the rows are identical, with the cancel outcome and exactly the
        parked witness `{"via": "native", "method": "seek", "bytes": null}`;
      - b1's record holds exactly one completed seek at that event, to 0;
      - it holds exactly one origin `[p, 0]`, the file offset before the
        seek.

      The evidence is parsed with exact shapes. Every record must be
      `[event index, list]`, and every index, target and offset must be
      exactly an int (`type(x) is int`), so a Boolean or float never stands
      for 0 or for an index. Malformed evidence anywhere in either list
      makes no trigger and never raises.
    - **The origin witness.** The gated executor's parked path probes the
      origin with `tell()` before it calls the seek. It is kept as `origins`
      in the run record: evidence only, never compared, like `seeks`. The
      probe must never change the call. When an abort has already closed the
      file, the probe records nothing and the seek reports the close itself.
      A first version raised from the probe, which changed b1's BC9 outcome
      (BC9 fell from 21 seeds to 0); that was found and fixed in this step.
    - **The range.** `[0, p]` must be a valid wire range with `p` below the
      wire's length. A regular file returns data until its end, so b1 cannot
      have seen the end before `p`, and must read on from offset 0. At the
      wire's end, b1 may already have read the end and then never reads
      again; 2907, 3766 and 3920 do exactly that. That is not witnessed, so
      there is no trigger.
    - **The view.** `replay_scenario` gives decoder input `wire[:p] + wire`,
      judged by the same oracle. The oracle is a deterministic function of
      its input sequence. Decoding the concatenation from a fresh state
      therefore equals the decoder state after `wire[:p]`, then fed the true
      wire from 0. That assumes b1 kept every byte it read before the seek.
      If b1 dropped any, the lossy run rejects b1's trace and nothing is
      claimed. `Bc2Request.taken` is `[p, p]`: a successful model rewind
      with a recorded seek at or before `p` restores the true view (D).
    - **Seeds.** In seed 1620, p is 49 of a 172-byte wire. A fresh decode
      inflates the whole member and fails only its CRC. The replayed state
      fails inside the body, as b1 does. Seed 242 is the other recorded
      example.
- **H. Several losses in one b1 run.** After the candidate's trigger, b1
  keeps reading while the candidate refuses, so b1 can hit later losses:
  armed failures that consume, cancelled reads. The candidate's model never
  sees them. The lossy model orders losses by physical-source epoch.
  Witness ranges are in true-wire coordinates. Deletions accumulate until a
  successful physical rewind (as in D), which restores the true view and
  starts a new loss epoch. The first loss is the shared trigger; each later
  one is a b1 row with its own `taken` witness, or a cancelled parked read.
  Any mid-member loss delegates to E's oracle, or fails closed.
  - **Later loss (step 4b).** After the trigger, `LossyChecker` treats an
    event as a later loss only with its own witness:
    - an `uncertain_failure`, `consumed_failure` or `cancel_uncertain`
      transition whose b1 row carries a `taken` range of exact ints with
      `0 <= a <= b <=` the true wire size;
    - a `cancel_no_effect` on a native source (a native cancel, which the
      candidate settles without effect) whose `taken` range is nonempty,
      the L2 shape; a checkpoint source's `cancel_no_effect` is never a
      loss, since the checkpoint restores the read;
    - a `cancel_uncertain` without `taken` on a custom source without
      checkpoints (the parked read never delivered): an empty loss, as at
      the trigger.

    The transition then takes b1's no-effect meaning (`NO_EFFECT`). Without
    a witness, or with a malformed one, the candidate's semantics stand and
    the event fails closed. An empty loss (`taken` empty, or none) leaves
    the view in force.
  - **Epochs.** The trigger's epoch holds its lost range (none for an empty
    trigger) and ends at a physical rewind at or before the trigger's lost
    start. A nonempty later loss on the true view opens a new epoch at its
    start; within an epoch, ranges must come in wire order (each starting at
    or after the previous end), or the model records a violation. A
    physical rewind over the epoch's first lost start restores the true
    view; this can repeat (`rebases`; `rebased_at` stays the first). A
    later loss over a replayed prefix (G native) is not modeled: a
    violation.
  - **View.** Within an epoch the view is `wire_view` (E's oracle view, now
    in `model.py`) over the true wire with every lost range removed,
    carrying `lossy_ranges`. If the oracle refuses the view (a limit it
    cannot order, or text it cannot decode), the model records a violation.
  - **Record and claim.** The lossy run records `losses` as `[index,
    range or None]` and `rebases`, as evidence. Since each loss opens a
    claim span, `bc2_claim` binds `losses` to b1's rows and claims nothing
    unless all of these hold: the field exists and is a list of
    `[int, None | [int, int]]` at strictly increasing indices; each index is
    a single b1 row strictly after the trigger; a range is exact ints with
    `0 <= a <= b <=` the true wire size and equals that row's `taken`; a
    None loss is a `cancel` row with outcome `{"cancelled": true}` and no
    `taken`, on a custom source without checkpoints. It
    claims the union of the trigger's span and, for each later loss, the
    span from that event's first candidate row until the models converge
    (D), with the same exclusions as before (owned, lossy violations,
    `final`).
  - **Seeds.** Recorded b1 runs: 58, 3626 and 5782 (losses inside the
    trigger's epoch, including adjacent ranges in 3626), 53 and 2473 (a
    cancelled native read after a rebase opens a new epoch), and 2228
    (empty custom cancels).
  - **Not covered.** Seed 2719's empty L2 trigger at EOF is followed by a
    G-native replay (a cancelled `seek0` that ran), a later loss of the
    replay kind, which H does not model; it stays unclaimed. Seed 5712's
    trigger span converges at op 8 while an armed no-effect failure is
    still pending in the candidate (b1 consumed it at op 5), so the
    candidate's op 9 fails where b1 reads; convergence does not compare
    pending injections. Codex's review: 2719 stays fail-closed until a
    separately reviewed later-replay clause can show whether b1 rereads
    EOF; for 5712, the amendment is to record the pending injected-source
    state in each model's `states` and require it equal in `_converged`.
- **I. Acquisition under the lossy model.** In 10 seeds (e.g. 20, 271,
  2716) the lossy model applies the candidate's open/open and open/close
  overlap rows to b1's acquisition, which `BC3-OPENING` claims exactly.
  No lossy violation is suppressed generically. When BC3 already claims
  the acquisition event exactly under O1, the BC2 request names the clause,
  and the lossy model judges that event's contender by O1's b1 lifecycle
  transition (`OPENING` stays `OPENING`; b1's contender error or `ok` is
  BC3's to check) instead of the candidate's `ConcurrentOperationError`,
  and records the normalized event. The comparison requires the record to
  correspond exactly: `[-1]` under O1, `[]` without a clause; a missing,
  duplicate, wrong-index or unknown entry fails the seed. Every remaining
  lossy violation still fails the seed. The current examples (20, 271, 2716) are O1 and end
  `OPEN`; O2 gets explicit mappings and tests before any support.
- **Residue.** About 25 seeds are not yet assigned: `BC2-TRIGGER-UNCLAIMED`
  (2745, 5119, 3525) and other single-event differences (e.g. 199, 670, 899,
  958, 1245, 2228, 2370, 2613, 2947, 3135, 3214, 3738, 4010, 5130, 5254,
