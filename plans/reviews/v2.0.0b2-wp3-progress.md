## Initial repair

The [BC3 policy](../design/v2.0.0b2-open-ownership.md) rejects overlapping open/close
using `ConcurrentOperationError`. Binary and text wrappers reserve opening before
the first suspension and publish only initialized resources. Failed-open cleanup
retains the reservation. Text still closes its failed nested binary wrapper.

Standard aiofiles path acquisition retains a shielded executor future through
native completion. Cancellation retrieves and closes an acquired raw file;
wrapping failure also closes it. Initial native header writes, seekability probes
and failed-open cleanup use the same settlement guarantee. Custom replacements
retain their cooperative completion contract. No helper task or executor is added.
The hot read/write paths are unchanged; initial header handling is separate.

Initial-header byte-count validation matches ordinary writes, including short
writes and rejection of invalid progress. Cleanup exceptions are chained as causes
without replacing the primary initialization failure; this is recorded under BC3.
External file objects are not closed on failed open, preserving the established
retry contract; after successful publication the usual `closefd` behavior applies.
