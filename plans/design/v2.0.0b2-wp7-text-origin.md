# WP7 design: text replay-origin object

WP7 implements plan §11 and closes G11: *text-origin snapshots do not alias;
cookies, newlines and rollback, and hot-path budgets, are preserved.* It is a
representation change compared against C0 (`refs/c0/v2.0.0b2`,
[record](../reviews/v2.0.0b2-c0-record.md)); no observable behavior changes.

## Current state at C0

The text layer's replay origin, the checkpoint a `tell()` cookie and a
`readlines()` rollback rebuild from, is five loose fields on
`AsyncGzipTextFile`, all in `__slots__`:

| Field | Meaning |
| --- | --- |
| `_buffer_origin_offset` | binary byte position where the buffered text began |
| `_buffer_origin_decoder_state` | incremental decoder state at that position |
| `_buffer_origin_trailing_cr` | pending CR from the previous chunk |
| `_buffer_origin_seen_newline_types` | newline-type mask at that position |
| `_buffer_origin_chars_to_skip` | characters already consumed since that origin |

A sixth, related checkpoint, `_pending_read_origin`, holds the same five values
as a tuple while an unpublished read retains decoded fragments (the BC6 cookie
correction, `cea195d`).

**Writers and readers by function** (C0 `_text.py`):

| Function | Role |
| --- | --- |
| `__init__` | initializes all five |
| `_set_buffer_origin`, `_capture_buffer_origin` | set all five from the live decoder at a new origin |
| `_read_chunk_and_decode` | sets all five when a refill starts from an empty buffer |
| `_readline_buffered_reserved` | sets all five on its rollback path; bumps the counter per chunk |
| `_rollback_readlines` | restores all five from a snapshot |
| `_readlines_rollback_state` | reads all five into a snapshot tuple |
| `tell` | reads all five (and `_pending_read_origin`) to build a cookie |
| `_append_buffer` | adds the compacted prefix to the counter |
| `_consume_buffer` | adds a fully consumed buffer to the counter |
| `_read_sized_reserved`, `_next_fast_line` | set or add to the counter around refills |

The counter changes only when a whole buffer is consumed, compacted or
refilled. Per-line consumption moves `_text_buffer_offset`, which is not part of
the origin, so no counter update happens per line.

## Decoder-state contract

The text layer uses `codecs` incremental decoders. Their documented
`getstate()` contract returns `(buffered_input: bytes, state: int)`, both
immutable. Checked for UTF-8, UTF-8-sig, UTF-16, UTF-16-LE, ISO-2022-JP,
Latin-1, Shift-JIS and GB18030: each returns a `tuple[bytes, int]`. A snapshot
can therefore share the decoder-state value; nothing is deep-copied. The
annotation stays the existing `Tuple[Any, int]`, so no supported codec is
narrowed.

## Design

### The checkpoint object

```python
@dataclass(slots=True)
class _TextBufferOrigin:
    byte_offset: int
    decoder_state: Tuple[Any, int]
    trailing_cr: bool
    seen_newline_types: int
    chars_to_skip: int

    def snapshot(self) -> "_TextBufferOrigin": ...   # independent copy
```

The text object holds one live, mutable `_buffer_origin`, replacing the five
slots. The live object is reused for the life of the handle: a new origin
updates its fields in place, so there is no new object per refill or per line.
`snapshot()` returns an independent object for rollback and for
`_pending_read_origin`, which becomes a `_TextBufferOrigin` snapshot instead of
a five-tuple. Snapshots and the live origin never share a mutable object; the
only shared value is the immutable decoder-state tuple.

### Centralized operations

| Operation | Method | Used by |
| --- | --- | --- |
| Capture a new origin from the live decoder | `_set_buffer_origin` (existing) | open, refill from empty, seek, reset |
| Snapshot for rollback | `_readlines_rollback_state` returns the buffer, its offset and an origin `snapshot()` | `readlines()`, buffered readline |
| Restore | `_rollback_readlines` copies a snapshot's fields into the live origin | rollback paths |
| Cookie | `tell` reads the live origin or the pending snapshot | `tell` |

### Pending origin: constructors and lifecycle

`_pending_read_origin` is not a uniform snapshot of the live origin. Its three
producers construct it differently, and each keeps its C0 construction:

| Producer | Construction |
| --- | --- |
| `_read_sized_reserved` (no buffered prefix) | new origin at the current binary position, decoder state, trailing CR and newline mask, with `chars_to_skip=0` |
| `_next_fast_line` (no buffered prefix) | the same frontier construction, with `chars_to_skip=0` |
| `_readline_buffered_reserved` | the saved rollback origin, with `chars_to_skip` increased by the buffered offset at the snapshot |

A pending origin is published once by its producer and never mutated
afterwards; it is a fresh `_TextBufferOrigin`, never the live object. It is
cleared at the three success sites (`_read_sized_reserved`, `_next_fast_line`,
`_readline_buffered_reserved`) and unconditionally by
`_TextReadReservation.__exit__`, which covers every error and cancellation path.

### Rollback ordering (preserved exactly)

The two restore paths keep their C0 order:

- `_readline_buffered_reserved`, when the binary reader allows restoring a failed
  read: restore the buffer and offset and the origin from the snapshot, then
  append the recoverable decoded pieces.
- `_rollback_readlines`, under the same condition: rebuild the buffer from the
  original prefix, the returned lines and the unread suffix; restore the offset;
  restore the origin; then clear the pending-line batch.

The rollback snapshot stays a single value carrying the buffer, its offset and
an origin snapshot, so restore order is visible at each site.

### Hot-path counter (explicitly listed exception)

The counter updates stay inline as `self._buffer_origin.chars_to_skip += n` (or
`= n`) at the sites above, with no helper call. That is one extra attribute
load per buffer event compared with C0, never per line; it is measured below
and covered by the parity tests.

## Tests

1. **Structure:** the five old names are not slots and are never stored or
   deleted in production code (AST check, as in WP6), and `_pending_read_origin`
   holds a `_TextBufferOrigin` or `None`.
2. **Copy independence:** mutating the live origin after a snapshot leaves the
   snapshot unchanged, and the reverse; restoring a snapshot and then mutating
   the live origin leaves the snapshot unchanged.
3. **Pending origin:** a concurrent `tell()` during an unpublished read from
   each of the three producers returns a cookie that replays every character;
   after success, error and cancellation the pending origin is `None`; and
   mutating the live origin while a pending origin is published does not
   change it.
4. **Rollback order:** both restore paths leave buffer, offset, origin and
   pending lines exactly as at C0, including the recoverable pieces appended
   after the buffered-readline restore.
5. **Characterization (§11.2):** UTF-8 at multibyte splits, UTF-16 variants and
   ISO-2022-JP; every newline setting; LF, CR, CRLF and mixed input; trailing CR;
   no final newline; `tell`/`seek` before and after compaction; repeated cookie
   round trips; foreign and stale cookie rejection; sized-read and `readlines()`
   rollback; failed decode; transient source error; approved source-cancellation
   outcomes; validation salvage; and direct binary `buffer` interaction. Much
   of this already exists from WP4–WP6; new tests fill gaps and assert the
   checkpoint itself.
6. **Regression guards:** the WP4 small-hint linear-work tests and the WP5
   long-line work tests run unchanged.
7. **C0 traces and both full engine suites pass.**

## Benchmarks

The same method A as WP6, in one reviewed window: `io,micro` against C0 on both
engines, plus a small targeted `text_origin` category for paths `io,micro` do
not isolate: repeated `tell()`/`seek(cookie)` round trips, `tell()` after
compaction, and small-hint `readlines()` rollback. Allocation is measured
separately by counting `_TextBufferOrigin` constructions, reported per category
so necessary copies are not mistaken for leaks, and an operation that creates
both kinds is reported as both:

| Category | Expected objects |
| --- | --- |
| Live-origin reset or refill | 0 (updated in place) |
| Rollback snapshot | 1 per composite read that snapshots |
| Unpublished-read pending origin | 1 per unpublished read |
| Per line consumed | 0 |
