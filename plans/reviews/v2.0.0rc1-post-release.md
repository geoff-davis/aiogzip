## Windows gate race

The release-merge run failed one test on Windows 3.12:
`TestRepeatedCancellationDuringCleanup::test_failing_close_is_noted[read-inspect]`
in `tests/test_inspection_settlement.py`, added by PR #135 in R13. The test
timed out waiting for the cleanup close to reach its gate. The suite
otherwise passed (7,239 passed, 34 skipped).

The cause is in the test's `_GatedExecutor`. A parked worker signals
`entered` and only then reads `self.release`; `_cancel_again_in_close` swaps
in a fresh release event as soon as it sees `entered`. On a slow runner the
swap can win, so the read worker waits on the new event, the close is never
submitted, and both sides time out. A 0.2 s delay between the signal and the
wait makes all four tests of the class fail every time; taking the release
event before signalling makes them pass with the delay in place. No other
test swaps a gate's release event.

The library is not involved, and the same tree passed on the PR. The fix is
test-only and is reviewed separately, in PR #136. `tests/` ships in the
sdist, so the published sdist still contains the racy test.

## Post-release decision

All RC1 publication, provenance, artifact and documentation checks pass.
Development advances to `2.0.0rc2.dev0`. A `2.0.0.dev0` would sort before
`2.0.0rc1` under PEP 440; `2.0.0rc2.dev0` sorts after it. Before 2.0.0 the
stability policy allows only compatible correctness fixes, documentation and
packaging updates, and semantics-preserving performance improvements. The Beta classifier and the frozen 2.0 compatibility contract
remain in force.

Follow-ups:

1. **Windows gate race** (above).
2. **Python 3.15.** 3.15.0 was released on 2026-10-09, but
   `actions/python-versions` lists only `3.15.0-rc.3` so far. Promote 3.15
   from the informational `python-preview` job into the build matrix and
   branch protection once `setup-python` offers 3.15.0.
3. **Deferred limitations** from the
   [R13 review](v2.0.0rc1-candidate-review.md#remaining-limitations). On
   2026-10-09 the maintainer chose three for the next release, each as a
   compatible correctness fix with a ledger entry and Codex review:
   - N3: a cancellation while an exceptional context exit settles the
     active call skips the close, leaving the file open, and drops the
     body's exception;
   - F2: shielded-future logging on Python 3.14+ from
     `_settle_before_cancel`, which needs a timing check because it is on
     the offload path;
   - the `_acquire_path` cleanup note, which reports a repeated
     cancellation as a cleanup failure and loses a close error behind it.

   Since these change `src/`, the next release is `2.0.0rc2`, not `2.0.0`.
   F3, `writelines()` with empty `str` subclasses, and RC1 plan §5's
   implementation and API opportunities stay deferred past 2.0. Python 3.15
   qualification, feedback intake and the external RC review stay on the RC
   path.

GitHub reports no open Dependabot alerts.
