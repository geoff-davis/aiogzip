# WP3 opening ownership

BC3 selects rejection of overlapping `open()` and `close()` while acquisition or
initialization is active, using the existing `ConcurrentOperationError`. The
reservation is synchronous and lasts through failed-open cleanup. Normal
already-open/closed errors and repeated close behavior remain unchanged.

The opener owns the resource locally until codec construction, the complete initial
header write or seekability probe succeeds. Publication has no suspension point.
Text opening similarly retains its binary wrapper locally until binary opening
succeeds, then installs observers and publishes it. No partially initialized
resource is visible through the ordinary handle fields.

For standard aiofiles path acquisition, a private executor future owns native open.
WP1 settlement shields it through cancellation and runner shutdown. If cancellation
wins after native acquisition, retrieve and close the result before propagating the
original cancellation. Wrapping failure has the same resource cleanup requirement.
Native initialization writes, probes and failed-open close also settle before
resource release. No helper task or new executor is needed.

Custom asynchronous replacements must finish resource access before returning or
raising, as in WP2. Failed acquisition cannot recover a resource that a custom
replacement hides internally. External file objects remain caller-owned until a
successful open; existing failed-open retry behavior does not close them. After
publication, ordinary `closefd` behavior applies. Cleanup errors are chained without
replacing the original acquisition/initialization exception.

local qualification are complete. WP2 PR #99 is independent of this branch.
