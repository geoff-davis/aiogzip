## Exit criteria (§13)

- **Named parity matrices (§13.1).** Eight retained duplications, none merged.
  Four parametrized modules pin them; T1–T5 share one. Each runs scenario
  tables through adapters for the duplicated and reference paths:
  - `tests/test_parity_operation.py` (D1): public `next()` against
    `_advance_raw()`: output, private progress, no-output work, completion,
    failure before and after output, ownership guards including `close()`
    before the first advancement, after one advancement and after
    exhaustion, reentrancy, discard with a retained
    iterator, and release ordering.
  - `tests/test_parity_encoder_feed.py` (D2): `feed()` against
    `_feed_snapshot()`, with public precedence pinned pairwise, so a refactor
    that moved the type check ahead of the state checks fails. The private
    adapter's type-first order is a recorded, tested difference.
  - `tests/test_parity_binary_write.py` (D3): inline `write()` reservation
    against a direct `_write_call`/`_write_reserved` adapter. Covers sink
    outcomes, codec failure, an empty write driving exactly one feed, a
    snapshot taken before the first suspension, position publication,
    cancellation, overlap and close, context-exit abort, waiter release, and
    same-call terminal failure without cross-call buffering.
  - `tests/test_parity_text_inline.py` (T1–T5): text `write()` against the
    reserved batch body; inline origin capture against
    `_capture_buffer_origin()` in every newline mode, with witnesses for
    pending decoder bytes, a pending CR and the newline mask; sized reads
    against buffered readline, including a recoverable source error after
    decoded text; iteration against `readline()` with cookies compared by
    replay on the issuing handle; bounded `readline(limit)` against
    `_take_buffered_line()`.

  Implementer-reported mutation checks (outputs not archived): breaking each
  inline path fails its matrix, including dropping the sized-read restore,
  the inline trailing-CR capture, and the inline byte offset in a fast
  newline mode, which passed before `2f27f5d`.
- **Contributor map.** `docs/contributing.md` lists each duplicate, its
  reference, why it exists, the benchmark that constrains it and the parity
  module that pins it.
- **Last yielded bytes are not completion (§13.2).** Encoder tests collect a
  `finish()` operation by counted `next()`, `break`, `islice()`, full `for`,
  `join`, and early `close()`. The partial styles yield a valid member yet
  leave the encoder reserved and unfinished until `StopIteration`; early close
  abandons it. `docs/codec.md` warns that a chunk completing a valid gzip byte
  sequence does not release the operation. `consumed_size` is not added; these
  tests are the evidence for any future additive helper. The counter-timing
  distinction stays discoverable in the guide's unchanged "Counter timing"
  section: encoder `input_size` and `crc32` move as the operation advances;
  decoder `compressed_size` moves when `feed()` returns, after its input is
  validated and snapshotted; decoder `uncompressed_size` moves as inflate
  steps complete and can lead the chunks already yielded.
- **Dead branch (§13.3).** The end-of-stream `decoder.finish()` loop in
  `_decompress_next` is synchronous, so its inner `except
  asyncio.CancelledError` was unreachable by task cancellation and is
  removed. A comment names the live boundaries: the preceding source read and
  the feed path's driver, whose handler stays. Behavior is unchanged for
  supported engines and ordinary cancellation. A `CancelledError` raised
  synchronously by the codec itself, which no supported engine does, now
  propagates without poisoning the reader, as `KeyboardInterrupt` already did.
  Source-read settlement, native work settlement, native I/O, read-health,
  lifecycle and bridge suites pass on both engines.
- **Private cleanup (§13.4).** `_reserve()` returns `_Operation`, so
  `_feed_snapshot` drops its runtime `cast()`. Public methods still return
  `CodecOperation`; mypy, ty, the typing tests and the b1 manifest are
  unchanged. The executor `workload` argument stays, because the WP1
  native-settlement design documents it as the retention of input until
  settlement. A warning helper is declined: it would add a frame and move
  every stack level.
- **Full suite passes.** Both engine suites at `2f27f5d`: 4,037 passed,
  1 skipped. All-file prek and the strict docs build pass.

## Benchmarks

Method A, as for G10–G12: `io,micro,regressions,text_origin` against clean
C0 and `2f27f5d` worktrees, the same frozen venv, both engines, eight
captures per engine in ABBA ABBA order with five repeats each, pinned to
CPU 13, compared by per-benchmark minimum of capture medians. The regressions
category used the quick profile in throughput mode. Codex reviewed the
scripts, unit and decision rule before the run, including adding
`text_origin` (the map names it for T2) to the design's three categories:
every row more than 5% slower is investigated and recorded; adjacent pair
deltas inform stability but do not decide eligibility.

The maintainer authorized the run, which started manually at 04:16 on
October 6. The quiet gate passed; peak foreign CPU was 0.52 cores (stdlib)
and 0.33 cores (zlib-ng). All 16 captures validated.

- **No row is more than 5% slower on either engine.** Deltas span −1.6% to
  +1.6% on stdlib and −4.1% to +2.8% on zlib-ng.
- **Constraining benchmarks from the map** are within ±2.2%: Small writes
  −1.6% and −1.4%, Text write −0.2% and −0.1%, Text writelines batching
  +0.0% and −0.3%, Line iteration −1.5% and +0.7%, `readline()` loop −0.2%
  and +0.4%, Text large reads +0.3% and +0.1%, Text read (bulk) +0.5% and
  +2.1%, and the `regressions` codec rows within ±1.4% (stdlib) and −4.1% to
  +1.0% (zlib-ng).
- **Largest slower row:** `text_origin readlines(64) loop` at +1.6% (stdlib)
  and +2.8% (zlib-ng), with all pairs positive. The window compares against
  C0 cumulatively, and WP8's window showed the same row at +1.84% (stdlib)
  and +1.77% (zlib-ng). The result is consistent with that pre-existing
  cumulative delta and does not establish a WP9 regression; no cause is
  attributed. (The path reaches the end-of-stream branch changed in
  `1d5e34a` once per file, through the now-unreachable handler.) It is below
  policy and is noted for G17, which re-measures every family against both
  baselines before release.

Evidence, including raw captures, monitor logs, scripts, unit and summary, is
archived in [`data/b2/wp9-g13`](../benchmarks/data/b2/wp9-g13/README.md).
