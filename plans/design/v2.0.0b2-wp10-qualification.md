# WP10 design: stateful, adversarial and installed qualification

Plan §14 and §15, gates G14–G18. WP10 collects final evidence. It adds a
stateful differential harness, closes the coverage and CI gaps listed below,
updates documentation, and ends with the G17 performance windows on the final
candidate. Production code changes only if a test finds a defect; any such
fix gets a ledger entry, review, and a fresh G17 candidate.

References:

- **b1:** `v2.0.0b1` / `048700f` (frozen public API, historical traces).
- **C0:** `refs/c0/v2.0.0b2` / `b074bdc` (oracle for the state refactor).
- **WP0 baseline:** `dc8950c` (pre-change performance baseline,
  [b2 results](../benchmarks/v2.0.0b2-results.md)).

## G14: stateful differential harness (§14.1)

### Shape

A seeded generator, not a Hypothesis state machine. Sequences must replay
byte-for-byte in a subprocess against another source root (C0, b1), so each
sequence is plain JSON produced from an integer seed by `random.Random(seed)`.
Hypothesis stays for the existing focused properties.

- `tests/stateful/generator.py`: `generate(seed) -> Scenario`. A scenario
  fixes the configuration (mode `rb`/`rt`, encoding and newline, member
  layout, fragmentation, seekability, source kind, `chunk_size`) and an
  operation list.
- **Operations:** `read(n)`, `read1`, `readinto`, `peek`, `readline(limit)`,
  `readlines(hint)`, one iteration step, `tell`, absolute, relative and
  backward `seek`, `seek` to an earlier text cookie, direct `buffer` reads,
  `close`, context exit, and the injected events below. Every scenario starts
  with an acquisition step: `open()`, `async with`, or the module factory,
  over a path (native acquisition) or an external file object. Acquisition
  events cover a failed open, cancellation during native acquisition, an
  initialization failure after acquisition (the gzip header write failing on
  a write-mode open, or the native file wrapper failing, as in the WP3 open
  traces), open/open and open/close overlap (`ConcurrentOperationError`), and
  `open()` after close, which must raise `ValueError` because a closed
  instance cannot be reopened. A new handle on the same path is the reopen
  case. These exercise BC3 differentially. Writes get their own
  smaller generator (write, writelines, flush, sink failure, cancellation,
  close) checked by decompression.
- **Configuration space:** seekable or not; native file (`aiofiles`), custom
  async source and `FramedAsyncReader` with chosen frames; single, multiple
  and empty members, NUL padding, corrupt CRC/ISIZE, truncation, an exact
  `max_decompressed_size`; utf-8, utf-16 and shift_jis with every `newline`.
- **Injected events:** a source failure with no effect (with a `tell`
  checkpoint) or with consumed input; cancellation while a source read or
  native work is in flight; overlap (a second call while one is parked);
  close during an active call; context-exit abort. Ordering uses events and
  barriers on the fake source; there are no sleeps.
- `tests/stateful/interpreter.py` runs a scenario using public API only, so
  the same interpreter runs unchanged against b1, C0 and the candidate. It
  emits a symbolic trace in the existing oracle format (symbolic cookies,
  exception type and message class, no I/O counts), reusing
  `scripts/compare_file_state_trace.py`'s conventions.
- Every sequence runs under a hard `asyncio.timeout`; a timeout fails the
  test (§14.1).

### Public replay and candidate-only observation

Two layers, kept separate:

1. **Public replay** (`interpreter.py`). Public API only, so it runs against
   b1, C0 and the candidate. Its trace records only what a caller can see:
   returned data, exceptions, `closed`, `tell()` (symbolic), and the fake
   source's and sink's own counters (reads after close, close calls).
2. **Candidate observation** (`observer.py`). Runs only against the
   candidate, in-process, after each replayed operation. It may read private
   state (`_read_health`, `_eof`, decoder liveness, reservation flags,
   observer attachment) and checks it against the model's expectation. It
   never feeds back into the public trace.

### Model

`tests/stateful/model.py` holds an importable transition table written from
the documented contract, not from the implementation: states HEALTHY,
VALIDATION_SALVAGE and BROKEN plus `eof` and `closed`, and the event that
moves between them (no-effect source failure, consumed-effect failure,
cancellation, validation failure, salvage exhausted, successful rewind,
failed rewind, close, abort). `test_read_health_transitions.py` is migrated
to assert against this table, so the table and the existing focused tests
cannot drift apart. The G14 record reports transition coverage in two
columns: transitions inferred from the public trace (for example, a
validation error followed by salvage data and then a broken-stream error),
and transitions inspected privately by the observer.

The expected bytes come from the generator, not from decoding the produced
file. The generator builds each member from a known clean payload, so the
model knows every member's payload and boundaries before corruption:

- **Clean members:** expected output is the concatenated payloads.
- **CRC or ISIZE corruption:** the DEFLATE body is intact, so the member's
  full payload is the expected provisional output, followed by the
  validation error; the salvage contract (C0) then serves exactly that
  payload's undelivered remainder, then a broken-stream error.
- **Truncation and body corruption:** expected output is bounded. A
  reference `zlib.decompressobj(-15)` fed the member body up to the cut
  gives the largest prefix any engine may emit. The model then accepts any
  delivered prefix of that reference that is no shorter than the payload
  bytes of earlier complete members, followed by an error. This allows engine
  buffering differences without accepting lost or invented data.
- **Text:** the same byte expectations decoded with `io.TextIOWrapper` under
  the scenario's encoding and newline mode, applied to the bytes a byte
  expectation allows.

After each operation the model checks:

- returned data is exactly the next unread slice of the expected bytes:
  nothing lost, nothing duplicated across retries, and a later valid member
  never hides an earlier lost one;
- a failed stream never reaches validated EOF;
- public outcomes are consistent with the transition table (public replay),
  and private state equals the table's state (candidate observation);
- after close, cancellation or failure, the fake source and sink are not
  touched again, and an owned resource is closed exactly once;
- a rollback restores state that a retry or replay continues identically;
- per-operation work stays bounded, using the source read counters the
  scaling tests already use (no wall-clock thresholds).

### Differential comparison

Post-C0 production changes, inventoried for their public-trace effect:

| Change | Gate | Public trace effect | Predicate |
| --- | --- | --- | --- |
| Raising poison observer can no longer skip `decoder.discard()` | G10 | None (observers are private) | None |
| Exceptional exit with native work in flight discards a closed reader's decoder | G10 | None (the reader is already closed) | None |
| Observer-failure precedence on close and abort | G12 | None (observers are private) | None |
| Failed abort notifies text, which then refuses further reads | G12 | Yes: after an abort whose underlying close fails, C0 serves one more decoded line; the candidate raises | `C0-WP8-FAILED-ABORT` |
| Codec-raised synchronous `CancelledError` no longer poisons the reader | G13 | Unreachable through the public API with supported engines | None |

Rules:

- **Candidate vs C0:** every seed. Traces match exactly, except a mismatch
  that `C0-WP8-FAILED-ABORT` accepts. This closes the ledger's pending C0
  trace comparisons for BC4 and BC5.
- **Candidate vs b1:** every seed. A mismatch is accepted only by a predicate
  named for one ledger exception, BC1 to BC6. No other allowance exists; b1's
  traces already contain the a3 behavior.
- **Exactly one predicate per accepted mismatch.** A mismatch that no
  predicate accepts, or that two predicates accept, fails the run. So does a
  predicate that accepts nothing across the release set, unless the record
  says why its scenario cannot arise.
- **Raw retention.** For every accepted mismatch the run keeps the seed, the
  scenario JSON, and both raw traces. Traces are never rewritten.
- **Predicate tests.** Each predicate has a positive test (a hand-written
  scenario it must accept) and a near-miss test (a similar mismatch it must
  reject).
- C0 and b1 run in subprocesses with `PYTHONPATH` pointing to clean
  worktrees, using the current venv, as the benchmark harness does. They
  never run `uv run` inside a worktree.

### Seeds, minimization and CI

- **PR CI:** a fixed seed set, sized to keep the stateful job under about
  60 s per leg, running against the candidate with model assertions only. It
  runs on every build leg; the differential runs need C0 and b1 worktrees, so
  they run locally and in the release run.
- **Release set:** a larger fixed range, run on both engines with the C0 and
  b1 differentials. The G14 record states the exact seed counts and ranges
  run.
- **Minimization:** a failing sequence is shrunk by deleting operations, then
  simplifying configuration, while it still fails. The minimized scenario is
  committed under `tests/data/stateful_regressions/` and runs in every CI
  leg.

### Other G14 work

- **Integration cancellation (§14.4).** The JSONL ingest example cancels the
  top-level task while a shard is inside offloaded native decompression. The
  test asserts that the worker settles before the handle closes, no task
  leaks, staging is removed, and nothing is published.
- **§14.2 map.** The G14 record maps each retained-coverage item to its
  named test, with no new test where one exists.

## G15: public contract (§14.3, §14.4)

- The b1 runtime manifest check (`capture_public_api.py --check`) runs from
  installed wheel and sdist, not only from source. The `installed-artifacts`
  job already does this; the record cites it.
- Negative typing fixtures must fail for intended reasons.
  `test_negative_public_api_typing` already requires an error on every
  `EXPECT_ERROR` line, and a broken import would erase those errors and fail
  it. Two gaps remain: an extra, unexpected error passes, and the error kind
  is not checked. Each `EXPECT_ERROR` marker gains the expected error code
  per checker, and the test asserts that the reported errors are exactly
  the expected set under both mypy and ty, with checker versions recorded.
  The `reject_plain_iterator_close.py` fixture gets the same treatment.
- `test_public_exports.py` confirms that no WP6–WP9 private type is exported.

## G16: environments and artifacts (§14.3, §14.4)

- **Strict docs in CI.** Add a `docs` job to `ci.yml` running `mkdocs build
  --strict` on every PR. Making it a required check is a separate maintainer
  action on the remote (`gh api -X PUT .../branches/main/protection`). The
  record lists it as a maintainer step, with the before and after context
  lists, and does not treat it as part of the code change.
- **Branch coverage.** The release run adds `--cov-branch` and reports branch
  coverage for the modules changed since b1 (`_binary.py`, `_text.py`,
  `codec.py`, `_streaming.py`, the open and settlement helpers). The floor
  stays at 85% line coverage; the record cites branch and transition
  coverage, the latter from the stateful model's transition counts.
- **Clean-worktree build.** `scripts/build_release_artifacts.py` builds the
  wheel and sdist from a clean detached worktree, runs `twine check`, and
  writes an inventory (file list, sizes, sha256) to the evidence directory,
  with the exact versions of `build`, `twine`, the build backend and the
  interpreter.
  Each artifact is installed into a fresh venv outside the repository; the
  script asserts that `aiogzip.__file__` resolves there, then runs the
  manifest check, codec, file, streaming, inspect, verify, CLI and aiocsv
  smokes, and both maintained examples.
- **Runtime attestation in every lane.** Today only the
  minimum-dependencies job runs `scripts/report_runtime_versions.py`. Add a
  step to each `build` leg, both `fast-engine` phases (zlib-ng active, and
  forced stdlib with zlib-ng installed) and each `installed-artifacts` leg. It
  prints and uploads a JSON attestation: the interpreter, the imported
  `aiogzip.__file__`, active compression and decompression engines, and the
  installed versions of aiofiles, aiocsv and zlib-ng. Each lane asserts its
  expected engine selection. The record collects the attestations from one
  green CI run on the final candidate.
- **Matrix.** Unchanged apart from the docs job. Python 3.15 is out of scope
  (§14.3).

## G18: documentation and index (§14.5)

- **Developer state model.** `plans/design/v2.0.0b2-file-state-model.md` is
  expanded in place into the consolidated model: source symbols, the
  read-health and text-origin transition tables, an ownership and settlement
  diagram, C0 as the corrected reference, the text checkpoint design, the
  bridge and its 11-name allowlist, the parity map (linking
  `docs/contributing.md`), performance constraints and the behavior
  exceptions. It cites symbol and test names, not line numbers.
- **User docs.** Operation exhaustion (done in WP9), source-cancellation
  consequences, read-ahead and resource tradeoffs, fairness, and efficient
  line batching. Provisional output, validation completion and recovery data
  are distinguished. No thread-safety or constant-memory overstatement.
- **`plans/README.md`.** Active b2, parked RC (`RELEASE_2_0_0B2_PLAN_REVISION_2.md`
  stays untracked until the maintainer decides), completed plans, all design
  records, reviews and benchmark evidence. Links are checked by the strict
  docs build or a link check over `plans/`.
- **Agent instructions.** `CLAUDE.md` points to the state model and ledger
  as durable invariants instead of repeating plan content.

## G17: performance (§15)

Run last, on the final candidate (the commit that closes G14–G16 and G18).
Any later production change invalidates the windows.

- **Comparisons.** Final candidate vs C0 (state-refactor effect) and vs the
  WP0 baseline `dc8950c` (cumulative effect). Each is a method-A window on
  both engines, using the WP8/WP9 harness with the same runner, venv and CPU
  pinning. The WP0 baseline is recaptured with the current runner through
  `--source-root`; the archived WP0 JSON is not overwritten and is not
  compared directly, since its legacy rows lack matched fixtures.
- **Families (§15.2).**
  - Binary, Text, Decoder preservation and Resources: categories
    `io,micro,concurrency,memory,regressions,read_health,text_origin`.
  - Writes from 10 B to 256 KiB: the `bench_a3_regressions.py` write sizes,
    added as a window step.
  - Writes: `benchmarks/bench_a3_regressions.py --categories writes` with its
    default sizes (10 B, 100 B, 1 KiB, 4, 16, 64 and 256 KiB) and
    `--repeat 5`, both engines, as part of each window's ABBA sequence.
  - Structural and resource gates, fixed now so none is chosen after
    results. Each runs on both engines against C0 and the final candidate
    (and the WP0 baseline where the original gate measured it), with the
    script defaults at the candidate unless listed:

    | Script | Gate | Phases or modes | Judged by |
    | --- | --- | --- | --- |
    | `measure_b2_native_settlement.py` | G02 | default (`--repeats 7`) | Native work settles before cleanup; latency recorded, not gated by percentage |
    | `measure_b2_source_reads.py` | G03 | default (`--repeats 11`) | Exactly-once source consumption; timing provisional |
    | `measure_b2_pending_lines.py` | G05 | `--category scaling`, `--category bulk`; `--payload varied` and `repetitive` | Aggregate linear work (the G05 structural bound) |
    | `measure_b2_scaling.py` | G05 | default | Line-scaling work and allocations against the WP0 baseline |
    | `measure_b2_long_lines.py` | G06 | `--phase resources`, `--phase timing` | The G06 scaling disposition |
    | `measure_b2_read_resources.py` | G07 | `--phase resources`, `--phase latency` | The G07 approved read-ahead and allocation statement |
    | `measure_b2_partial_read.py` | G07 | single mode | Read-ahead diagnostics within the G07 limits |
    | `measure_b2_stream_fairness.py` | G08 | `--throughput-only`, `--latency-only` | Sibling progress and bounded work, not millisecond thresholds |

    Each result is compared with the criterion recorded when its gate
    closed; the G17 record cites that criterion per row.
- **Controls.** An A/A window (C0 against C0) measures noise on this host for
  the G17 category set. It does not depend on the final candidate, so it can
  run early, once its pre-registration is reviewed and the maintainer
  authorizes it. Early A/A evidence counts for G17 only if the final windows
  use a byte-identical harness and runner, the same `uv.lock`, categories,
  fixtures and statistics. If any of those change, the A/A window is rerun
  with the final windows.
- **Policy (§15.1).** At most 5% slower needs no investigation. More than 5%
  slower gets an investigation and a recorded disposition. More than 10%
  slower and attributable to the candidate blocks by default. Medians, all
  samples and dispersion are archived; the candidate is never rerun alone.
- **Claims (§15.3).** Release notes state only the proven algorithmic
  corrections and the measured, paired, named-condition results.

Each window is pre-registered with Codex and authorized by the maintainer,
as in WP8 and WP9.
