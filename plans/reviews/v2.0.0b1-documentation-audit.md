# 2.0.0b1 documentation status audit

Date: 2026-08-31

The active user documentation now describes the current line as beta and the
documented public API as frozen for 2.0. Historical release records were not
rewritten. The targeted repository search was classified as follows.

## Change during final release preparation

- `pyproject.toml` and `tests/test_version_sync.py` still contain
  `Development Status :: 3 - Alpha`. This is intentional while the package
  version remains `2.0.0b1.dev0`; WP8 changes both to the Beta classifier in
  the release-candidate commit.

## Keep: historical status

- `docs/api.md`, `docs/migration.md`, and `docs/adr-sans-io-codec.md` say that
  exact Boolean validation and the sans-I/O design were settled *during* the
  alpha series. These are bounded historical statements followed by the
  current beta-freeze guarantee.
- `CHANGELOG.md` retains alpha release notes and uses `v2.0.0a4` as the b1
  comparison base. These are release history and required provenance.
- Release plans and their evidence retain `a4`, alpha, and pre-beta language
  because they document the sequence that led to this release.
- `SECURITY.md` names older 2.0 alphas/betas only in the unsupported row.

## Keep: data-integrity state, not API maturity

- README and maintained-example uses of `provisional` describe decoded output
  seen before gzip trailer validation. The matching example identifiers and
  integration tests encode that application state and remain correct.
- `docs/examples.md` uses `provisional` for the same unverified-output state.

## Keep: unrelated fixture data

- Literal `alpha` strings in binary, text, readline, and regression tests are
  ordinary payload contents. `alphabet` in a property-test strategy is also
  unrelated to release status.

No active documentation outside plans and the changelog still contains
`2.0.0a4`, bare status-oriented `a4`, or `before beta` language. No current
page calls the API a provisional alpha or promises production stability.
