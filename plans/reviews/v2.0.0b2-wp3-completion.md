## Final behavior and review follow-up

An opening reservation lasts from before acquisition through initialization or
failed-open cleanup. Binary and text wrappers publish their resource and codecs
without suspension only after successful initialization. Overlapping open/close
calls raise the existing `ConcurrentOperationError`; no second opener can replace
the first owner's file, and close cannot report closure before late publication.

Native acquisition retains its private executor future until completion. Cancellation
recovers and closes an acquired file before propagating; failed aiofiles wrapping
also closes the raw file. Native initialization and cleanup settle through repeated
cancellation, including queued acquisition and actual `asyncio.run` shutdown.
Supplied aiofiles delegates retain their configured loop/executor behavior.

The maintainer's cause-chain observation is fixed: ordinary cleanup errors add a diagnostic note
and the original exception is re-raised, preserving its original cause. The wider
matrix also found a text/binary inconsistency in exceptional context exit during
opening. Both now preserve the body's exception while the separate opener retains
ownership; neither reports the handle closed. Clean exit rejects the overlap.

External resources remain caller-owned after failed opening, preserving existing
retry behavior; after publication, `closefd` applies normally. Cooperative custom
methods must finish resource access before returning or raising. Arbitrary hidden
background activity or a custom close that does not complete resource disposal
cannot be made safe by cancelling an asyncio wrapper. A cleanup failure is reported
in a note; arbitrary failed closes are not retried automatically. See the
[ownership design](../design/v2.0.0b2-open-ownership.md) and
[BC3 ledger](v2.0.0b2-behavior-exceptions.md#bc3-selected-correction).

## Cleanup-cancellation review correction

The maintainer found that an ordinary opening failure swallowed cancellation during
cleanup, leaving the caller running after an `except Exception`, or preventing an
expired `asyncio.timeout` from producing `TimeoutError`. G04 was reopened. The six
existing tests that asserted the ordinary error were incorrect; they now assert
cancellation while keeping their reservation, native-settlement and single-close
checks. All six failed before the production correction.

Production commit `003ca5f` fixes the three ordinary-failure handlers in binary
opening, native wrap failure and text-wrapper cleanup. If cleanup raises a control-flow
`BaseException` while the original failure is an ordinary `Exception`, cleanup wins.
The original failure is attached as context if no context is present; repeated
native cancellation did not always retain it implicitly. Existing causes and contexts
are not overwritten. Ordinary cleanup errors still become notes. When acquisition
was already cancelled, its first cancellation still wins over further cleanup
cancellation. No outside cancellation count is consumed.

Nine new direct regressions cover timeout during custom/native header cleanup and
native wrap cleanup, plus direct cancellation, timeout and an interrupt-like
`BaseException` in the text wrapper's separate cleanup handler. Two trace tests add
eight named custom/native, binary/text, cancellation/timeout scenarios. The trace
isolates control flow after independently waiting for native close; it does not
pretend b1 settled native cleanup before returning to the caller.

All clean captures use the same `003ca5f` harness: b1 `048700f`, reviewed `a75de3d`,
and fixed `003ca5f`. The reviewed source differs from b1 in all eight new cases;
the fixed source matches b1 exactly under both engines. The original 30-case opening
fixture and its 26 BC3 allowances are unchanged. No new allowance is needed for
restoring these b1 cancellation/timeout outcomes. The
[clean b1 cleanup fixture](../../tests/data/open_cleanup_b1.json) and
[review-correction evidence](data/b2/wp3/cleanup-review/manifest.json) retain the
raw captures, expected regression differences, passing comparisons and checksums.
