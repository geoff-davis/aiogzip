# v2.0.0a2 Compression Regression Analysis

> [!WARNING]
> These measurements were captured on an Apple M3 MacBook Air. They validate
> WP6 locally, but the release gates remain incomplete until the candidate is
> rerun on the Framework Desktop used for the published GitHub numbers.

## Decision

Keep one scoped optimization: internal binary and streaming writers call a
private encoder entry after they already own an exact `bytes` snapshot. The
public `GzipEncoder.feed()` validation path is unchanged. Operation allocation,
lazy advancement, CRC and ISIZE accounting, output bounds, sink error timing,
and one-operation-per-write ownership remain unchanged.

The 10-byte stress case still misses the target of no more than 25% over
`v1.11.0`, but it is within the hard guard of `v2.0.0a1` +10%. The remaining
cost is the deliberate per-write operation lifecycle. Reducing it materially
would require buffering input across `write()` calls, which would defer codec
work and potentially sink errors. That option is deferred; it is forbidden for
`a2` by the release plan.

## Representative Compression

All candidate results use nine samples. Times are medians in milliseconds.
The engine-selection rows use the matching M3 `v1.11.0` capture; default
compression remains stdlib even when zlib-ng decompression is active.

| Selection | Case | v1.11 | Candidate | Change | Result |
| --- | --- | ---: | ---: | ---: | --- |
| stdlib | 64/64 KiB | 119.684 | 120.606 | +0.8% | target met |
| stdlib | 512/256 KiB | 122.275 | 122.895 | +0.5% | target met |
| zlib-ng active | 64/64 KiB | 120.177 | 119.191 | -0.8% | target met |
| zlib-ng active | 512/256 KiB | 121.970 | 123.107 | +0.9% | target met |
| opt-in zlib-ng compression | 512/256 KiB | 109.534 | 108.888 | -0.6% | target met |

The direct 512/256 stdlib profile attributes 116.940 ms of 121.371 ms
(96.3%) to engine compression. CRC uses 0.221 ms, output slicing and encoder
feed bookkeeping 0.343 ms, input normalization 0.002 ms, operation allocation
0.007 ms, and `__next__` self time 0.016 ms.

The matching async profile records 129.788 ms wall time, 0.133 ms of async
driver self time, and 0.902 ms of event-loop self time. The direct opt-in
zlib-ng case spends 102.296 ms of 109.121 ms (93.7%) in engine compression.
No representative Python-side optimization has enough weight to justify more
production complexity.

## Tiny-Write Diagnostic

The exact a1 tag and candidate use the same current harness, 8 MiB payload,
10-byte writes, and nine repeats on the M3. Times include the final read, as in
the historical benchmark.

| Engine selection | v1.11 | a1 | Before | Candidate | vs a1 | vs v1.11 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| stdlib | 470.947 ms | 994.550 ms | 1054.444 ms | 1021.526 ms | +2.7% | +116.9% |
| zlib-ng | 467.158 ms | 1005.515 ms | 1050.326 ms | 1036.275 ms | +3.1% | +121.8% |

The scoped optimization improves the stdlib-selection median by 3.1% and the
zlib-ng-selection median by 1.3%. Under cProfile, the stdlib case improves from
2.997 seconds to 2.851 seconds, and exact input-normalization calls fall from
1,677,722 to 838,861. Normalization self time falls from 139.365 ms to
72.630 ms.

The final stdlib profile attributes the 838,861 write calls as follows:

| Area | Calls | Self time | Cumulative time |
| --- | ---: | ---: | ---: |
| Input normalization | 838,861 | 72.630 ms | 72.630 ms |
| Operation allocation | 838,863 | 148.912 ms | 194.217 ms |
| `__next__` | 839,377 | 124.993 ms | 1242.375 ms |
| Engine compression | 838,862 | 301.517 ms | 301.517 ms |
| CRC | 838,861 | 66.645 ms | 66.645 ms |
| Output slicing/feed bookkeeping | 839,378 | 256.259 ms | 660.779 ms |
| Async driver | 0 | 0 ms | 0 ms |
| Sink writes | 1,028 | 0.617 ms | 10.514 ms |
| Event-loop functions | 3,102 | 3.628 ms | overlapping |

The small-write path deliberately avoids the async driver. Sink calls are also
not the bottleneck. The remaining hot functions are the public write dispatch,
private feed validation, operation reservation and advancement, engine call,
CRC, and position accounting repeated for every accepted write. Removing
those would weaken deterministic ownership or defer work across calls.

## Validation

- Active zlib-ng: `1643 passed, 1 skipped`.
- Forced stdlib excluding the engine-reload module:
  `1610 passed, 1 skipped`.
- Forced-stdlib isolated engine reloads: `33 passed`.
- Focused encoder and writer suite: `174 passed`.
- Public codec snapshot behavior remains covered by the existing hostile
  `bytes` subclass tests.
- New focused tests prove binary and streaming wrappers do not repeat an
  already completed snapshot.

The final Framework Desktop benchmark run must repeat the representative and
diagnostic cases before release.
