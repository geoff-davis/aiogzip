## G14: stateful differential harness (§14.1)

### Shape

A seeded generator, not a Hypothesis state machine. Sequences must replay
byte-for-byte in a subprocess against another source root (C0, b1), so each
sequence is plain JSON produced from an integer seed by `random.Random(seed)`.
Hypothesis stays for the existing focused properties.

- `tests/stateful/generator.py`: `generate(seed) -> Scenario`. A scenario
  fixes the configuration (mode `rb`/`rt`, encoding and newline, member
  layout, fragmentation, seekability, source kind, `chunk_size`) and an
  operation list.
- **Operations:** `read(n)`, `read1`, `readinto`, `peek`, `readline(limit)`,
  `readlines(hint)`, one iteration step, `tell`, absolute, relative and
  backward `seek`, `seek` to an earlier text cookie, direct `buffer` reads,
  `close`, context exit, and the injected events below. Every scenario starts
  with an acquisition step: `open()`, `async with`, or the module factory,
  over a path (native acquisition) or an external file object. Acquisition
  events cover a failed open, cancellation during native acquisition, an
  initialization failure after acquisition (the gzip header write failing on
  a write-mode open, or the native file wrapper failing, as in the WP3 open
  traces), open/open and open/close overlap (`ConcurrentOperationError`), and
  `open()` after close, which must raise `ValueError` because a closed
  instance cannot be reopened. A new handle on the same path is the reopen
  case. These exercise BC3 differentially. Writes get their own
  smaller generator (write, writelines, flush, sink failure, cancellation,
  close), checked against the model by decompression and differentially
  by raw output.
- **Configuration space:** seekable or not; native file (`aiofiles`), custom
  async source and `FramedAsyncReader` with chosen frames; single, multiple
  and empty members, NUL padding, corrupt CRC/ISIZE, truncation, an exact
  `max_decompressed_size`; utf-8, utf-16 and shift_jis with every `newline`.
- **Injected events:** a source failure with no effect (with a `tell`
  checkpoint) or with consumed input; cancellation while a source read or
  native work is in flight; overlap (a second call while one is parked);
  close during an active call; context-exit abort. Ordering uses events and
  barriers on the fake source; there are no sleeps.
- `tests/stateful/interpreter.py` drives a scenario through public
  operations only, so the same interpreter runs unchanged against b1, C0
  and the candidate. It emits a symbolic trace in the existing oracle
  format (symbolic cookies, exception type and message class, no per-call
  I/O counts), plus the harness witnesses described below, reusing
  `scripts/compare_file_state_trace.py`'s conventions.
- Every sequence runs under a hard `asyncio.timeout`; a timeout fails the
  test (§14.1).

### Public replay and candidate-only observation

Two layers, kept separate:

1. **Public replay** (`interpreter.py`). It performs public operations
   only, so it runs against b1, C0 and the candidate. Its trace records
   what a caller can see (returned data, exceptions, `closed`, `tell()`
   symbolically) plus harness witnesses. Most witnesses are the fake
   source's and sink's own facts: reads or calls after close, close calls,
   and whether a parked custom-sink call resumed. The parked-call record
   below is the exception, because it inspects an implementation object.
   Writers use a fixed `mtime=0`, so raw output is comparable across roots.
   The final event records the decoded output and the raw output: as raw
   bytes in scenarios with an `abort` or `cancel` event, otherwise as a
   length and digest. An event that parked a sink write records the parked
   call: whether it was custom or native, the bytes it carried, and, for a
   custom sink, whether the call resumed (rather than being cancelled
   while parked) and the bytes it accepted. Those bytes are kept raw in the same
   abort/cancel scenarios. For a native sink, the call's description comes
   from the callable submitted to the harness's gated executor: aiofiles'
   `partial` on C0 and b1, `_NativeSourceCall` on the candidate. This is the
   replay's one inspection of an implementation object, and is
   instrumentation, not caller-visible behavior. It fails closed:
   an unrecognized callable records no bytes, and `BC8-WRITER-ABORT` then
   accepts nothing for that event. Error messages replace the per-run
   temporary directory with `$WORKDIR`.
2. **Candidate observation** (`observer.py`). Runs only against the
   candidate, in-process, after each replayed operation. It may read private
   state (`_read_health`, `_eof`, decoder liveness, reservation flags,
   observer attachment) and checks it against the model's expectation. It
   never feeds back into the public trace.

### Model

`tests/stateful/model.py` holds two importable tables, written from the
documented contracts (the [open-ownership](v2.0.0b2-open-ownership.md),
[read-health](v2.0.0b2-wp6-read-health.md) and
[bridge](v2.0.0b2-wp8-bridge.md) designs), not from the implementation.

**Lifecycle and ownership table.** One row per handle:

- **Lifecycle:** UNOPENED, OPENING, OPEN, CLOSED.
- **Resource:** none, held locally by the opener (unpublished), published.
- **Ownership:** owned (path acquisition, or an external object with
  `closefd=True`) or borrowed (an external object with `closefd=False`).
- **Reservations:** the open/close reservation, and the read or write call
  reservation, each idle or active.
- **Text binding:** for text handles, whether observers are attached.

Events and expected outcomes:

| From | Event | Outcome |
| --- | --- | --- |
| UNOPENED | A read, write or other reserved call | `ValueError` (file not opened); no state change |
| UNOPENED | `close()` | CLOSED; nothing was acquired, so nothing is closed |
| UNOPENED | `open()` starts | OPENING; open/close reservation active; resource none, then held locally |
| OPENING | Acquisition or initialization succeeds | OPEN; resource published with no suspension in between; reservation idle; text observers attached |
| OPENING | Acquisition fails, or is cancelled after native acquisition | UNOPENED; a natively acquired resource is closed exactly once before the error or cancellation propagates; nothing published |
| OPENING | Initialization fails (header write, native wrapper) | UNOPENED; an owned resource is closed exactly once; a borrowed external object is not closed; the open/close reservation stays active until cleanup settles |
| OPENING, cleanup | Cleanup raises an ordinary `Exception` | The original opening exception propagates with its cause unchanged; the cleanup error is added as a note |
| OPENING, cleanup | Cleanup raises a non-`Exception` `BaseException` (cancellation, including repeated cancellation, or an interrupt) | The `BaseException` propagates once cleanup has settled, with the opening failure as its `__context__` and the opening failure's own cause unchanged. Cancellation requested during cleanup does not interrupt it: the resource is closed exactly once. A close call that itself raises is never retried, so the resource is closed at most once |
| OPENING | Overlapping `open()` or `close()` | `ConcurrentOperationError`; no state change |
| OPENING | Exceptional context exit | Body exception propagates; no closure claimed; the opener still owns its resource |
| OPEN | `open()` | `ValueError` (already open); no state change |
| OPEN | Reservation-taking read or write call starts | Call reservation active; an overlapping reservation-taking call raises `ConcurrentOperationError`. Calls that take no reservation, such as text `tell()` during an active read, are allowed and are checked by cookie replay |
| OPEN, call active | `close()` | `ConcurrentOperationError`; no state change |
| OPEN, call active | Context-exit abort | CLOSED; read health BROKEN, retained; resource closed if owned; text notified |
| OPEN | `close()` | CLOSED; read health and `eof` retained as they were; an owned resource closed exactly once, a borrowed one never; observers detached |
| CLOSED | `close()` | No effect |
| CLOSED | `open()` | `ValueError`; a closed instance is not reopened |
| — | New handle on the same path | An independent row; the reopen case |

**Read-health table.** HEALTHY, VALIDATION_SALVAGE and BROKEN plus `eof`,
moved by no-effect source failure, consumed-effect failure, cancellation,
validation failure, salvage exhausted, successful rewind, failed rewind and
abort. Health and `eof` are defined from OPEN onward and are retained,
unchanged, across close: a closed reader keeps the health and `eof` it had,
as C0 does (`test_close_of_a_broken_reader_keeps_health_and_eof`). Abort
sets BROKEN before closing.

Combination rules tie the tables together. For example, CLOSED implies that
an owned resource is closed, the binary holds no reference to text, and no
call reservation is active, while health and `eof` keep their last OPEN
values. Every reachable (lifecycle, health, `eof`) combination is listed,
including CLOSED with each health state.

Completions found while building the harness. Each restates a documented
contract the first draft of the tables left out; none is a tolerance:

- **An abort with no active call is a close.** Exceptional context exit
  aborts only a call that is active; when none is (the body raised, or an
  abort's call finished before exit), exit closes normally, retaining
  health and `eof`. Only an active call takes the context-exit-abort row
  and BROKEN.
- **A consumed-effect failure at the end of the source consumes nothing.**
  The fake source reports it with its own message and the model treats it
  as a no-effect failure.
- **Cancellation of an unhealthy reader's call** (a recovery rewind): a
  proven no-effect cancellation keeps VALIDATION_SALVAGE or BROKEN; an
  uncertain one makes VALIDATION_SALVAGE BROKEN.
- **Rewinds are parked too.** The generator parks a `seek0` for abort,
  cancellation, overlap and close-during-call on any rewindable source,
  which found BC9.

Migration: `test_read_health_transitions.py` asserts against the read-health
table, and the focused opening tests (`test_b2_open_ownership.py`,
`test_open_settlement.py`, `test_open_qualification.py`, which owns the
cleanup-precedence states, and `test_file_lifecycle.py`) assert their end states
against the lifecycle table wherever they check states. The tables and the
focused tests therefore cannot drift apart.

The G14 record reports coverage of both tables in two columns: transitions
inferred from the public trace (for example, a validation error, then
salvage data, then a broken-stream error; or `ConcurrentOperationError` plus
the fake resource's close count), and transitions inspected privately by the
observer (reservation flags, observer attachment, decoder liveness).

The expected bytes come from the generator, not from decoding the produced
file. The generator builds each member from a known clean payload, so the
model knows every member's payload and boundaries before corruption:

- **Clean members:** expected output is the concatenated payloads.
- **CRC or ISIZE corruption:** the DEFLATE body is intact, so the member's
  full payload is the expected provisional output, followed by the
  validation error; the salvage contract (C0) then serves exactly that
  payload's undelivered remainder, then a broken-stream error.
- **Truncation of a valid body:** the bytes before the cut are a prefix of
  a valid DEFLATE stream, so any engine can emit at most the member's clean
  payload. The model accepts any delivered prefix of the expected payloads
  that is no shorter than the payload bytes of earlier complete members,
  followed by an error. This allows engine buffering differences without
  accepting lost or invented data.
- **Body corruption:** malformed DEFLATE has no cross-engine output bound;
  stdlib zlib and zlib-ng may emit different bytes before detecting the
  error. The reference is therefore engine-matched per leg: the generator
  feeds the corrupted member body to the raw decompressor
  (`wbits=-15`) of the engine that `aiogzip.engine_info().decompression`
  reports for that leg (`zlib.decompressobj` on stdlib legs,
  `zlib_ng.zlib_ng.decompressobj` on zlib-ng legs). A single
  `decompress(body)` call is not a reference: it raises at the bad code and
  discards everything it inflated in that call, while aiogzip may already
  have returned that output from earlier bounded steps. The reference is
  instead built on a fixed schedule: feed the body one compressed byte at a
  time, and for each byte call `decompress(data, 1)` repeatedly (passing
  `unconsumed_tail` back in) until a call returns no output and leaves no
  tail; append the output of every successful call and stop at the first
  engine error. Because each call can produce at most one byte, every byte
  the engine can inflate before reaching the bad code is captured, so the
  reference is the largest prefix that engine can emit. Scenario evidence
  retains the schedule's name and version (`raw-1in-1out/v1`), the reference
  length, the compressed offset of the failing byte and the engine's error
  message. A corruption the engine does not detect (it inflates to garbage
  and fails only at the trailer or stream end) is not a body-corruption
  scenario. Whether an engine detects a random overwrite depends on the
  fixture: a prototype detected about 7% on one 300 KB payload and about
  half on others. The generator therefore
  re-rolls until the reference schedule reports an engine error, and records
  the number of re-rolls. The model accepts any delivered prefix of that
  leg's reference under the same lower bound, followed by an error.
  A focused oracle test (`tests/stateful/test_oracle.py`) pins the
  schedule. It uses a corruption more than 64 KiB of output past the start
  of the body, and asserts on both legs that a one-shot `decompress` raises
  with no output, that the reference captures that output, and that
  `GzipDecoder` and `AsyncGzipBinaryFile` output across several
  `chunk_size` and `output_chunk_size` values is always a prefix of the
  reference. Each scenario records the reference engine, and the
  run fails if it differs from the engine the candidate (or C0, or b1)
  reports on that leg. A C0 or b1 differential compares implementations on
  the same leg only, never across engines.
- **Text:** an incremental model, not `io.TextIOWrapper` over a finished
  prefix. The allowed bytes go through `codecs.getincrementaldecoder(encoding)`
  with `final=False`, then the newline stage `TextIOWrapper` itself uses:
  `io.IncrementalNewlineDecoder` with `translate=True` for `newline=None`
  and `translate=False` for `newline=""`, and no newline decoder for `"\n"`,
  `"\r"` and `"\r\n"`. A gzip failure can end inside a multibyte character, so at a gzip
  failure the expected text is that `final=False` output: every complete
  character, then the gzip error, with the incomplete tail retained. The
  newline stage, by contrast, is finalized at that boundary: a pending CR
  is resolved as a line end (`"\n"` for `newline=None`, `"\r"` for
  `newline=""`). Every continuation of the bytes decodes to text that begins
  with that resolution, so emitting it is a correct prefix. (The first model
  held the CR; b1, C0 and the candidate all emit it, and that disagreement
  was recorded as model finding F1b.) Only the returned text is resolved.
  The `newlines` record stays unresolved at a failure boundary, because the
  continuation could have made the CR part of a CRLF; b1, C0 and the
  candidate all leave it unrecorded, and the model expects that. After a validation failure the
  drained salvage obeys the same rule, and a salvage that completes no
  character ends in the broken-stream error, never `''` (ledger BC7). This holds only when
  every byte the reference allows is valid in the encoding. Truncation of a
  valid payload satisfies that. DEFLATE body corruption can emit bytes that
  are invalid for the encoding, so for text scenarios the generator keeps a
  body corruption only if the whole engine-matched reference prefix decodes
  without error under `final=False`, re-rolls it otherwise, and records the
  check per scenario. Body corruption that emits invalid encoded bytes stays
  binary-only in the stateful run. No existing test covers invalid decoded
  bytes racing a gzip body-corruption error (`test_text_io.py`'s `errors`
  tests use valid gzip streams), so WP10 adds one focused regression in
  `tests/test_text_io.py`: a UTF-8 member whose clean payload contains
  invalid bytes ahead of a body corruption, read under `errors="strict"`
  and `errors="replace"`, with the invalid bytes placed both more than one
  `chunk_size` ahead of the corruption and inside the refill that reaches
  it. It pins which error surfaces first, the text delivered before it, the
  read-health state after each, and that a retry does not re-deliver text.
  The expected ordering is not predicted here: the test is written against
  C0's observed behavior, and any candidate difference is classified under
  the differential rules like any other mismatch.
  `final=True` is applied only at validated EOF, where payloads are valid
  text by construction. For truncation, the generator deliberately places
  cuts both on and inside character boundaries, and records which for each
  scenario, so both cases are attested. If C0 and the candidate agree with each other but not
  with the model at a failure boundary, that is a model finding to
  investigate and record, never a tolerance added afterwards.

After each operation the model checks:

- returned data is exactly the next unread slice of the expected bytes:
  nothing lost, nothing duplicated across retries, and a later valid member
  never hides an earlier lost one;
- a failed stream never reaches validated EOF;
- public outcomes are consistent with the transition table (public replay),
  and private state equals the table's state (candidate observation);
- after close, cancellation or failure, the fake source and sink are not
  touched again, and an owned resource is closed exactly once;
- a rollback restores state that a retry or replay continues identically;
- per-operation work stays bounded, using the source read counters the
  scaling tests already use (no wall-clock thresholds).

Rules:

- **Candidate vs C0:** every seed. Traces match exactly, except differences
  that `C0-WP8-FAILED-ABORT` claims. This closes the ledger's pending C0
  trace comparisons for BC4 and BC5.
  `BC7-TEXT-SALVAGE`, `BC8-WRITER-ABORT` and `BC9-REWIND-ABORT` also claim
  differences, under the rules below.
- **Candidate vs b1:** every seed. A difference is claimed only by a
  predicate named for one ledger exception, BC1 to BC9. No other allowance exists; b1's
  traces already contain the a3 behavior.
- **Event-wise composition.** A seed may carry several independent
  corrections; against b1, for example, seed 584 differs at a cancelled
  native read (BC2) and later at an aborted native rewind (BC9). Each
  predicate therefore claims specific differing events, and for the final
  event specific fields; it never accepts a whole trace. A seed passes
  when every differing event and every differing final field is claimed
  by exactly one predicate, and everything unclaimed matches exactly. An
  unclaimed difference fails the seed, and so does a difference that two
  predicates claim. A predicate's conditions on its own claimed events
  are evaluated as written, against the full traces and scenario for
  context; it places no condition on events claimed by another predicate.
  Both traces must have the same number of events.
- **`BC7-TEXT-SALVAGE`** applies to both comparisons. It claims an F
  event: a `read` in a text scenario whose read health is
  VALIDATION_SALVAGE at that event.
  - **Clause F1a:** only for an unbounded `read` (size normalized to -1,
    which includes `read(None)` and negative sizes): the reference raises
    `UnicodeDecodeError` and the candidate returns text. Sized `read(n)`
    already held the incomplete tail in b1 and C0, so the fix did not
    change it. The candidate's return value must equal the
    model's boundary text for the remaining salvage, and the scenario's
    allowed bytes must end inside a character.
  - **Clause F2:** for sized and unbounded `read` alike: the reference
    returns `''` and the candidate raises the broken-stream `OSError`.
  - It also claims the later events of the same reader that differ only
    because of the F event's outcome: each must be the broken-stream
    refusal on one side and identical to the other side once the
    reference's error (F1a) or its empty result (F2) is accounted for.
  - Its near-miss tests cover a healthy reader (clean EOF `''` must still
    match), a binary reader, a non-`read` op, a `UnicodeDecodeError`
    on bytes that are invalid in the encoding (not an incomplete tail), and
    an F1a-shaped mismatch on a sized `read(n)`. Its positive tests cover
    F1a on `read()`, `read(None)` and `read(-5)`, and F2 on both sized and
    unbounded reads.
- **Every predicate is exercised.** A predicate that claims nothing across
  the release set fails the run, unless the record says why its scenario
  cannot arise.
- **Raw retention.** For every seed with a claimed difference the run keeps
  the seed, the scenario JSON, both whole raw traces, and which predicate
  claimed each event and final field. Traces are never rewritten.
- **`BC8-WRITER-ABORT`** applies to both comparisons, in write scenarios
  only. It claims only the events and final fields its clauses name, and
  at least one of them must differ.
  - **Clause W1** applies when exactly one `abort` or `cancel` event
    records a parked sink write (the W1 event). It claims the W1 event
    and, in the final event, the decoded output, the raw output and the
    sink's calls after close; both outputs must be incomplete members. Let `C`
    and `R` be the candidate's and the reference's raw output, and `P` the
    parked call's bytes. Which side writes more depends on the event and
    the sink:
    - **W1a, `abort` of a custom-sink write.** The candidate cancels the
      parked call: its record shows the call never resumed and accepted
      nothing, and its sink has no calls after close. The reference's
      record shows the call resumed, which holds whether or not the sink is
      borrowed; that is the required difference, so the final event need
      not differ. `R` is `C` followed by `E`. `E` is a prefix of
      `P` and begins with the bytes the reference's parked call accepted;
      the reference may deliver the rest of `P` in further calls after
      close. `E` is empty exactly when the reference's call raised the
      injected no-effect failure: a no-effect failure armed before the
      abort stays armed on the candidate, which never resumes the call,
      while the reference consumes it, so `R` equals `C`. At the W1 event,
      the parked call's resumed flag and accepted bytes may differ. The
      call's own outcome
      may differ only when a sink failure was armed before the event: the
      reference raises that injected failure (no-effect or partial) and the
      candidate raises `write aborted…`/`flush aborted…`.
    - **W1b, `abort` of a queued native write.** Exit settles the queued
      call before closing, so `C` is `R` followed by exactly `P`. At the
      W1 event, the call's own outcome must differ: the candidate raises
      `write aborted…`/`flush aborted…`, the reference an `OSError` without
      that message (C0's closed-file error). The sink's calls after close
      must match.
    - **W1c, `cancel` of a queued native write.** The candidate prevents
      the queued call, so `R` is `C` followed by exactly `P`. The W1 event
      and the sink's calls after close must match.
    - No difference is accepted for a cancelled custom-sink write, which
      behaves identically on every root, or for a native write that had
      already started. The harness parks native work before it starts, so
      that state is covered by `tests/test_write_abort_settlement.py`
      instead.
  - **Clause W2:** it claims one event, a text `writelines`. The
    reference returns `None` and the candidate raises
    `write stream is broken…`. It claims no final field.
  - **Tests.** Positive tests: one each for W1a (including short writes
    delivered after close, an armed partial failure, and an armed
    no-effect failure with `R` equal to `C`), W1b, W1c and W2.
    Near-miss tests: a read scenario; a complete member; a second differing
    event, which stays unclaimed and fails the seed; `E` not a prefix of `P`; `E` empty without the reference's
    no-effect failure, or non-empty with it; W1a where the candidate's
    parked call resumed or the reference's did not; an exact-`P` difference in the
    wrong direction for each of W1a, W1b and W1c; W1b where the reference
    already raises the aborted message; a cancelled custom-sink write; and
    a binary `writelines`. The parked-call extraction has its own tests for
    an aiofiles `partial`, a `_NativeSourceCall` and an unknown callable.
- **`BC9-REWIND-ABORT`** applies to both comparisons, in read scenarios
  with a native source only. It claims one event: an `abort` whose parked
  call, on both sides, is the native `seek` of a `seek0` call. At that
  event only the call's outcome may differ: the candidate raises the
  `OSError` `read aborted because the gzip file was closed while the call
  was active`, and the reference returns `0` (C0) or raises `ValueError`
  `seek of closed file` (b1). The injected abort and the parked record
  match. It claims no final field.
  - **Tests.** Positive tests: a C0-shaped and a b1-shaped mismatch.
    Near-miss tests: a custom source; a parked native `read` rather than a
    `seek`; a `cancel` rather than an `abort`; a reference that raises some
    other error; the candidate returning `0`; and a second differing event,
    which stays unclaimed and fails the seed.
- **Predicate tests.** Each predicate has a positive test (a hand-written
  scenario it must accept) and a near-miss test (a similar mismatch it must
  reject). Composition has its own tests: a positive seed-584-shaped pair
  whose BC2 and BC9 events are claimed independently, and near misses with
  an unclaimed third difference, with one event claimed by two predicates,
  and with traces of different lengths.
- C0 and b1 run in subprocesses with `PYTHONPATH` pointing to clean
  worktrees, using the current venv, as the benchmark harness does. They
  never run `uv run` inside a worktree.

### Seeds, minimization and CI

- **PR CI:** a fixed seed set, sized to keep the stateful job under about
  60 s per leg, running against the candidate with model assertions and
  the observer. It is seeds 0 to 999 plus named regression seeds (about
  18 s per leg); a coverage test requires every table row to be reached,
  except the OPENING cleanup-precedence and context-exit rows, which it
  maps to their focused tests. It
  runs on every build leg; the differential runs need C0 and b1 worktrees, so
  they run locally and in the release run.
- **Release set:** a larger fixed range, run on both engines with the C0 and
  b1 differentials. The G14 record states the exact seed counts and ranges
  run.
- **Minimization:** a failing sequence is shrunk by deleting operations, then
  simplifying configuration, while it still fails. The minimized scenario is
  committed under `tests/data/stateful_regressions/` and runs in every CI
  leg.

## G17: performance (§15)

Run last, on the final candidate (the commit that closes G14–G16 and G18).
Any later production change invalidates the windows.

- **Comparisons.** Final candidate vs C0 (state-refactor effect) and vs the
  WP0 baseline `dc8950c` (cumulative effect). Each is a method-A window on
  both engines, using the WP8/WP9 harness with the same runner, venv and CPU
  pinning. The WP0 baseline is recaptured with the current runner through
  `--source-root`; the archived WP0 JSON is not overwritten and is not
  compared directly, since its legacy rows lack matched fixtures.
- **Families (§15.2).**
  - Binary, Text, Decoder preservation and Resources: categories
    `io,micro,concurrency,memory,regressions,read_health,text_origin`.
  - Writes from 10 B to 256 KiB: the `bench_a3_regressions.py` write sizes,
    added as a window step.
  - Writes: `benchmarks/bench_a3_regressions.py --categories writes` with its
    default sizes (10 B, 100 B, 1 KiB, 4, 16, 64 and 256 KiB) and
    `--repeat 5`, both engines, as part of each window's ABBA sequence.
  - Structural and resource gates, fixed now so none is chosen after
    results. Each runs on both engines against C0 and the final candidate
    (and the WP0 baseline where the original gate measured it), with the
    script defaults at the candidate unless listed. The exception is
    `measure_b2_partial_read.py`, which has no `--engine` option and forces
    and asserts the stdlib engine; it stays the existing stdlib-only
    diagnostic:

    | Script | Gate | Phases or modes | Judged by |

    | `measure_b2_source_reads.py` | G03 | default (`--repeats 11`) | Exactly-once source consumption; timing provisional |
    | `measure_b2_pending_lines.py` | G05 | `--category scaling`, `--category bulk`; `--payload varied` and `repetitive` | Aggregate linear work (the G05 structural bound) |

- **Controls.** An A/A window (C0 against C0) measures noise on this host for
