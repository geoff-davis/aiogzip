## First publication attempt

The first signed tag targeted `e5c4d10`. Its publish run
[37699863778](https://github.com/geoff-davis/aiogzip/actions/runs/37699863778)
failed in the `test` job because that job never installed `uv`, which
`tests/test_build_release_artifacts.py` needs; `publish` was skipped and
nothing reached PyPI. The release-prep record has
[the details](v2.0.0b2-release-prep.md#first-publication-attempt).

PR #109 added the pinned `setup-uv` step. Codex reviewed it read-only and found
no blocking issue. Its one wording note is applied to the release-prep record
in this change: the publish `test` job lacked `uv` unlike every CI job that
runs tests or builds artifacts (`coverage-comment` installs neither).

With the maintainer's approval, the GitHub release and the tag were deleted
and the tag re-signed on `962bfe4`. The original tag object was `7a9c06c`.

## Windows stateful timeout

The release-merge run failed on Windows: stateful seed 734 (a 7-byte
`chunk_size` over about 330 KB of input) failed with `WinError 32` while
`TemporaryDirectory` cleanup ran, in `test_seed_matches_the_model[734]` and
`test_seed_set_covers_every_table_row`. The pytest progress line that
contains seed 734 took 34.6 s on that run and 22.8 s on the passing PR run.
The harness bounds each scenario with `SCENARIO_TIMEOUT = 30.0` and does not
close the handle when that fires, so Windows cannot remove the still-open
file. That is consistent with a slow runner reaching the timeout, not a
library failure; Codex reached the same reading. The same tree passed
Windows on the PR, and every later Windows run has passed.

Because `tests/` ships in the sdist, the maintainer deferred the harness fix
to after b2. It is the first follow-up below.

## Post-release decision

All b2 publication, provenance, artifact and documentation checks pass. On
2026-10-07 the maintainer chose to advance to `2.0.0rc1.dev0`: no unresolved
beta correctness issue needs another beta. F2 and F3 are inherited from b1
and disclosed in the
[candidate review](v2.0.0b2-candidate-review.md), and the Windows failure is
in the test harness. The Beta classifier and the frozen 2.0 compatibility
contract remain in force.

As with b1, this development version does not promise an RC. If beta feedback
or later review finds a code or public-contract correction, it ships as
`2.0.0b3`.

## RC handoff

No RC plan is committed under `plans/` (see the
[index](../README.md#parked-rc-plan)), so there is no document to rebase yet.
When the RC plan is written, it starts from these baselines (plan §17):

```text
public API baseline:       v2.0.0b1
approved behavior fixes:   b2 exception ledger (BC1-BC10)
immediate runtime oracle:  v2.0.0b2
performance baseline:      v2.0.0b2, with historical continuity rows
```

It must not assume that runtime source or every behavior is identical to b1.
It retains, from plan §17: later Python 3.15 qualification, action pinning,
PR documentation validation, public feedback intake, exact-artifact
publication and external RC review. Supported versions and source SHAs are
reverified when that work starts. Plan §18 lists the deferred opportunities.

Follow-ups found during b2 publication:

1. **Windows stateful timeout.** Close the handle when `SCENARIO_TIMEOUT`
   fires, and make seed 734 lighter or give it more time on Windows.
2. **F2.** Cancelling `close()` does not wait for the underlying file's own
   native close to finish, as in b1.
3. **F3.** Concurrent `tell()` during `readlines()` is not a transactional
   cookie for the whole call.
4. **Action pinning.** `publish.yml` still uses moving tags
   (`actions/checkout@v7`, `actions/setup-python@v7`,
   `pypa/gh-action-pypi-publish@release/v1`).
5. **Dependabot.** GitHub reported three open alerts on `main` (two high,
   one moderate) when the branches were deleted; they are not yet triaged.

Issues [#71](https://github.com/geoff-davis/aiogzip/issues/71) and
[#72](https://github.com/geoff-davis/aiogzip/issues/72) remain open and
deferred.
