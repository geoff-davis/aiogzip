# v2.0.0a2 WP3 Decoder Buffer Tuning

> [!WARNING]
> These measurements were captured on an Apple M3 MacBook Air. They support
> the private constant selection and local algorithmic gates only. The release
> gates remain incomplete until the candidate and historical references are
> rerun on the Framework Desktop used for the published GitHub numbers.

## Decision

Keep both initial private values at 256 KiB:

```python
_INFLATE_INPUT_WINDOW = 256 * 1024
_INFLATE_OUTPUT_BATCH = 256 * 1024
```

The 64 KiB candidates add measurable loop overhead and require two engine
calls for the 128 KiB tiny-output fixture. Larger values do not provide a
consistent cross-engine improvement over 256 KiB and increase the maximum
retained input or output block. The 256 KiB values are the smallest candidates
that meet the deterministic engine-call invariant and the provisional M3
direct-scaling gates.

## Profile Disposition

The initial tuning stream medians appeared to miss the high-level gate. The
first tuning runner incorrectly created and destroyed an event loop and default
executor for every sample, charging thread-pool startup. Those files were
invalidated before commit, the runner was corrected to use one
`asyncio.Runner`, and all four raw files were recaptured with the final runner
hash.

An executor-hop profile of the corrected code recorded 16 first-step offloads
for 17 source items. Later bounded steps and output-only slicing remained
inline. After executor warm-up, repeated exact-case values stabilized around
5.0–5.8 ms. This supports keeping the body fix in WP3 and leaving cooperative
scheduling and executor-policy ownership to WP5.
