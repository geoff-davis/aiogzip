## Draft GitHub release notes

### aiogzip 2.0.0b1

This is the first beta in the aiogzip 2.0 series. The documented 2.0 public
API is now frozen: no intentional incompatible change is planned before 2.0
stable. Beta remains a prerelease, so applications should test and pin it
appropriately.

The release adds a deterministic machine-readable public API manifest and
shared positive and negative mypy/ty fixtures. CI now tests the supported
Python 3.11 through 3.14 range, stdlib zlib, optional zlib-ng acceleration,
forced stdlib operation with zlib-ng installed, exact dependency floors, and
clean wheel/sdist installations on Linux, Windows, and macOS.

The declared floors now match the oldest releases that satisfy the supported
runtime contract: `aiofiles>=23.2.1`, `aiocsv>=1.2.3`, and optional
`zlib-ng>=0.4.0`. The new stability, API, codec, errors, streaming, migration,
security, and example documentation describes the frozen contract and its
non-guarantees.

Runtime behavior is intentionally preserved from `2.0.0a4`; the runtime source
differs only in `__version__`. AnyIO/Trio support and indexed random access
remain deferred. Same-call write visibility and sink-error timing also remain
unchanged. For many tiny records, use `writelines()` or explicit bounded
application batching when one sink-failure boundary per record is unnecessary.

Issue #86 is ready to close as an accepted 2.0 design tradeoff, not as a claim
that the historical tiny-write difference was eliminated. The tiny-write row
remains an active regression gate. Maintained fragmented-transport and
concurrent-ingest examples are available in the
[example runbook](https://github.com/geoff-davis/aiogzip/blob/v2.0.0b1/examples/README.md).

Local reproducible artifacts prepared from `fdab840` have these hashes:

- wheel: `6c66ef2ed3249db41f7c2ac7ce5d624892bc4e8d13e692682c46eda92318be27`
