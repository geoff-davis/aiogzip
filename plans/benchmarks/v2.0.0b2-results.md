# b2 measurements: WP0 baseline

These are pre-repair observations, not candidate speedups or release qualification.
Source: `dc8950cb334e1cf4082f2bf50074464e06c72287`; clean harness:
`440ed71ebdbeeebcdb526590f86fa8f9f0533a5e`. Both runs use the same Python 3.14.2
environment, aiofiles 25.1.0 and zlib-ng 1.0.0. The [manifest](data/b2/wp0/manifest.json)
retains source/harness trees, file hashes, dependencies, run order and limitations.

## General suite baseline

Executed all ten existing categories with three repeats, default 1 MiB workloads,
and the quick codec-regression profile in all measurement modes. All categories
completed: 83 rows under forced stdlib and 84 with zlib-ng available. The forced
stdlib fast-compression placeholder is explicitly skipped, not a zero-cost result.
The optional-engine run includes explicit fast compression; native compressor
types and round trips were verified separately in the WP0 engine record.

```sh
python benchmarks/run_benchmarks.py --all --repeat 3 \
  --source-root /tmp/aiogzip-b2-reviewed-baseline-dc8950c \
  --engine stdlib --regression-profile quick --regression-mode all \
  --environment-label wp0-local-linux-py314 --output OUTPUT.json
```

Repeat with `--engine zlib-ng`. The actual executable and runner root are in JSON.

- [Stdlib results](data/b2/wp0/baseline-stdlib-executor.json)
- [zlib-ng results](data/b2/wp0/baseline-zlib-ng.json)

The legacy suite retains three outer duration samples and median/MAD values. Some
rows generate fresh random data without retaining fixture hashes; the fast-compress
row internally uses best-of-five timings. These legacy rows document suite behavior
and cannot independently support a paired, exact-fixture numerical speed claim.
Deterministic codec-regression and new scaling rows retain fixture hashes. Before
using any affected legacy row for b2's hard performance gate, capture matched
fixtures and the required samples using a reviewed harness on both sides.

The host is shared, uses the powersave governor, and has nonzero recorded system
load. These measurements do not establish the 5%/10% candidate thresholds. Final
cumulative and C0 comparisons remain G17 work; this is not the release regression
profile or the final platform/dependency matrix.

The initial restricted-sandbox invocation stalled before producing a result. It
was terminated with exit 143. The successful runs used the same execution
permissions as the passing test suite. No timing from the stalled attempt is used.

## F4: small-hint scaling

The deterministic harness runs 2,048 through 32,768 lines with hints 1, 32 and -1.
Fixture generation, open and result validation are outside timing. Public-call
iteration and output collection are inside timing. Each row has three uninstrumented
samples plus a separate allocation/work observation.

| Lines | Stdlib hint=1 median seconds | zlib-ng hint=1 median seconds |
| ---: | ---: | ---: |
| 2,048 | 0.015697 | 0.015588 |
| 4,096 | 0.063876 | 0.059709 |
| 8,192 | 0.246460 | 0.237221 |
| 16,384 | 0.920040 | 0.930605 |
| 32,768 | 3.857365 | 3.796336 |

The approximately fourfold doubling pattern supports the already reproduced
structural defect: 2,094,081 suffix-copy entries for 2,048 lines in the focused
test. This is a failing baseline for WP4, not acceptance of quadratic work.

## F5: generic long-line scaling

Each engine has 50 long-line rows: 1/2/4/8/16 Mi characters, UTF-8 ASCII and
ISO-2022-JP Japanese text, all five newline settings, and a fixed 64 KiB file chunk.
Inputs contain no terminator. Timings and allocation/append instrumentation are
separate; hashes and individual samples are retained.

| Input / newline | 8 Mi chars median seconds | 16 Mi chars median seconds | Engine |
| --- | ---: | ---: | --- |
| ASCII UTF-8 / empty newline | 0.023214 | 0.084656 | stdlib |
| ASCII UTF-8 / LF | 0.015098 | 0.033834 | stdlib |
| Japanese ISO-2022-JP / empty newline | 0.126302 | 0.431703 | stdlib |
| ASCII UTF-8 / empty newline | 0.009843 | 0.052448 | zlib-ng |
| Japanese ISO-2022-JP / empty newline | 0.093500 | 0.423212 | zlib-ng |

The generic path presents 2,155,872,256 cumulative characters to growing-buffer
concatenations for the 16 Mi-character ASCII case; the ISO-2022-JP case presents
4,320,132,096. This counter is a structural work indicator, **not** a claim that
the allocator copied exactly that many characters. The specialized LF path uses
fragment accumulation and does not enter this append path in these fixtures.

F5 is now a package-level scaling finding. WP5 must evaluate a localized repair
or obtain an explicit disposition before C0. Split/final terminators, other
chunk sizes, less-compressible text and wider codec scenarios remain WP5's matrix.
WP0 neither changes validation timing nor introduces a new line-size limit.

## F6 and fairness

The [reviewed F6 measurements](../reviews/v2.0.0b2-wp0-review-response.md#f6-diagnostics)
remain valid because production code is unchanged. They distinguish one compressed
item expanding to 16 MiB from an incompressible file spanning many source reads.
Buffer sizes are diagnostics, not regression requirements. Limits, all partial-read
methods, RSS, concurrency and scheduler gaps still require WP5 qualification.

F7's deterministic tests show zero sibling progress before the last source item
for both empty-item wrappers. This establishes the baseline fairness failure without
using a host-specific timing threshold; the across-item repair remains WP5.

## WP2 source-read measurements

[WP2 completion](../reviews/v2.0.0b2-wp2-completion.md#performance-and-disposition)
records paired measurements for all 24 native/custom, binary/text read cases
under each engine. The [raw evidence](../reviews/data/b2/wp2/manifest.json)
retains both the initial direct-shield implementation and final worker-owned
implementation, minimum/median comparisons, baseline drift and a focused custom
source diagnostic. Results are provisional: G17 remains open, with no performance
exception or general speedup claimed.

The [WP2 maintainer follow-up](../reviews/v2.0.0b2-wp2-completion.md#maintainer-review-correction)
attributes a separate ABBA review measurement: +0.34 µs/custom read and
+0.45 µs/native read at 4 KiB chunks (about +6.6% in that case), negligible at
the default chunk size. G17 retains this small-chunk cost. These are review
results, not new local timing captures.
