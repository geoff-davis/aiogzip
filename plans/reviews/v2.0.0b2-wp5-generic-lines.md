# WP5: generic long-line accumulation

This increment follows cookie fix cea195d. It repairs the repeated growing-string
append in generic newline iteration/readline and in bounded readline, but **G06
remains open for comparative timing and allocation qualification**.

## Implementation and preserved behavior

Each refill decodes into an empty buffer using the unchanged
`_read_chunk_and_decode`. Previously decoded text is retained in a local list
and joined once when publishing the line. This keeps the existing EOF,
trailing-CR, validation and newline tracking behavior in one decode primitive.
The current chunk retains its own replay origin for any unread remainder.

The existing terminator finder examines only the new chunk, plus a carried CR
when relevant to `newline=""` or `"\r\n"`. Empty decoder outputs preserve that
carry. The temporary buffer swap around this synchronous scan has no await and
is restored in a finally block; it avoids adding another helper call to every
ordinary buffered generic-line scan. Ordinary non-CR refills do not concatenate
the carried character with the new chunk.

Pending read origins now include the already-consumed character count, allowing
concurrent tell() to replay both empty-prefix and shared-prefix reads. Retryable
and validation-salvage failures restore the original state plus decoded pieces.
Real terminal poison still discards text via the binary observer; restoration
must not resurrect it or change post-error tell()/seek() behavior. Readlines'
outer rollback remains responsible for previously consumed complete lines.

## Deterministic evidence and review

Twelve linear-work cases cover both generic newline modes, readline, iteration
and bounded readline, at 1 and 2 MiB. They charge characters presented to buffer
concatenation and require at most twice the line size plus one 64 KiB chunk.
They all fail on cea195d at the intended work assertion and pass on the candidate.
The bound is structural, not an allocator-copy count or a timing threshold.

The two focused modules contain 408 cases: the work checks, pending cookies across
five read surfaces/three encodings/five newline modes and three prefix states,
cancellation and no-effect errors, stdlib differential line/cookie checks at
7/64-byte chunk sizes, exact CR boundary cases, CRC salvage and real terminal
source errors. The terminal tests pass unchanged against cea195d: ordinary
retries remain broken and explicit seek(tell()) resumes at the same decoder
frontier. They exercise actual poison callbacks rather than forcing an
inconsistent private failure flag.

Claude independently reviewed the implementation through Herdr and reported
3,000 differential fuzz seeds with no stdlib mismatches, including cookie replay.
These are reviewer results, not Codex-run fuzz evidence. An initial synthetic
non-restorable-failure finding was retracted after both reviewers independently
checked actual terminal source failures and the poison observer. No change to
terminal-failure semantics is included.

Final Codex validation: both full suites (default and forced stdlib) give
3,369 passed, 1 skipped, with no xfails. Against cea195d, the focused matrix
gives exactly 12 intended work-assertion failures and 396 passes. All pre-commit
checks pass. Claude's final diff review reports no remaining correctness concerns.

## Qualification still required

No throughput or wall-clock improvement is claimed by this commit. Refills now
take a decoder-origin snapshot each round, so compare ordinary short-line
iteration in both generic modes at the default chunk size, as well as long-line
scaling. Include wider chunk sizes, compressible/incompressible fixtures,
UTF-8/stateful encodings, terminators absent/at end/split, peak memory and
doubling ratios. A returned unlimited line still inherently occupies O(N) memory.

The overnight G08 job remains pinned to its earlier reviewed source and cannot
qualify this change. G06 measurements, G07 resource disposition and C0 remain
separate commit/review boundaries.
