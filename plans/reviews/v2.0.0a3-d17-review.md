## Area 1 — Header notification timing: PASS

Verified byte-granularly against plan §6.1–6.3: a fresh decoder reports
generation 0 / mtime `None`; the commit point is exactly header completion —
feeding 9 of 10 fixed-header bytes commits nothing, the 10th byte commits
with zero body bytes fed; FHCRC members commit only after the two FHCRC bytes
validate, and a corrupted FHCRC commits nothing. Body and trailer failures
preserve the committed header state; truncated or bad-magic headers commit
nothing; a rejected or mid-FNAME-truncated later header preserves the prior
member's values with no partial commit. Generation counts events (repeated
timestamps and mtime=0 each bump it). The file layer observes the
notifications correctly, including the full §6.2 rewind sequence
(retain-then-reparse). The read-ahead nuance (mtime can be ahead of returned
bytes when one transport chunk holds several headers) was confirmed to be
exactly the documented, contract-licensed behavior.

## Area 2 — File-layer synchronization under errors and cancellation: PASS

All probes passed. Overlap rejection is genuinely pre-effect: concurrent
intruding read/readline/readlines/seek and write/flush/writelines/close calls
each raised `ConcurrentOperationError` while the winning call completed with
output byte-identical to a serial reference run. The salvage state machine is
consistent across all six read surfaces (binary and text read(-1)/readline
loop/readlines): BadGzipFile → recovery data exactly once → terminal OSError,
never clean EOF; an unterminated remainder is withheld from readline but
retrievable via read(-1); decompression-cap and cancellation failures enable
no salvage. CancelledError/TimeoutError were never swallowed in any probe,
including `asyncio.timeout` expiring during context exit on both read and
write handles; every abort path left owned resources verifiably closed and
torn members verifiably invalid (no trailer). Clean context exit waited for
in-flight and looping producers and produced byte-exact valid streams; an
exceptional exit preserved the body exception identically and made the
aborted call raise rather than report success. seek(0) recovery constructs a
fresh decoder for both validation-poisoned and cancellation-poisoned handles.
Reviewer note for maintainers: cancellation landing in the source read before
any codec input is consumed leaves the handle retryable rather than poisoned;
this is structural (`_read_compressed_chunk` sits outside the poisoning try),
consistent with the documented transient-retry contract — optional post-a3
doc polish at most.

## Area 3 — Rewind and concatenated-member behavior: PASS WITH COMMENTS

The documented last-completed-header mtime semantics hold under execution,
match the stdlib oracle's final state, and the mid-stream read-ahead
divergence is exactly as documented. Rewind retains the last observed value
until a header re-parses, on both seekable and rewind-cached non-seekable
sources. Sixty randomized text tell()/seek() cookie round-trip trials
(multibyte UTF-8, mixed newline conventions, chunk sizes 1–8192, buffer
compaction past the threshold, CRLF split at chunk and member boundaries)
landed exactly with zero mismatches. `member_count` commits strictly
post-trailer; a corrupt second trailer does not increment it.

**Comment A3-1 (low, documentation/consistency):** on decoder failure,
`_release_state()` clears collected `members` while `member_count` (a plain
int) survives, so a failed decoder reports `member_count == 1` with
`members == ()` even for a member committed by an earlier successful
operation. `docs/codec.md`'s "change only after a complete member trailer has
been validated" does not mention the release-on-failure. Post-a3: either
document the release or retain `_members` alongside the count; add a test for
`members` after failure.

## Area 4 — Removal of duplicate parsing: PASS WITH COMMENTS

`_try_parse_gzip_header_mtime` and the header probe buffer are gone tree-wide
(the only mentions are historical plan text and a negative slot assertion).
The gzip magic appears in exactly two source files — the parser
(`_gzip_header.py`) and the builder (`_common.py`) — both consumed in
production only by `codec.py`; wrappers contain no framing, flag handling, or
member loops (verified by grep and by the AST purity test, which passes). The
single-state-machine architecture rule holds. **Comments (advisory):** the
builder helpers would sit more naturally beside the parser than among
`_common.py`'s validators; the AST purity test covers `_binary`,
`_inspection`, `_streaming` but not `_text` (which delegates everything —
a coverage nicety, not a gap).

## Area 5 — Small-write semantic preservation: PASS

All five frozen semantics verified: input snapshot isolation (mutating a
written bytearray/memoryview after `write()` returns does not affect output;
hostile `__bytes__` overrides are not consulted); the documented type surface
at the file layer with the stricter codec boundary intact underneath;
position published only after sink acceptance (failed and partial-progress
sink writes leave `tell()` unchanged and the member poisoned with the
documented error); per-call sink-failure attribution with no cross-call
output buffering; and byte-exact round-trip with correct CRC/ISIZE over 600
varied small writes. Informational note: a tiny write whose deflate output is
fully buffered makes no sink call and therefore cannot observe an
already-broken sink until the next emitting call (at latest `close()`) —
consistent with the frozen per-operation wording and inherent to DEFLATE.

## Area 6 — Benchmark methodology: PASS WITH COMMENTS

The harness excludes fixture generation and verification from timed regions;
correctness gates (SHA-256, live mtime, position, counts, bounded-source)
genuinely raise; regression-harness expected-failure gates accept only
`BadGzipFile` in both directions; source attestation (pre-import guard,
src-path check, engine check, commit + dirty + harness SHA-256) is strong.
Every sampled recorded hash (11 full, 10 prefixed) matched `sha256sum`; all
25 referenced intermediate commits exist; recomputation of the gated tables
from raw records reproduced every ratio under the stated metric — with one
exception now corrected (round-6 table was min-of-run-medians, not
min-of-samples; the error overstated the regression and the triggered
investigation stands). A transcribed nonexistent full hash in the small-write
disposition table was also corrected. **Comments (advisory):** the
outlier-dismissal isolation runs are prose-only (no archived raw JSON) —
acceptable for noise triage, worth archiving in future cycles; direct-decoder
rows include digest updates inside the timed region (both compared sides
identical, ratios valid, but the preflight doc's "verification outside the
timed region" is imprecise for those rows); `verify_a3_headers.py` accepts
`(EOFError, OSError)` with a message-fragment check rather than
`BadGzipFile`-only; the git dirty check ignores untracked files (mitigated by
`describe --dirty`); the `wp4-write-surfaces` capture ran unpinned and is
used descriptively only. None of these change any gate outcome.

## Area 7 — Public integrations and beta-contract audit: PASS WITH COMMENTS

`__all__` is set-equal to the documented API (31 names);
`ConcurrentOperationError` is exported as an `OSError` subclass;
`__version__` is consistent with the changelog posture. A battery of
documented-contract probes (closed/unopened/overlap/broken error types and
messages, the decompression-cap prefix, salvage ordering, codec misuse
errors, live-mtime behavior, cookie handle-binding, strict boolean/parameter
validation) matched the documentation exactly. A differential battery against
`main` found five behavior changes to established public APIs; every one is
CHANGELOG-documented and recorded as deliberate — no uncovered public-API
change. **Comments:** two of plan §17's beta-entry conditions cannot be
established by execution probes and remain open for the maintainer: (a) two
realistic public-only integrations have not yet been exercised; (b) this
document itself constitutes the independent-review condition only upon
maintainer acceptance. Pre-existing nit: stdlib/typing names re-exported from
`__init__.py` are importable though not in `__all__` (unchanged from main).
