## Reproducible artifact build

An ordinary repeated `uv build` preserved the sdist hash but changed the wheel
hash because wheel ZIP timestamps followed the build time. Recording that hash
would have made the handoff's local-versus-PyPI comparison impossible. Commits
`e9fa639` and `81e8cca` therefore make the tag-triggered publish job derive
`SOURCE_DATE_EPOCH` from the dated changelog release heading before building.
That value is independent of later evidence commits and merge strategy.

The exact local equivalent for the 2026-08-23 release is:

```bash
SOURCE_DATE_EPOCH=1787443200 uv build
```

## Isolated artifact smokes

Fresh Python 3.12 environments outside the checkout installed the final wheel
and sdist with `aiofiles`, `aiocsv`, and `typing-extensions`. `PYTHONPATH` was
unset for every run.

| Environment | Import path |
| --- | --- |
| Wheel | `/tmp/aiogzip-repro-wheel.eEgUS0/venv/lib/python3.12/site-packages/aiogzip/__init__.py` |
| Sdist | `/tmp/aiogzip-repro-sdist.2QsHCs/venv/lib/python3.12/site-packages/aiogzip/__init__.py` |

Both environments passed a public `aiogzip.open()` binary round-trip and
reported version `2.0.0a4`. Both passed the fragmented-transport self-test.
Both staged-ingest runs published three shards, 120 rows, 6,570 bytes, and
dataset SHA-256
`da984903329763970288bb264a05cc963923e054a1aa717d4a5880b35e0f0b0f`.

The restricted command sandbox did not allow executor-backed `aiofiles` opens
from `/tmp` virtual environments to settle. The exact smoke commands were
therefore rerun with normal filesystem/thread permissions; they completed
without changing repository or artifact state.
