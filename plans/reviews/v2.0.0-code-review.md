# aiogzip 2.0.0 post-release code review

> **Date:** 2026-11-09
>
> **Reviewed:** `main` at `a52c824` (`2.0.1.dev0`). Its `src/` differs from
> the `v2.0.0` tag only in `__version__` and one docstring in
> `_inspection.py`.
>
> **Status:** findings recorded; seven issues filed. No code was changed.

The maintainer asked for a review of the 2.0 code for correctness problems,
maintainability opportunities and possible new features. This is not a
release gate.

## Method

Five Claude subagents each reviewed one slice, read-only, and reproduced
their findings with scripts. Each was given the file-state model, the
behavior-exception ledger and the plan's deferred list, and told not to
re-report recorded decisions. No benchmarks or timings were run.

| Slice | Files | Report |
| --- | --- | --- |
| Sync codec core | `codec.py`, `_codec_buffer.py`, `_gzip_header.py`, `_engine.py`, `_metadata.py` | [codec](data/2.0.0/code-review/codec-report.md.txt) |
| Binary handle | `_binary.py`, `_source_io.py`, `_opening.py` | [binary](data/2.0.0/code-review/binary-report.md.txt) |
| Text handle | `_text.py` | [text](data/2.0.0/code-review/text-report.md.txt) |
| Async drivers and public surface | `_streaming.py`, `_inspection.py`, `_codec_async.py`, `__init__.py`, `__main__.py`, `_common.py`, packaging and typing | [api](data/2.0.0/code-review/api-report.md.txt) |
| Features and developer experience | docs, public API, CLI, neighbouring libraries | [features](data/2.0.0/code-review/features-report.md.txt) |

The reports are the reviewers' own text, with the session's scratch
directory replaced by `scripts/<slice>/`. Their scripts are in
[`data/2.0.0/code-review/scripts/`](data/2.0.0/code-review/scripts/), saved
with a `.txt` suffix so that the linters and pytest ignore them. Run one by
copying it to a `.py` file outside the repository and using
`uv run python <file>` from the repository root. Some write temporary files,
and the API scripts expect small `.gz` fixtures that were not kept.

The coordinating session re-ran the reproductions for the seven findings
below, except the lost timeout in #173 and the path-source and
returned-position observations in #172. Everything else in this record is as
the reviewers reported it.

## Result

No data corruption or wrong output was found on valid input. Seven bugs are
worth fixing in 2.0.1.

### Filed for 2.0.1

| Issue | Problem | Where |

### Lower priority, not filed

These were reproduced by the reviewers and not re-run by the coordinating
session. The reports have the details and script names.

- **Event-loop fairness with in-memory sources or sinks.** `inspect()` and
  `verify()`, `writelines()` and the write-mode zero-fill `seek()` never
  yield to the event loop. Path-opened files are unaffected. This overlaps
  the deferred fairness-policy item, but these gaps were not recorded.
- **Many tiny members.** 11,397 members of 23 bytes in one 256 KiB feed hand
  about 1.5 GB to inflate: a CPU amplification on untrusted input that
  `max_decompressed_size` does not catch.
- **Typing.** `WithAsyncWrite` requires `write(str | bytes)`, so a real
  binary sink fails `mypy --strict`. `os.PathLike` works at runtime but the
  annotations reject it. The fallback `open()` overload accepts any keyword,
  so typos type-check.
- **CLI.** A broken pipe is reported as a failed file; a header filename is
  printed raw, so escape sequences reach the terminal; `inspect --json`
  success output lacks the `ok` key that `verify --json` has.
- **Documented guarantees that do not hold.** `docs/codec.md` says a `bytes`
  subclass cannot alter the data the codec sees; on Python 3.12 and newer a
  `__buffer__` override can. `docs/index.md` claims full `tarfile`
  compatibility, but `tarfile.open(fileobj=handle)` fails.
- **Small validation gaps.** `readlines(None)` raises in both handles;
  `mtime=float("inf")` raises `OverflowError`; `mtime=True` is accepted; a
  mistyped `AIOGZIP_ENGINE` value is silently ignored; text `tell()` raises
  `struct.error` for ISO-2022-KR; an unopened text handle can raise a bare
  `AssertionError`; text write-mode `seek()` always fails with a misleading
  message; `fast_compress=True` without zlib-ng re-warns on every
  `compress_chunks` call; an early `aclose()` on a chunk stream leaves the
  inner generator to a later loop turn.

### Checked and found sound

- RFC 1952 framing, truncation and limit handling, fuzzed on both engines.
- 12,600 text operation sequences against `io.TextIOWrapper`, with no
  differences under strict decoding.
- About 12,000 cancelled reads: surviving results always concatenated to the
  exact text.
- Rewind cache, multi-member and padding reads, write/flush/close ordering,
  and settlement of native and custom calls.

## Maintainability

- **Cleanup precedence is implemented three times** (`_close_async_iterator`,
  `_scan_gzip`, `_acquire_path`). One shared helper would have prevented
  #173.
- **The handle has no state for "parked on codec work".** The four
  `_source_*` slots cover custom and native calls only, which is the blind
  spot behind #172. The stateful harness has the same gap: it parks calls
  only on source calls.
- **`_drive_operation` has two accounting modes** (budget or none). Always
  passing a budget removes the branches and fixes the `inspect()`/`verify()`
  fairness gap.
- **Module seams.** Neither large module should be split through its core.
  `_binary.py`'s source and sink transport (about 400 lines) could move to
  `_source_io.py`. `_text.py`'s cookie codec and writer half (about 350
  lines) could move out; separating the writer also removes the root cause
  of #175.
- **Duplication missing from the hot-path map:** the source and sink call
  pairs in `_binary.py`; the two pull loops in `_streaming.py`; the "publish
  fresh chunk" stanza, five times in `_text.py`; the `open`/`AsyncGzipFile`
  overloads; and the fixed-header fast path, which needs a `Parity:` comment
  and a map row.
- **Dead code:** `_mode_plus`; `_replay_characters(strict=False)`; the
  `search_from` parameter; most of `_engine._normalized_retained`, which
  only fake engines in tests exercise.
- **`CLAUDE.md` is stale:** it references `tests/test_aiogzip.py` and
  `mypy src/aiogzip.py`, neither of which exists.

## Features and developer experience

The features report ranks twelve proposals with usage sketches and evidence.
In outline:

- **2.0.x, no new public names.** An error-message pass (a sync file object
  passed as `fileobj`; corrupt-file errors that do not name the file; no
  magic bytes or format hint for a non-gzip file). Widen the path
  annotations to `os.PathLike`. Recipes for httpx, aiohttp and S3 bodies and
  for wrapping `BytesIO`; document the CLI.
- **2.1.** One-shot `compress()`/`decompress()` with a size limit. A reader
  adapter for `AsyncIterable[bytes]`. `iter_batches()` and `iter_chunks()`
  on the binary handle. `await aiogzip.open(...)`, `aclose()` and a `mode`
  attribute. A `ResourceWarning` for a writer dropped without closing.
- **Later.** Indexed random access (#72): the reviewer argues the issue's
  bit-offset design is not buildable on Python's zlib, and proposes
  in-memory `Decompress.copy()` checkpoints, then member-chunked writing
  with a persistent member index. Dropping aiofiles: the code already
  depends on aiofiles privates (`_file`, `_loop`, `_executor`).
