# 2.0.0a2 WP4 Incremental Header Parser

> **Machine status:** provisional implementation evidence from an Apple M3
> MacBook Air. The release-reference measurements and final gate decision must
> be rerun on the Framework Desktop used for the published GitHub numbers.

## Scope

WP4 replaces whole-pending-buffer header parsing with a stateful parser over
immutable queue spans. Fixed fields, FEXTRA, FNAME, FCOMMENT, and FHCRC are
consumed once. Header CRC is updated from zero-copy span views, metadata bytes
are retained only when requested, padding is consumed by queue cursors, and
trailers use an exact eight-byte queue read.

The reduced-limit tests prove that a terminator at the exact limit is accepted
and that the first byte beyond the limit remains queued when the parser rejects
the header. The release-only test exercised the real 128 MiB boundary.

## Results

Fragmented 64 KiB-feed medians:

| Field | 16 MiB | 32 MiB | 64 MiB | 64/32 |
| --- | ---: | ---: | ---: | ---: |
| FNAME | 1.597 ms | 3.273 ms | 6.712 ms | 2.05x |
| FCOMMENT | 1.611 ms | 3.497 ms | 6.390 ms | 1.83x |

Both largest doubling ratios are below the 2.5x gate. For context, the locked
same-machine `2.0.0a1` medians for 64 MiB fragmented fields were 4.109 seconds
for FNAME and 4.081 seconds for FCOMMENT; the candidate medians are measured in
milliseconds.

32 MiB incomplete-field peak Python allocation:

| Field | Metadata | Peak | Gate |
| --- | --- | ---: | ---: |
| FNAME | disabled | 5,509 bytes | < 4 MiB |
| FCOMMENT | disabled | 1,971 bytes | < 4 MiB |
| FNAME | enabled | 37,602,887 bytes | <= 79,691,776 bytes |
| FCOMMENT | enabled | 37,602,907 bytes | <= 79,691,776 bytes |

The real 128 MiB exact-boundary test passed. These functional and allocation
results support the implementation boundary, but the release checklist remains
open until the complete matrix is rerun on the Framework Desktop.
