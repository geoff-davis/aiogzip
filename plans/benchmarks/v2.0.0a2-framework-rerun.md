# 2.0.0a2 Framework Desktop Release Rerun

This is the execution checklist for the final release-reference capture. It
contains no benchmark result and does not satisfy a release gate by itself.
Run it on the Framework Desktop used for the published GitHub numbers, after
the production and documentation commits are frozen.

## Preconditions

1. Check out the candidate commit with a clean working tree.
2. Confirm the locked tags:

   ```bash
   git rev-parse v1.11.0^{commit}
   git rev-parse v2.0.0a1^{commit}
   ```

   Expected values are `3f23eadb524c8dba840c4fd855ad5acf84486048`
   and `920004672bbb5e76fb2088358d1cb7051290576d`.
3. Create or refresh detached worktrees outside this checkout:

   ```bash
   git worktree add --detach /tmp/aiogzip-v1.11.0-regression v1.11.0
   git worktree add --detach /tmp/aiogzip-v2.0.0a1-regression v2.0.0a1
   ```

4. Record the Framework model, CPU, RAM, kernel, Python, zlib, zlib-ng, `uv`,
   power profile, governor, boost state, affinity, load, and temporary
   filesystem. Stop unrelated workloads and keep these conditions unchanged.
5. Write initial JSON to `/tmp`. Writing into the source checkout during a run
   would make the benchmark attestation report a dirty target.

## Historical Suite

Use the current harness against each source root. Five repeats exceed the
zlib-ng minimum as well as satisfying the stdlib requirement.

```bash
categories=io,memory,concurrency,compression,scenarios,errors,inspection,streaming,micro

for source in \
  /tmp/aiogzip-v1.11.0-regression \
  /tmp/aiogzip-v2.0.0a1-regression \
  .
do
  if [ "$source" = "." ]; then
    label=aiogzip-v2.0.0a2
  else
    label=$(basename "$source")
  fi
  AIOGZIP_ENGINE=stdlib uv run --frozen python \
    benchmarks/run_benchmarks.py \
    --category "$categories" --size 8 --repeat 5 \
    --source-root "$source" \
    --environment-label "Framework Desktop 2.0.0a2 final ${label} stdlib" \
    --output "/tmp/${label}-historical-stdlib.json"
  AIOGZIP_ENGINE=zlib-ng uv run --frozen python \
    benchmarks/run_benchmarks.py \
    --category "$categories" --size 8 --repeat 5 \
    --source-root "$source" \
    --environment-label "Framework Desktop 2.0.0a2 final ${label} zlib-ng" \
    --output "/tmp/${label}-historical-zlib-ng.json"
done
```

## Regression Matrix

Capture throughput, memory, and ticker modes with identical release fixtures
for both historical references and the candidate:

```bash
for source in \
  /tmp/aiogzip-v1.11.0-regression \
  /tmp/aiogzip-v2.0.0a1-regression \
  .
do
  if [ "$source" = "." ]; then
    label=aiogzip-v2.0.0a2
  else
    label=$(basename "$source")
  fi
  for engine in stdlib zlib-ng
  do
    AIOGZIP_ENGINE="$engine" uv run --frozen python \
      benchmarks/run_benchmarks.py \
      --category regressions --regression-profile release \
      --regression-mode all --source-root "$source" --repeat 5 \
      --environment-label \
      "Framework Desktop 2.0.0a2 final ${label} ${engine}" \
      --output "/tmp/${label}-regression-${engine}.json"
  done
done
```

Rerun any named case whose candidate or comparison median differs by more than
5% with nine interleaved repeats. Preserve the original raw file, document why
the rerun was required, and never recapture only the candidate after a harness
change.

## Acceptance and Commit

1. Verify every JSON reports the expected source commit, a clean target,
   matching harness and fixture hashes, the requested engine, all individual
   samples, dispersion, memory peaks, scheduler gap distributions, and engine
   call counts.
2. Compare the candidate to `v1.11.0` for established high-level surfaces and
   to `v2.0.0a1` for codec-specific cases. List and investigate every delta
   above 5%.
3. Apply every hard gate in the release plan. The 512/256 KiB decoder,
   one-feed scaling, tiny-output engine-call, scheduler-gap, header, and memory
   gates have no waiver.
4. Copy the accepted raw JSON into `plans/benchmarks/data/` with unambiguous
   final names. Do not overwrite the locked earlier records.
5. Create `plans/benchmarks/v2.0.0a2-candidate.md` from those exact files,
   including commands, hashes, environment, all named deltas, and the accepted
   tiny-write disposition.
6. Run the complete quality and packaging checklist from the exact candidate
   commit. Only then prepare the version and dated changelog commit.
