Existing cancellation coverage uses a cooperative fake reader, so it misses these boundaries ([test_inspection.py:553](/home/geoff/Projects/personal/aiogzip/tests/test_inspection.py:553)).

2. **RC1-02 — Calculate `SEEK_END` correctly when EOF is known but data remains buffered**

   **Category:** RC1-blocker
   **Severity:** medium · **Confidence:** high

   **Evidence:** [_binary.py:603](/home/geoff/Projects/personal/aiogzip/src/aiogzip/_binary.py:603) drains buffered output only inside `while not self._eof`. A sufficiently large `peek()` can establish EOF while leaving all plaintext unread.

   Reproduced with a valid ten-byte payload:

   ```text
   peek(100)                 -> b'abcdefghij'
   seek(0, SEEK_END)          -> 0
   read()                    -> b'abcdefghij'
   ```

   After consuming one byte first, the same sequence reports position **1**, rather than **10**. This misreports the endpoint and leaves readable data after an ostensibly successful seek to EOF. The same branch exists in b1. Current endpoint tests start with fresh handles ([test_binary_io.py:339](/home/geoff/Projects/personal/aiogzip/tests/test_binary_io.py:339)); the stateful generator does not exercise `SEEK_END`.

   **Fix/test:** Account for unread buffered output even when `_eof` is already true. Test zero, negative and positive end-relative offsets after oversized `peek()` and partial consumption, on physical and cached rewind sources. Add end-relative seeks to the stateful interpreter/model.

3. **RC1-03 — Bound text `writelines()` storage for empty inputs**

   **Category:** should-fix-before-RC1
   **Severity:** medium · **Confidence:** high

   **Evidence:** [_text.py:2136](/home/geoff/Projects/personal/aiogzip/src/aiogzip/_text.py:2136) appends each empty string to `pending`, while the flush threshold counts only characters. This contradicts the bounded-memory claim in [docs/api.md:249](/home/geoff/Projects/personal/aiogzip/docs/api.md:249).

   A generator of empty strings with `chunk_size=64` retained **10, 1,000 and 10,000 pending entries** at those respective input counts, while producing zero plaintext. Retention therefore grows with input count rather than batch size. This is inherited from b1.

   **Fix/test:** Bound retained empty entries or coalesce them while preserving empty-write encoder semantics. Test long empty runs, mixed empty/nonempty inputs, iterator failure, and UTF-16/UTF-32 BOM behavior. Pin an item-count bound directly; timing measurements are unnecessary.
