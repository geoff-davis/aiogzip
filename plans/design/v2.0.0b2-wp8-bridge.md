# WP8 design: narrow text/binary bridge, one health authority

WP8 implements plan §12 and closes G12: *binary health is authoritative; bridge
and callback ownership are tested; the temporary seam is removed.* It is a
representation change compared against C0 (`refs/c0/v2.0.0b2`,
[record](../reviews/v2.0.0b2-c0-record.md)); no observable behavior changes.

## Current state

`AsyncGzipTextFile.open()` always constructs its own `AsyncGzipBinaryFile`; a
caller cannot hand text an existing binary object. After the binary open
succeeds, text assigns two binary slots directly and publishes the binary
object, with no suspension in between:

```python
binary_file._closed_observer = self._mark_binary_closed
binary_file._read_poison_observer = self._mark_binary_read_poisoned
self._binary_file = binary_file
```

Binary calls the poison observer from `_poison_read` (health and EOF committed
first; `decoder.discard()` in a `finally`), and the closed observer from
`_mark_closed`, which clears both slots before calling it.

## Design

### One labeled wrapper-support section in `_binary.py`

Every binary method text calls moves into one section headed as private
wrapper support, with a short contract per method. The section holds the
observer operations, the health and salvage predicates above, `_read_buffer_exhausted`,
`_close_on_context_exit` and `_check_write_call_available`. `_eof` and
`_position` stay plain slot reads, listed in the allowlist as measured hot-path
accesses. No Protocol: text uses one concrete class, and the allowlist test is
the stronger static check here.

### Health queries

The temporary `_read_broken` property is replaced by a binary predicate,
`_read_is_healthy()` (`self._read_health is _HEALTHY`), at its three text sites:
the terminal-poison check in `_check_text_read_usable`, the trailing-CR wait in
`_find_line_terminator` and `_finalize_pending_newline_state`. All three are
cold: the first runs only after a poison event, and the other two only for a
trailing CR in generic-newline mode or at EOF. `_has_validation_failure()` and
`_can_restore_failed_read()` stay as the authoritative predicates. Then
`_read_broken` and `_read_validation_failed` are deleted.

### Text's `_read_poisoned` latch (recorded design exception)

Text keeps a Boolean, `_read_poisoned`, set by the poison observer and cleared
when text itself rewinds (`_reset_to_start`, cookie `seek`). It gates the hot
read entry points (`readline`, `__anext__`, `read`, `readlines`) as
`if self._read_call_active or self._read_poisoned:`. It is not a health
mirror: it holds no health value, and every decision it gates queries the
binary authority. It is a one-way hint, "a poison event reached this text
handle since text last rewound", so that a healthy call pays one slot load.

Alternatives, timed in isolation (gate expression only, CPU 13):

| Gate | Cost per call | On the 100K-line `readline()` loop (~164 ns/line) |
| --- | ---: | ---: |
| Latch (C0) | baseline | baseline |
| `bf._read_health is not _HEALTHY` | +2.4 ns | about +1.5%, plus a `None` check before open |
| `not bf._read_is_healthy()` | +10 ns | about +6% |

Recommendation: keep the latch as a recorded exception, renamed
`_read_poison_seen` to say what it is, with this invariant tested after every
event in §12.3: *while the text handle is open, if binary health is not
HEALTHY then the latch is set.* The converse need not hold: after a direct
`buffer.seek(0)` the binary is healthy and the latch stays set, so the next
text read queries the authority, finds it healthy and proceeds, as at C0.
Removing the latch for the direct enum read is the alternative if the
maintainer prefers no text-side state at all; it would put binary's private
enum in the allowlist.

### Observer attachment and detachment

```python
def _attach_text_observers(
    self, *, closed: Callable[[], None], poisoned: Callable[[bool], None]
) -> None: ...   # raises RuntimeError if either slot is already set

def _detach_text_observers(self) -> None: ...   # idempotent; clears both slots
```

- **Ownership:** attaching over an existing observer raises instead of
  overwriting it. Text constructs its own binary, so this cannot happen through
  public API; the check guards internal misuse.
- **Initial synchronization:** text attaches after `binary_file.open()`
  succeeds and before publishing `_binary_file`, with no suspension between, as
  now. A fresh open is HEALTHY with an empty latch, so there is nothing to
  replay. A failed or cancelled open never attaches, and its cleanup close has
  no observer to call.
- **Detach:** `_mark_closed` detaches before calling the closed observer, as
  now; detach clears references only and never closes externally owned
  resources. It is called nowhere else, because text and binary close
  together; it exists so ownership is explicit and testable.
- **Observer failure:** `_poison_read` keeps health and EOF committed before
  the observer and `decoder.discard()` in a `finally`, so an observer error
  propagates without skipping cleanup (WP6). `_mark_closed` latches closure and
  detaches before calling the closed observer, so a raising observer cannot
  leave the binary open. Text's observers do not raise; the order covers
  internal misuse. Primary-error precedence is unchanged.

### Same-health events and direct `buffer` use

A successful text rewind resets text-local state itself, whatever the health
before and after. A rewind through the public `buffer` (`buffer.seek(0)`)
resets binary health without notifying text; text's decoded buffer and replay
origin are not synchronized. Mixing text reads with direct binary reads or
seeks is unsupported at C0, and WP8 does not add a synchronization guarantee:
new tests characterize the C0 behavior of direct `buffer` reads, seeks, and
close, and pin it.

### Allowlist

A structural test walks the AST of `_text.py`, collects every private
attribute accessed on the binary object, and requires the set to equal a
reviewed allowlist (the "keep" rows above plus the two observer operations),
with no stores to binary attributes. It replaces line-number matching.

## Tests (§12.3)

1. **Structure:** the temporary properties are gone; `_text.py` stores no
   binary attribute; private binary access matches the allowlist (AST).
2. **Attachment:** attach sets both; a second attach raises and leaves the
   first observers; detach is idempotent and clears both; a failed or
   cancelled open never attaches; close through text and through `buffer`
   detaches, and a repeated close is a no-op.
3. **Callback lifetime:** after close the binary holds no reference to the
   text handle (weakref check).
4. **Health authority:** after each event (open, ordinary breakage, validation
   salvage, transport-uncertainty correction, successful and failed rewind,
   close during active work, context-exit abort), text's decisions match the
   binary predicates, the latch invariant holds, and text-local effects (buffer
   discard on terminal poison, retention on salvage) happen.
5. **Observer failure:** a raising poison observer still discards the decoder
   (existing WP6 test); a raising closed observer leaves the binary closed and
   detached.
6. **Direct `buffer`:** read, seek and close through `buffer`, characterized
   against C0.
7. **C0 traces** (close, rewind, salvage, file-state) and both engine suites
   pass.

## Benchmarks

The same method A as WP7 in one reviewed window: `io,micro,text_origin,
read_health` against C0 on both engines. The hot read gates are unchanged, so
no hot-path cost is expected; the window confirms it.
