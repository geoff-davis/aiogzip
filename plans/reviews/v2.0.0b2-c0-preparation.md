## Open ledger questions

The committed b1 fixtures in `tests/data/` (`file_state_b1.json`,
`source_failure_b1.json`, `open_b1.json` and `open_cleanup_b1.json`) are compared
with a fresh capture of the current source by the full suite. Today's suite
passes on source identical to 2f78925, so every b1 scenario matches apart from
the named BC2 and BC3 allowances.

1. **Cookie correction `cea195d`.** It changes what `tell()` returns during an
   unpublished fragment read with no shared prefix: the old cookie skipped
   unpublished characters. No b1 trace scenario reaches that case, since the
   traces pass unchanged, so no trace allowance is needed. Decide whether the
   ledger should still record it as a narrow correction, with its regression
   tests as the evidence.
2. **Generic line accumulation `55c1e3e`.** It preserves semantics; the b1 traces
   confirm that for the scenarios they cover.
3. **BC5.** Fairness changes scheduling, not results; no trace allowance exists
   or is expected.

## C0 procedure

Run this only after G06–G08 are accepted and the C0 commit is chosen. Capture
from a clean worktree of that exact commit on both engines, and never import one
source from another's process. Run the worktree's own scripts, so the harness
checkout that `--require-clean` also checks is the same clean worktree. Run them
with the main environment's `uv run` from the main checkout; never `uv run`
inside the worktree, which would create a separate environment.

```sh
git worktree add /tmp/aiogzip-c0 <C0-commit>
C0=/tmp/aiogzip-c0
mkdir /tmp/c0-trace
PYTHONPATH=$C0/src uv run python $C0/scripts/capture_public_api.py \
  --check $C0/tests/data/public_api_2_0.json
for engine in stdlib zlib-ng; do
  uv run python $C0/scripts/capture_file_state_trace.py --source-root $C0 \
    --engine $engine --extended --require-clean \
    --output /tmp/c0-trace/file_state-$engine.json
  for kind in b2_source_failure b2_open b2_cleanup; do
    uv run python $C0/scripts/capture_${kind}_trace.py --source-root $C0 \
      --engine $engine --require-clean --output /tmp/c0-trace/$kind-$engine.json
  done
done
```

The file-state capture needs `--extended`: the committed b1 fixture and
`tests/test_file_state_trace.py` include the extended scenarios.
`capture_public_api.py` has no source-root option, so `PYTHONPATH` selects the
C0 source; confirm the imported `aiogzip` path before relying on the result.
Compare each trace capture with its committed b1 fixture, applying only the exact
BC2 and BC3 allowance files, as `tests/test_file_state_trace.py`,
`tests/test_source_failure_trace.py`, `tests/test_open_trace.py` and
`tests/test_open_cleanup_trace.py` do. The full suite on the C0 commit already
runs those comparisons; archive the separate captures and their hashes as the C0
record.

Then:

- run both full engine suites and all-file prek on the C0 commit;
- record the C0 commit, tree ID, `uv.lock` hash, public-manifest hash, trace
  hashes, ledger revision and the G06–G08 dispositions;
- create a local reference only, with no tag, and verify it resolves to the
  recorded commit and tree.
