# WP1 native-work settlement

BC1 repairs the cancellation race in `_codec_async.py`: the old helper could
be cancelled while its executor call still mutated the codec. The outer driver
mistook the helper's terminal state for native completion and closed the operation.

## Ownership and transitions

The driver owns the operation and workload snapshot. Its existing helper owns
one privately retained `run_in_executor` future in the loop's default executor.
The helper shields that future; the driver independently shields the helper.
Neither ownership layer cancels its retained work. Each uses
`_settle_before_cancel` to defer cancellation until its work is terminal.

| Transition | Ownership and allowed action |
| --- | --- |
| Helper created, not yet started | The driver retains operation/input; cancelling the helper prevents submission and permits cleanup |
| Executor submission | Exactly one synchronous `run_in_executor` call submits the advancement; no await separates submission from entering the protected wait |
| Submitted, queued | Cancellation does not try to withdraw the executor wrapper. The queued call is allowed to execute and settle |
| Native advancement running | The executor invocation retains the bound operation and workload. Driver/helper cancellation cannot authorize close, discard or input release |
| Native return or exception | The executor publishes the result only after the call's final operation access; the private asyncio future is never cancelled by these owners |
| Cancellation during wait | Preserve the first delivered cancellation at that ownership layer; repeated cancellations resume the protected wait |
| Settled after cancellation | Retrieve the result/exception, then propagate cancellation. A simultaneous failure is retained as its cause, including through the helper's cancellation chain |
| Driver exits unsuccessfully | Existing operation close/abandonment rules run only after settlement. Waiters may then observe cancellation and the codec's existing unusable state |

The retained future is authoritative because it is private and always shielded,
not because arbitrary asyncio futures have trustworthy cancellation semantics.
There is no check-then-discard race on a worker `started` flag. Cleanup stays in
the owning task, never in a worker finalizer. Input references may remain in
exception tracebacks while callers retain diagnostic exceptions; they cannot be
released prematurely. Normal cancellation releases them after task/callback and
diagnostic references are dropped.

Eliminating the helper and directly shielding the executor future was considered.
It is viable, but unnecessary for this bounded repair: preserving the existing
asynchronous dispatch boundary keeps caller-only cancellation and dispatch hooks
unchanged. Adding settlement protection at the inner boundary makes the existing
helper's terminal state trustworthy, including direct and global shutdown
cancellation. No executor, producer, thread, or task is added to the prior policy;
thresholds and inline work budgets are unchanged.

Cancellation may wait indefinitely for an uninterruptible native call, or for
work ahead of it in the default executor. Arbitrary blocked threads cannot be
forcibly terminated safely. Test watchdogs bound defective test runs; they are
not a production timeout or a cancellation-latency guarantee.

## Regression coverage

`tests/test_native_work_settlement.py` uses real executor threads and independent
gates to cover caller/helper/both cancellation, one and three cancellations,
worker success/failure, input lifetime, publication-before-cleanup, queued work,
pre-submission cancellation, output/progress/completion, errors before/after
output, outer timeout and TaskGroup failure. Queued-work tests occupy a dedicated
single-worker test executor; production still uses the loop's default executor.

The original F1 reproductions now run as ordinary passing tests. Actual
`asyncio.run` shutdown remains in a child with a parent timeout and independent
thread timer. Real encoder and decoder integration checks cover single/repeated
caller cancellation, with and without simultaneous helper cancellation. Both
engine modes must pass before G02 is closed.

The paired measurement harness is `scripts/measure_b2_native_settlement.py`.
It measures the same deterministic encode/decode fixtures and executor-step
latency on clean baseline/candidate trees, using a single committed harness.
Fixture creation, warmup and round-trip validation are outside timing. Individual
samples, median/MAD, hashes and engine/environment identity are retained. These
shared-host observations are a focused repair check, not release qualification.
