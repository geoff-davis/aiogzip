# 2.0.0a4 documentation decisions

Date: 2026-08-22

## Optional HTTP recipe

The two required integrations exercise the public codec and the high-level
file API without credentials or network services. An additional HTTPX recipe
would not close a contract or test gap for this alpha, so it is deferred as a
post-2.0 documentation idea and does not add HTTPX to core or example
dependencies.

If revisited, the recipe should request `Accept-Encoding: identity`, consume
`response.aiter_raw()` so HTTP content decoding cannot be confused with gzip
decoding, stage decoded output, and promote it only after the iterator ends
normally.
