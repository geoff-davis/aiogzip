# 2.0.0a3 Review Record

This is the living review record required by WP8. It records settled decisions
as they are reviewed; it does not by itself satisfy the final independent-review
gate. D17 remains open until the feature-frozen candidate and complete evidence
packet receive independent approval.

## Settled decisions through the read/write hardening review

### Live `mtime` compatibility correction

The a3 release decision knowingly accepts the `mtime` behavior specified by D5
and D6: the file property follows the most recently completed valid member
header, so concatenated-stream read-ahead can change it beyond the member
containing the bytes returned by a call. This matches the standard-library gzip
reader and is a deliberate compatibility correction despite the normal
alpha-series rule that established asyncio file APIs retain their contract. The
behavior remains documented in the changelog and locked by binary, text,
rewind, corruption, and stdlib-differential tests.

### Reader failure and recovery

All terminal decoder failures are poisoned through one file-layer path whether
they arise during `feed()` or `finish()`. Only format and integrity failures may
salvage already-buffered decoded bytes; decompression limits, cancellation, and
unexpected internal errors fail immediately. `seek(0, SEEK_SET)` on a rewindable
source is the explicit recovery operation and constructs a fresh decoder. Other
seeks on a poisoned reader fail with the close/reopen guidance.

Salvage is explicitly recovery of bytes decoded before the failure, not proof
that their member passed CRC/ISIZE validation. `read(-1)` keeps its buffer and
position transactional across a later failure without retaining a duplicate
buffer for the whole read. Terminal non-validation failures do not recopy bytes
that no read surface may expose. `readline()` accumulates a candidate line in
the shared buffer and publishes bytes and position together only after a
newline, explicit limit, or clean EOF; `readline()`, `readlines()`, and async
iteration therefore retain an unterminated pre-failure remainder and its error.
Recovery guidance mentions `seek(0)` only while the underlying source or
retained compressed cache is rewindable.

Overlapping read or seek calls on one handle are rejected before decoder
reservation without poisoning the stream or discarding another task's live
operation. The reservation remains active across source I/O, codec work, and
result publication. `close()` applies the same rejection while a read is live.
All file-layer overlap rejections use the public `ConcurrentOperationError`,
an `OSError` subtype that callers can catch explicitly before awaiting the
active call and retrying.
Each primitive read surface intentionally inlines only the two healthy-path
flag reads; overlap and salvage behavior is centralized in the shared cold-path
helper. An unconditional helper call here would restore the per-line call cost
that the prior `io,micro` review explicitly removed.

### Same-handle write concurrency

One file handle remains single-task-owned. Overlapping `write()`, `flush()`, or
`close()` calls are rejected before codec reservation/finalization and do not
poison the member. The guard remains active through codec completion, sink I/O,
underlying `flush()`, and file-position publication so the write/write,
write/flush, and write-or-flush/close gaps are not left implicit.

Text close checks that binary reservation before finalizing its incremental
encoder and remains open after an overlap rejection, so callers can retry once
the active write completes. Concurrent text closes serialize incremental
encoder and binary-trailer finalization, making close idempotent through its
awaits rather than only before and after them.

A clean binary or text context exit waits for an in-flight call and then owns
normal close/finalization, retrying if a looping producer reserves the handle
again before the waiter resumes. When an active call instead outlives a context
body that is already propagating an exception, context exit preserves that
primary exception and attempts owned-resource cleanup without discarding the
other task's live codec operation. Every reserved read surface crosses one
shared post-await abort check before any binary or text call can publish bytes,
position, a line, or EOF. Writes and flushes apply the symmetric check
before publishing position or success. Cancellation during abort cleanup
propagates; an ordinary underlying-close failure preserves the body exception
but leaves both binary and text layers reportably open for an explicit retry.

Binary and text close each serialize their complete finalization. A second
close therefore cannot return while the first is suspended writing encoder
tail bytes or the gzip trailer. Public text `closed` is derived from the binary
layer once that layer exists. The internal per-operation flag is refreshed by
one helper only at cold cleanup boundaries; consulting the delegated property
on every line was measured and rejected as a material hot-path regression.

The final lifecycle pass explicitly audited the symmetry matrix below. A dash
means the layer delegates the contract to the binary implementation rather
than maintaining an independent guard.

| Surface | Overlap ownership | Clean exit | Exceptional abort | Close completion |
| --- | --- | --- | --- | --- |
| Binary reads/seek | Read reservation | Retry wait loop | Pre-publication error | Binary lock |
| Text reads/seek | Binary delegation | Retry wait loop | Binary error before text publication | Binary lock |
| Binary write/flush | Write reservation | Retry wait loop | Pre-publication error | Binary lock |
| Text write/flush | Binary reservation | Retry wait loop | Binary error before success | Text then binary locks |
| Binary close | Rejects active I/O | Owns finalization | Retryable abort cleanup | Serialized |
| Text close | Binary preflight | Owns finalization | Binary cleanup/state | Serialized |

### Integration history

This release branch will be squash-merged. The final squash commit must follow
the `CLAUDE.md` subject/body and attribution-trailer requirements. The older
branch-local commits will not be rewritten individually: benchmark records
attest exact intermediate commit hashes, and rewriting those hashes would make
the release evidence misleading without changing the integrated history.

### Release harness failure gates

Incomplete-header cases accept only `gzip.BadGzipFile` as the expected failure;
an unrelated `OSError` aborts the run. The direct-decoder harness applies that
gate across both `feed()` and `finish()`, so feed-time corruption is recorded
per sample instead of terminating the complete benchmark process.

## Explicit post-a3 deferrals

- Keep the decoder notification generation and file-side observed-generation
  mirror required by D4/D5. Their two reset sites and read-only codec properties
  stay test-locked; collapsing them to a timestamp `None` check is post-a3 work.
- Keep `_feed_snapshot()`'s performance-motivated inline preconditions. A
  parameterized parity test now requires identical exception types and messages
  to public `feed()` across not-started, active, finalized, discarded, and
  strict-size states. Consolidating the implementation is post-a3 work unless a
  correctness issue appears.
- Keep `_Operation.__next__()`'s synchronous-hot-path copy of the ownership and
  lifecycle block used by `_advance_raw()`. Lifecycle parity tests exercise
  both the public iterator and async driver; consolidating the two blocks is
  post-a3 work unless profiling changes the current inlining disposition.
- Freeze the a3 release harness's evidence schema through this release. Its
  verification scripts reuse harness helpers, but convergence with
  `run_benchmarks.py` environment/schema machinery is post-a3 cleanup so the
  captured baseline and candidate records are not mutated late in the release.

These deferrals are intentional release-scope decisions, not unresolved a3
correctness gates. They should be reconsidered after the a3 tag rather than
reopened during final evidence recapture.
