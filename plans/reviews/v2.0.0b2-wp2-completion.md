## Correctness and compatibility

The maintainer explicitly selected: “Make unknown-effect errors terminal;
preserve retries only with a provable no-effect guarantee.” This resolves the
separate decision required by WP2 §6.2 for ordinary custom-source errors.

Supported native aiofiles calls retain a worker-owned completion record. An atomic
entry guard can prevent source access before it starts; otherwise cancellation
waits for the worker's last source access. A cancelled successful read retains
one chunk, including EOF, for ordered exactly-once retry. The original cancellation
remains primary, with a simultaneous native failure chained as its cause. Normal
reads use the ordinary executor notification without an extra shield hop.

Custom sources must finish their source activity before returning or raising.
Changed or unknown consumption poisons the reader, invalidates incomplete replay
state, and prevents text/binary buffered output from concealing a gap. An optional
truthful synchronous cursor proves no effect only if it accounts for all consumed
input, including before exceptions. No new public method is required. Physical
rewind/reopen permits safe recovery; cached replay cannot repair missing input.

The [design](../design/v2.0.0b2-source-consumption.md) explains pending-input/cache
ordering, exceptional context exit, borrowed resources and the completion contract.
The [BC2 ledger](v2.0.0b2-behavior-exceptions.md#bc2-selected-correction) scopes the
intentional behavior change. Validation salvage, original first-error classes,
public signatures and ownership flags remain unchanged. Uninterruptible native
work or a non-cooperative custom source can delay settlement indefinitely.

## Performance and disposition

The [manifest](data/b2/wp2/manifest.json) identifies all raw evidence and hashes.
The [full comparison table](data/b2/wp2/performance-summary.csv) contains both
minimum and median values, candidate deltas and identical-baseline drift for every
case. Initial direct-shield evidence is retained in a separate subdirectory and
is not counted as final-candidate results.

The final committed-harness measurements compare clean WP1 `1b7e0e6` with clean
WP2 `f66c92b`, using one interpreter/environment and harness `a923f22`. Each engine
runs A/B/B/A, with one warmup and eleven retained samples per case. The 24 cases
cover hex lines and incompressible random bytes, native/custom sources, binary/text,
and read-all/read-sized/readline. Both compressed fixtures exceed a default input
chunk. Setup/open/close/validation are outside timing; collection/join are inside.
These are warm-cache read measurements, not memory or storage qualification.

One-minute loads were 1.18–1.38 for stdlib and 1.48–1.80 for zlib-ng. This does
not independently establish a quiet host. Identical-baseline movement and sign
changes are substantial. Selected observations below illustrate the limits;
the CSV retains every row, including unfavorable ones. Positive deltas mean slower.

The initial direct-shield implementation had repeated incompressible-read slowdowns.
The final implementation removes its extra normal-read scheduling hop by construction;
that is a structural reduction, not proof that the measured slowdowns are eliminated.
In particular the final custom binary read-all results warrant investigation.

A retained standalone [focused diagnostic](data/b2/wp2/source-micro.py.txt) measures
the private source boundary and public random-data read-all separately, again
A/B/B/A with eleven samples. It uses clean sources and records its exact script
hash, but was not run from a committed harness and is not qualification evidence.
It omits the main harness's per-read diagnostic list. Loads were 2.48–2.52.
The source-boundary minima add 0.11–0.88 microseconds per call across the four
pairs: the added checks have a measurable local cost. Public read-all minimum
deltas are +8.3% / -3.0% for stdlib and +23.4% / +9.8% for zlib-ng; identical
baseline minima drift +8.4% and +13.1% respectively. Zlib-ng read-all medians
change +15.0% / -3.8%, while its baseline median drifts +22.7%.

The focused check confirms added boundary work but does not resolve the end-to-end
regression magnitude. Do not infer either a general speedup or a clean performance
pass. G03 closes on source correctness; G17 remains open for quiet-machine,
interleaved cumulative baseline/C0/final qualification, including this custom binary
read-all case. No performance-policy exception is asserted. Any attributable
regression above the plan's threshold must still be repaired or explicitly resolved
under that policy before G17 can close.

## Maintainer review correction

Review of `156ae27` found that context exit's cancellation of a custom read was
converted to `OSError("read aborted")` without removing its cancellation count.
G03 was reopened for this finding and closed again with the correction and tests
in this commit. All previous captures and counts above remain historical evidence
for the initial implementation, not reruns of the correction.

`_call_custom_source` now calls `uncancel()` exactly once when converting the
context-abort `CancelledError` to the existing `OSError`. It does not reset all
counts or consume cancellation on other error paths. A separate regression queues
an outside cancellation before the abort and verifies that its count remains one.

Ten new cases cover binary/text readers, exceptional body exit and cancellation
of clean context exit: four direct count assertions, four caught-TaskGroup-error
sequences on Python 3.13+, and two independent-cancellation controls. The first
eight failed on unpatched Python 3.14 at the intended stale-count or cancelled-task
outcome. All ten pass after the correction. Python 3.11/3.12 run the direct count
and outside-request checks; the TaskGroup sequence is restricted to 3.13+ because
older TaskGroup implementations do not preserve cancellation counts in the same way.

Executed for this correction on Linux:

- Python 3.14.2, full default and forced-stdlib suites: **2,653 passed, 1 skipped,
  12 xfailed** each.
- Python 3.11.14 and 3.12.12, aiofiles 23.2.1, each engine: **258 passed, 4 skipped**
  in source settlement, source trace, lifecycle, state matrix and native I/O files.
  The four skips are the version-specific TaskGroup cases.
- Required `uv run prek run --all-files` and strict documentation build pass.

The [review-fix evidence](data/b2/wp2/review-fix/manifest.json) retains logs and
file hashes. Python 3.13 was not run in this session; Python 3.14 exercises the
reported visible regression. Floor checks select checkout source, not a wheel.

Additional evidence below is **maintainer-reported**, not rerun here: both full
initial suites matched 2,643 passed, 1 skipped, 12 xfailed; the review's 3.11/3.12
floor runs gave 279 passed, 1 skipped, 4 xfailed; twenty repeated runs passed.
The maintainer's scratch fix passed 252 focused tests. Their ABBA measurements at
4 KiB chunks used identical 258-read counts and measured +0.34 microseconds per
custom read and +0.45 microseconds per native read, approximately +6.6% in that
small-chunk case and negligible cost at default 256 KiB chunks. They identified
the earlier +105% custom row as host noise. G17 retains the small-chunk cost for
qualification; these review measurements do not constitute a new local timing run.

The source contract now explicitly documents that synchronous `tell()` is called
before each physical custom read/seek and, when possible, after failure. This is
new observable activity in user code, necessary for no-effect evidence; successful
reads need only the initial checkpoint. The maintainer observed 0 → 258 calls in
their benchmark. No WP2 commits have been pushed.
