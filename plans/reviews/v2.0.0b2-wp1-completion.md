# WP1 completion: native-work settlement

G02 is complete locally. The final repair is `f39fb8e`; the initial safe repair
and shared measurement harness are `c27b48d`. Only `_codec_async.py` changes
production behavior. F2/F3 and the remaining work packages are still open; C0
has not been created. No commits were pushed and no hosted/platform qualification
is claimed.

## Correctness and compatibility

The driver now directly retains a shielded executor future until native completion.
It no longer creates a helper task. Repeated cancellation, cancellation of the
shield waiter, and actual runner shutdown cannot make running or queued native
work appear finished. Cancellation remains the outcome; a simultaneous worker
failure is retrieved and retained as its cause. Cleanup and input release follow
native settlement. See the [ownership design](../design/v2.0.0b2-native-settlement.md)
and [BC1 ledger](v2.0.0b2-behavior-exceptions.md#bc1-selected-correction).

The executed environment is Linux/Python 3.14.2, aiofiles 25.1.0 and zlib-ng 1.0.0.
Forced stdlib uses stdlib compression/decompression/CRC. Optional-engine mode uses
stdlib default compression and zlib-ng decompression/CRC, as the raw records show.
Full suites include existing public API, typing and contract tests; they are not
fresh installed-wheel or Windows/macOS results.

## Paired performance and disposition

Baseline source is `dc8950c`; final candidate is `f39fb8e`. Both were measured from
clean trees with the same clean `c27b48d` harness, interpreter and dependencies.
Each engine ran A/B/B/A: baseline, candidate, candidate-reverse, baseline-reverse.
Each case retains 21 samples, median and MAD, exact fixture hashes and engine
identity. Timing is sequential, with warmup, fixture creation and correctness
validation outside the samples. These are direct codec-driver measurements using
its default offload threshold, not file-reader performance qualification.

The first safe implementation retained the helper and added a shield. Its separate
[raw records](data/b2/wp1/initial-helper/) show executor-step overhead of about
1.6–33.3% across the four pairs, motivating removal of the helper before G02 closed.
Those observations have not been overwritten or counted as final-candidate results.

Final executor-step latency decreased 4.7–20.2% in all four pairs. Caller-only
cancellation latency was within -0.5% to +0.7%; this separate instrumented probe
measures cancellation plus gate release through real encoder work and cleanup,
excluding the gate wait. It does not compare safe settlement with unsafe early
return, or promise a bound for uninterruptible work.

Throughput remains noisy on this shared host. The unchanged 16 KiB inline controls
vary substantially; zlib-ng 4 MiB decode changes from +35.4% in the first pair to
-3.2% in the reverse pair, and its 1 MiB decode changes from +11.4% to -4.5%.
These >5% observations were investigated with the balanced second pair and
unchanged-path controls. They do not establish a candidate-attributable hard-gate
regression or a general speedup. G17 remains open for controlled cumulative
baseline/C0/final qualification; no performance-policy exception is asserted.

Cancellation can still wait for queued or uninterruptible native work. WP2 must
apply authoritative settlement to source I/O separately; this codec repair does
not resolve consumed-input loss.
