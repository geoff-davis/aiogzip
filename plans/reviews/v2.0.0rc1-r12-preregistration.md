# R12 pre-registration: RC1 timing windows

Codex confirmed (two rounds, then wording-only corrections; it also
confirmed the retry amendment under Pinned inputs). Nothing here has run. The maintainer authorized a
window starting at about 01:00 on 2026-10-09, when the machine is expected to
be quiet. Gate R12 of the [2.0.0rc1 plan](../RELEASE_2_0_0RC1_PLAN.md)
collects the timing checks deferred by R01, R03, R04, R08 and R15. Its
acceptance criterion is "no unexplained cost above 5%". The method follows the
[G17 pre-registration](v2.0.0b2-g17-preregistration.md) (CLAUDE.md method A).
It differs in four ways: one comparison window, a targeted script, no
preflight and no structural steps.

## What is measured

| Repair | Changed path | Rows that measure it |
| --- | --- | --- |
| R01 (BC11) | Text `seek()` snapshot and rollback; read-cursor witness on the binary reader | `text_origin` (tell/seek cookie round trip), `read_health` (seek(0) rewind and recovery), and the `io` and `micro` text read rows |
| R03 (BC14) | `inspect()` and `verify()` settle the native open, read and close | `inspection` (verify, inspect, read-and-discard) |
| R04 (BC12) | The end-relative binary seek's drain loop counts unread buffered output before checking EOF | `rc1_paths.py`: `open + seek_end drain x20` (a fresh file of about 1 MiB drained by `seek(0, SEEK_END)`, every fill through the changed loop) and `open + peek + seek_end x200` (`peek(1025)` reaches EOF on a 1 KiB file, then `seek(0, SEEK_END)`: the peeked-output branch; b2 returns 0 there and the candidate 1024, so this times the path, not equal work). No runner row seeks from the end |
| R08 | Text `writelines()` no longer stores empty strings in `pending` | `rc1_paths.py`: `text writelines empty runs x20` (20,000 items, 12,000 of them empty in short runs, then a run of 20,000 empty strings). The `micro` text writelines row times the non-empty path; the write-size `writelines` rows are binary and do not reach R08's code |
| R15 (BC13) | `close()` and context exit settle the owned native close | `rc1_paths.py`: `open/close x200`, and every runner row that opens and closes a file |
| R09 (BC15) | An abort keeps the task's cancellation count when a cancelled custom call ends without `CancelledError`; context-exit cleanup failures are attached as notes; unexpected CLI failures exit with status 2; the `readinto` comment | No new row. The cleanup-failure and CLI changes run only on cleanup-failure and CLI-error paths. The cancellation change adds a `finally` condition that every custom-source and custom-sink call evaluates, but its `uncancel()` body runs only during an abort; ordinary custom-sink calls are timed by the write-size rows, which write to a custom sink (`CountingMemorySink`), but no captured row reads from a custom source, so the source-side condition is not timed; the `readinto` item is a comment. Ordinary reads and context exits are timed by the runner rows |

Every other runner row is also judged, so a cost on an unlisted path is
caught too.

## Harness

The harness lives in `.cache/rc1-bench/`, which git ignores. It is archived
with the evidence. `quiet_gate.py` and `envcheck.py` are byte copies of the
G17 files. `run.sh` and `summarize.py` are adapted from G17's.

### Pinned inputs

- **Unit.** `aiogzip-r12.service` (`Type=oneshot`, `TimeoutStartSec=4h`) runs
  `attempt.sh`, which runs `run.sh` with `MODE=ab`, then with `MODE=aa`. Its
  `ExecStartPre` lines check the sha256 of `run.sh`, `harness.sha256` and
  `attempt.sh`. `aiogzip-r12.timer` starts it at 01:00, 02:00, 03:00, 04:00
  and 05:00 on 2026-10-09; a firing while an attempt is still running starts
  nothing.
- **Retries.** At the maintainer's request, a window whose quiet gate never
  passes is retried at the next firing. A window counts as attempted once its
  gate passes, because `run.sh` writes `provenance.txt` only then; a gated
  window is never retried automatically, whatever its outcome. `aa` is
  attempted only after `ab` has passed its gate, so the control always
  follows the evidence window. A deferred attempt times nothing, so retrying
  cannot select among results.
- **Driver checks.** `run.sh` refuses to start unless
  `sha256sum --check --strict harness.sha256` passes. That list pins
  `quiet_gate.py`, `envcheck.py`, `summarize.py`, `rc1_paths.py`,
  `runner-rows.json` and both manifests.
- **Manifests.** `manifest-<mode>.json` is the only source of commits,
  roles, the runner commit, the categories, the runner's `benchmarks/` tree,
  the `uv.lock` sha256 and the installed-environment fingerprint.

### Execution

- **Worktrees.** As in G17: fresh detached worktrees for A, B and the runner,
  at `/tmp/aiogzip-r12-{a,b,runner}`. The driver checks each commit and a
  clean tree, the runner's `benchmarks/` tree and both `uv.lock` copies.
- **Environment.** `uv sync --locked --all-extras --check` must pass, and
  `envcheck.py` must reproduce the pinned fingerprint.
- **CPU and quiet gate.** Every step runs on CPU 13. The G17 quiet gate must
  see 120 s at 2.5 foreign cores or fewer within 30 minutes, or the window
  is deferred and the driver exits. A monitor samples foreign CPU every 5 s.
- **Captures.** For each engine (stdlib, then zlib-ng), eight captures run
  in ABBA ABBA order. Each capture runs three steps:
  1. `run_benchmarks.py --category <categories> --repeat 5 --regression-profile quick --regression-mode throughput`;
  2. `bench_a3_regressions.py --categories writes --repeat 5`, with the
     default sizes (10 B to 256 KiB) and all four write methods;
  3. `rc1_paths.py --repeat 5`, which runs one warm-up and then five timed
     batches for each of its four rows. Its fixtures come from `random.Random(0)`, so both
     sides read the same bytes. It imports aiogzip only from the side's
     `src/`, verifies the import and the active engine, and records the
     source commit, the clean state and its own sha256.

## No preflight

G17 froze each role's row set in a separate preflight. R12 does not run one
before tonight, because the machine is not yet quiet and a preflight also
needs authorization. Instead, the inventory is pinned without timing:

- `runner-rows.json` lists the 57 runner rows every capture must have,
  exactly. It is G17's frozen runner row set (48 rows, identical for C0 and
  the candidate on both engines, from the same `benchmarks/` tree `41e9979`)
  plus the nine `inspection` rows that `bench_inspection.py` names
  statically: `verify`, `inspect` and `_read_discard` for each of
  `compressible`, `incompressible` and `many-members`.
- The write sizes must have every size and method, as in G17.
- `rc1_paths.py` must report its four rows by name.

`summarize.py window` also requires all eight captures in each engine to
agree: identical runner row sets, identical write fixtures and identical
`rc1_paths.py` fixtures. A row set that differs between b2 and the candidate
refuses the window rather than being compared.

`summarize.py` was dry-run on a synthetic window built from the archived
G17 C0 window's runner and write JSON. It reproduced G17's flush deltas
(+5.94% stdlib, +7.54% zlib-ng). It refused each injected defect: a changed
row set, a missing inventory row (G17's captures lack `inspection`), captures
with no results, a wrong commit, changed `rc1_paths.py` fixtures, a dirty
source, and foreign CPU above 2.5 cores. The `rc1_paths.py` rows were checked
for correctness (not timed) on both `962bfe4` and `dd70af4`: both drain to
1,024 bytes, the peeked-output branch gives 0 on b2 and 1,024 on the
candidate, and both write the expected text.

## Statistics and decision rule

`summarize.py window` refuses any window in which:

- a capture is missing, incomplete, failed or mislabeled;
- a commit, the runner commit, the requested or active engine, or the clean
  state is wrong;
- `rc1_paths.py`'s recorded sha256 differs from the pinned file;
- the per-engine agreement above fails;
- a duration, a write median or an `rc1_paths.py` median is not a finite
  positive number, or a `memory` row lacks a finite `memory_increase_mb`;
- foreign-CPU samples fail to cover any step continuously, or foreign CPU
  exceeds 2.5 cores during any step.

A refused window is rerun whole, and the candidate is never rerun alone.

The primary statistic is each row's minimum of the four capture medians on
each side. The four adjacent A/B pair deltas are reported alongside it. The
policy is G17's (plan §15.1 of b2):

| Slowdown (B against A, by minimum) | Required action |
| --- | --- |
| 5% or less | None |
| More than 5% | Investigation and a recorded disposition |
| More than 10% and attributable to the candidate | Blocks by default |

The `aa` window reports each row's delta and the largest absolute delta per
engine. It is evidence within an investigation, not a waiver. G17's accepted
costs (D1–D9) are b2's baseline and are not re-litigated. A row above 5% is
judged against `962bfe4`, which already carries them.

The `memory` category's durations are timing rows and are judged like any
other. Its `memory_increase_mb` values are reported per capture and are not
judged by percentage.
