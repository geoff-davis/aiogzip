## Draft GitHub release notes

### aiogzip 2.0.0b2

This is the second beta in the aiogzip 2.0 series. The documented 2.0
public API remains frozen: every public signature, type and codec-lifecycle
rule is unchanged from `2.0.0b1`, and the runtime contract manifest is
identical. Beta is still a prerelease; test it against your workloads and
pin it appropriately.

This beta corrects cases in which `2.0.0b1` could lose, skip or misreport
data, or touch a resource after its owner had released it:

- **Cancellation waits for native work.** Cancelling a compression or
  decompression step, or a native read, write, flush, seek or open, whose
  work runs in an executor thread now waits for that thread before the
  cancellation propagates, so closing a handle can no longer run cleanup
  while that work is still active. As in `2.0.0b1`, cancelling `close()`
  itself does not wait for the underlying file's own native close.
- **No silent skips after a failed source read.** A native aiofiles read that
  completes after cancellation is kept for the next read. A custom source
  that fails or is cancelled without proving it consumed nothing leaves the
  reader broken rather than accepting whatever it returns next.
- **One owner per opened resource.** A concurrent `open()` or `close()`
  during acquisition raises `ConcurrentOperationError` instead of leaking a
  file, and a cancelled path-backed `open()` closes what it opened.
- **Writer and reader context exits settle in-flight calls.** An exception
  leaving a writer's context while `write()` or `flush()` is running now
  waits for that sink call before closing the sink, and a native rewind that
  finishes after the reader's context exit no longer reports success from
  the closed reader. If that exit's close of the underlying file fails, a
  text handle no longer returns text it decoded before the exit.
- **Text correctness.** `tell()` during an in-progress long-line or sized
  read returns a cookie that replays every character. After an integrity
  failure whose recovery bytes end inside a multibyte character, text
  `read()` returns every complete recoverable character instead of raising
  `UnicodeDecodeError`, and it reports the broken stream instead of a false
  EOF.
- **Fairness and scaling.** `decompress_chunks()` and `compress_chunks()` no
  longer starve sibling tasks when the source is always ready.
  `readlines()` with small hints, and long lines with `newline=""` or
  `newline="\r\n"`, now take linear time.

Two changes affect recovery code:

- After a custom source raises or is cancelled, an `OSError` no longer means
  a retry is safe. The reader stays usable only when an unchanged synchronous
  `tell()` on the source proves nothing was consumed, so custom sources'
  `tell()` is now called around each physical read and seek; it must be cheap
  and free of side effects. Otherwise recover with a `seek(0)` that completes,
  or reopen the source.
- After an integrity failure, a text reader may refuse `seek(cookie)` to a
  cookie saved before the failure. `seek(0)` remains the guaranteed
  recovery; after it, saved cookies work again.

Separately, the binary and text handles were refactored internally to share
one read-health authority, one source and native-call owner, and an
explicit opening state. This private refactor removes no public name.

The ownership guarantees cost some per-call throughput. In microbenchmarks
against `2.0.0b1`, `flush()` is about 6–8% slower, and `read1()`,
`readinto1()` and small-buffer `readline()` about 6–9% slower; reads at
default chunk sizes amortize it. Small reads such as `read(1)` can still
inflate and retain much more plaintext than they return; the
[errors guide](https://github.com/geoff-davis/aiogzip/blob/v2.0.0b2/docs/errors.md)
explains how to bound memory for concurrent untrusted inputs.

AnyIO/Trio support and indexed random access remain deferred. See the
[changelog](https://github.com/geoff-davis/aiogzip/blob/v2.0.0b2/CHANGELOG.md)
for the full list.
