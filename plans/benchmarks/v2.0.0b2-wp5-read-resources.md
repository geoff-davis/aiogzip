## Read-ahead and retained data

The following are seekable-source binary `read(1)` observations. Inflated bytes
are summed across the cohort. Allocation peaks are incremental tracemalloc bytes,
including task/instrumentation overhead but excluding fixture creation and open.
Peaks include transient copies while buffers are built and are distinct from
the unread data retained after the call.

| Plaintext per handle | Handles | Total inflated bytes | Stdlib Python peak | zlib-ng Python peak |
| ---: | ---: | ---: | ---: | ---: |
| 1 MiB | 1 | 1,048,576 | 2,101,048 | 2,101,048 |
| 1 MiB | 4 | 4,194,304 | 5,382,514 | 5,389,186 |
| 16 MiB | 1 | 16,777,216 | 33,600,761 | 33,600,761 |
| 16 MiB | 4 | 67,108,864 | 84,075,455 | 84,082,127 |
| 32 MiB | 1 | 33,554,432 | 69,255,601 | 69,255,601 |
| 32 MiB | 4 | 134,217,728 | 176,313,681 | 176,313,681 |

The repeated-byte 16 MiB fixture compresses to 16,328 bytes, all fetched and
accepted in one source read. Binary read retains 16,777,215 unread bytes after
returning one. Peek returns one and retains all 16,777,216. Text read returns one
character, with 16,515,072 binary bytes and 262,143 decoded characters unread.
Each codec output piece is at most 262,144 bytes; that does not cap the aggregate.
One member is already validated and mtime is 123 on these successful first calls.

The seeded random 16 MiB control differs: binary read fetches 262,144 compressed
bytes and inflates 262,054, retaining 262,053 after returning one. Text read needs
two source chunks to satisfy its 262,144-byte binary refill: 524,288 compressed
bytes fetched, 524,118 inflated, 261,974 binary bytes and 262,143 text characters
unread. Neither first call has validated the member yet. Whole-file inflation is
therefore fixture-dependent, not a claim about every 16 MiB input.

Nonseekable handles additionally retain compressed rewind data: 16,328 bytes for
the compressible fixture, 262,144 for random binary read and 524,288 for random
text read. Physically seekable handles retain no compressed cache. All successful
rows pass complete post-measurement content verification, including peek's
non-consumption.

## Limits, validation and disposition

With a 1 MiB limit against the 16 MiB fixture, all six limit rows per engine
inflate exactly 1,048,577 bytes, account for only 1,048,576 and return no logical
data. A subsequent read raises; readinto leaves its destination unchanged. The
extra byte is the codec's overflow detector, not delivered plaintext. CRC-failure
rows return an error on the first small read, retain the full plaintext for
explicit salvage, verify that salvage's complete hash, then raise on further
read. Metadata has advanced to mtime 123, but no member is validated.

The [public tests](../../tests/test_wp5_partial_read_limits.py) additionally cover
all seven surfaces at limits below/at/above the exact payload boundary, two members
inside one source item, and a corrupt trailer fetched after successful early
reads. Their 86 cases pass. These tests preserve public behavior rather than
asserting private retention sizes.

Retain eager drain for b2. The measurements substantiate the documented tradeoff:
small read sizes bound delivery, not aggregate memory or validation work. Existing
[untrusted-input guidance](../../docs/recipes.md) recommends bounding decompressed
size and concurrent handles. A demand-bounded reader requires a separate decision
about validation, metadata and salvage timing; it is not an incidental optimization
in this increment.

Tracemalloc excludes native allocations. RSS fields are process snapshots before
and after first calls, include pre-existing fixture storage and are not transient
peaks. Text uses Latin-1/LF to map characters directly to plaintext bytes. These
are single resource observations per case, with no wall-clock measurements and no
quiet-machine or throughput qualification claim. The separate latency phase and
its review remain outstanding before closing G07.
Recorded one-minute load spans approximately 2.4–2.8, with all 32 CPUs allowed;
this was not a quiet-machine run.

Claude reviewed the captures through Herdr and independently verified the hashes,
provenance, all quoted numbers and the 86-case public-test count, with no findings.
Both full local engine suites pass 3,430 tests with one skip each; all-file prek
passes. These checks do not substitute for the remaining latency qualification.
