## Exit criteria (§12)

- **Binary health is authoritative (§12.1).** Text holds no copy of binary
  health. Where the latch gates a health decision, text queries binary
  authority: `_read_is_healthy()`, `_has_validation_failure()`,
  `_can_restore_failed_read()`, `_validation_salvage_exhausted()` or
  `_check_read_usable()`. A healthy fast path with the latch clear
  deliberately skips the query and relies on the tested invariant below.
- **Recorded design exception: the latch.** Text keeps one Boolean,
  `_read_poison_seen`, set by the poison observer and cleared only when text
  itself rewinds. It is a one-way hint that lets a healthy hot-path call skip
  the binary query; once set, the decisions it gates query binary. The maintainer
  chose to keep it on 2026-10-05. The measured alternative costs, in an
  implementer-reported micro-test (outputs not archived): latch check 18.3 ns,
  direct enum read 20.7 ns, predicate method call 28.3 ns per readline,
  about +6% on the readline loop. Invariant, tested after every event: while
  text is open, binary health that is not HEALTHY implies the latch is set.
- **One labeled interface (§12.2).** A "Private wrapper support" section in
  `_binary.py` holds every binary method text calls, plus
  `_detach_text_observers`, which binary uses itself on close and tests use
  directly; text never calls it. The section holds observer attach and
  detach, the five health and salvage predicates, `_check_read_usable`,
  `_close_on_context_exit` and `_check_write_call_available`. No Protocol;
  text uses one concrete class.
- **Allowlist (AST).** `tests/test_text_bridge.py` parses `_text.py`, finds
  every private attribute read on the binary object (through `_binary_file`,
  `buffer` or a local alias), and requires the set to equal a reviewed list of
  11 names, with no stores. `_eof` and `_position` are listed as measured
  hot-path slot reads. A guard test checks the alias detection itself.
- **Ownership.** A second attach raises and keeps the first observers; detach
  is idempotent, clears both and closes nothing; a failed or cancelled open
  never attaches; close through text or through `buffer` detaches; a repeated
  close is a no-op. No assignment to binary observer fields remains in
  `_text.py`.
- **Callback lifetime.** After close the binary holds no reference to the text
  handle. Text has `__slots__` without `__weakref__`, so the test walks the
  binary's referents, having first shown the walk finds the text handle while
  attached.
- **Every §12.3 event.** Open, ordinary breakage (buffer discarded), validation
  salvage (buffer kept, salvage served, then terminal), transport-uncertainty
  correction, successful rewind (latch cleared) and failed rewind (latch kept),
  close during active work (rejected, no health change), abort with a
  successful close, and abort with a failing close, with and without later
  poison from the active call.
- **Accepted correction: failed abort.** At C0, an abort whose underlying
  close failed left the text handle open with its latch clear, and it served
  one more line decoded before the abort. The abort now notifies text when it
  breaks the reader. The archived probe shows C0 serving `'line 1\n'` with 9
  characters buffered, and `93fd3af` refusing the read with the latch set and
  nothing buffered. Delivery is at least once: when the active call later
  poisons too, text receives two notifications, and the test shows its handler
  is idempotent. The maintainer accepted this correction on 2026-10-05.
- **Observer failure (§12.2).** Health and EOF commit before any observer
  runs. A raising observer cannot skip mandatory cleanup: on normal close the
  trailer is written or the encoder discarded, the decoder discarded and the
  underlying file closed, asserted on the file and codec objects; on abort
  the underlying file is still closed. The observer error O combines with the
  close outcome by the design's precedence table, each row tested: O alone is
  raised; with a failed finalization F, F is raised with O as a note; with F
  and a failed underlying close C, F is raised, C suppressed, O a note; with F
  and a cancelled C, C is raised with F as its context and O as a note; with C
  alone, C is raised with O as a note; an interrupt from the observer
  outranks an ordinary F.
- **Seam deleted (§12.3).** `_read_broken`, `_read_validation_failed` and
  text's `_read_poisoned` no longer exist (AST and attribute tests).
- **Direct `buffer` use.** Characterized, not synchronized: a direct
  `buffer.seek(0)` leaves text's decoded buffer in place, a direct
  `buffer.read()` takes only bytes text has not decoded, and closing `buffer`
  closes text.
- **C0 traces pass.** File-state, source-failure, opening, opening-cleanup,
  read-health and bridge suites: 122 passed on each engine at `93fd3af`.
- **Full suite passes.** Both engine suites: 3,781 passed, 1 skipped.
  All-file prek passes.
- **Hot-path performance (below).**

Implementer-reported mutation checks (outputs not archived): removing the
abort notification fails three bridge tests; raising the closed-observer
error before cleanup fails seven; skipping the active call's `_poison_source`
fails the poisoning failed-abort case and two transport-uncertainty tests.

## Benchmarks

Method A, as for G10 and G11: `io,micro,text_origin,read_health` against clean
C0 and `93fd3af` worktrees, the same frozen venv, both engines, eight captures
per engine in ABBA ABBA order with five repeats each, pinned to CPU 13,
compared by per-benchmark minimum of capture medians. Codex reviewed the
scripts, unit and decision rule before the run: every row more than 5% slower
is investigated and recorded; adjacent pair deltas inform stability but do
not decide eligibility; a targeted micro-test is the default where
attribution is open.

The maintainer authorized the run, which started manually at 03:10 on
October 6. The quiet gate passed; peak foreign CPU was 0.87 cores (stdlib)
and 0.34 cores (zlib-ng). All 16 captures validated.

- **zlib-ng:** no row more than 5% slower. The largest are `read_health
  seek(0) rewind x50` at +1.69% and `readlines(64) loop` at +1.77%.
- **stdlib:** one flag, `CRC failure + salvage read() - 4MB` at +6.32% (pairs
  −0.6, +7.5, +0.9, −0.3). Every other row is within ±2.1%, except `Text large
  reads` at −5.26%, which is faster.
- **Text hot paths:** line iteration, `readline()` loop and `readlines()` rows
  are within ±0.7% on both engines.

### Follow-up: salvage `read()` on stdlib

The flag comes from one C0 capture. The C0 capture medians were 2.985, 2.758,
2.905 and 2.952 ms; the candidate's were 2.968, 2.966, 2.933 and 2.944 ms.
Without the fast C0 capture 4, the minimum delta is +1.0%. The benchmark is
binary only (CRC-failing `read()`, salvage `read()`, close); the only WP8
code change on that path is close error handling. Its cost was not measured
separately, and no zero-overhead claim is made.

A targeted micro-test ran exactly that operation, 20 operations per timing,
7 timings per fresh process, in 10 interleaved C0/candidate rounds with the
stdlib engine. The archived output shows fresh processes, their import paths
(`/tmp/aiogzip-wp8-c0` and `/tmp/aiogzip-wp8-cand`), engines, order and
values: C0 minimum 2.438 ms and median 2.477 ms; `93fd3af` minimum 2.445 ms
(+0.26%) and median 2.473 ms (−0.16%). The CPU 13 pinning, the worktrees'
commits and cleanliness, and the commands are implementer-reported, in an
archived transcription of the driver.

**Proposed disposition:** the window's >5% flag was not reproduced; it comes
from one fast C0 capture, and the targeted micro-test shows no stable
slowdown above policy. G17 re-measures every family against both baselines
before release.

Evidence, including raw captures, monitor logs, scripts, unit, summary, the
micro-test and the failed-abort probe, is archived in
[`data/b2/wp8-g12`](../benchmarks/data/b2/wp8-g12/README.md).
