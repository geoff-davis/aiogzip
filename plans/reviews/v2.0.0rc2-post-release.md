## First publication attempt

PR #143 merged as `2e49a38`. The signed tag `v2.0.0rc2` (tag object `e73a58a`)
was pushed on it, and a GitHub prerelease was created. The publish run
[38064418547](https://github.com/geoff-davis/aiogzip/actions/runs/38064418547)
passed `test`. `build` then refused the sdist at the record check:

```text
sha256 mismatch: aiogzip-2.0.0rc2.tar.gz: cb12f9989705a6fdbef3d1e3cac877457e4262fa780369971d2711e4dd9fb07d != b9399771e4fc80bf9239b3cc33e08a1bba58aafc7042fc7f0d1e09d84e9da673
```

`publish` was skipped, so nothing reached PyPI. The wheel matched.

**Cause.** `scripts/build_release_artifacts.py` passes `--python` only to
its smoke environments; `uv build` chooses its own interpreter. Python 3.15.0
had been installed through uv for S07. The local record build ran the sdist
build on it, and Python 3.15's `tarfile` gzips at level 6, while Python 3.14,
which the workflow uses, gzips at level 9. Both sdists decompress to the same
tar (sha256 `afe00387…`). Recompressing that tar at level 9 gives CI's size,
and a rebuild with `UV_PYTHON` set to Python 3.14.2 reproduced
`cb12f998…` exactly. The evidence JSON's `python` field records only the
smoke interpreter, so the record build gave no sign of the switch. rc1's
record was built before 3.15 was installed.

**Recovery.** The maintainer chose to correct the record and re-tag ("Fix
record, re-tag"). The steps were:

1. [#144](https://github.com/geoff-davis/aiogzip/pull/144) changed only
   `plans/releases/v2.0.0rc2.sha256`. `plans/` is not packaged, so the
   artifacts did not change. Codex approved it, all 22 checks passed (run
   [38065203980](https://github.com/geoff-davis/aiogzip/actions/runs/38065203980)),
   and it merged as `3dd9e94` at the maintainer's request.
   `git diff 2e49a38 3dd9e94` lists only that file.
2. The unpublished GitHub prerelease and the `v2.0.0rc2` tag on `2e49a38` were
   deleted.
3. A new signed tag was pushed on `3dd9e94`, and the release was recreated.

The failed run's log, the first tag object and the first release's metadata
are kept untracked in the maintainer's checkout
(`.cache/rc2-publish-attempt1/`).

## Post-release decision

All RC2 publication, provenance, artifact and documentation checks pass.
Development advances to `2.0.0rc3.dev0`. A `2.0.0.dev0` would sort before
`2.0.0rc2` under PEP 440, while `2.0.0rc3.dev0` sorts after it. The final
2.0.0 release can still follow directly. The Beta classifier and the frozen
2.0 compatibility contract remain in force.

Follow-ups:

1. **Release build interpreter.** `scripts/build_release_artifacts.py` should
   pass an explicit interpreter to `uv build`, and record it separately from
   the smoke interpreter.
2. **S08 LOWs left for later:**
   - the stale "no shield" docstring in `_inspection.py`;
   - `_acquire_path`'s cancellation-branch cleanup noting a `KeyboardInterrupt`
     from the late close instead of propagating it (unchanged from rc1).
3. **Python 3.15 on setup-python.** Switch the 3.15 leg from uv's managed
   CPython to `actions/setup-python` once that offers 3.15.0.
4. **2.0 readiness review.** The maintainer asked, on 2026-10-10, for a review
   by Claude Opus and Codex of what remains before 2.0.0.

GitHub reports no open Dependabot alerts.
