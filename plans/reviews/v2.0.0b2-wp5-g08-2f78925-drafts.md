## G07 capture duration

G07's 30-minute block span had no timing evidence. A daytime check ran one
latency capture per engine with the pinned harness against 2f78925 on CPU 13:
26.5 seconds for stdlib and 20.5 seconds for zlib-ng, with all 104 rows each.
A two-engine round therefore takes under a minute plus runner monitoring, far
inside the span. These were duration checks on a busy host (load average about
0.7–1.0), not evidence; the outputs stay in the implementer's scratch space.
The elapsed times are implementer-reported: the capture files don't record
overall duration. Codex confirmed the captures' clean 2f78925/e6d8422 sources,
CPU 13 and 104 rows per engine. The pinned worktrees stayed clean.

## Before registering any of these

As with every window: explicit maintainer authorization, a dated regeneration
with the same generator and pins, `--check`, `systemd-analyze --user verify`,
at least one minute of runtime-cap grace and a pre-registration review. The
September 30 record's host-timing notes apply to any start time.
